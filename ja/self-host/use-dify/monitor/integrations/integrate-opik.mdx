## Opik の概要

Opik は、大規模言語モデル（LLM）アプリケーションを評価、テスト、および監視するためのオープンソースプラットフォームです。LLM ベースのアプリケーション開発において、直感的な評価・テスト・監視機能を提供し、開発効率の向上を支援します。

<Info>
詳細については、[Opik](https://www.comet.com/site/products/opik/) をご参照ください。
</Info>

---

## Opik の導入ガイド

ホスト型 Opik では、以下のアカウントと API キーの手順に従ってください。認証を使用しないセルフホスト環境では、**API Key** を空欄にできます。

### 1. [Opik](https://www.comet.com/signup?from=llm) に登録/ログイン

### 2. Opik API キーの取得

右上のユーザーメニューから **API Key** を選択し、API キーを取得・コピーしてください。

<Frame>
  ![Opik API キー](https://assets-docs.dify.ai/2025/01/a66603f01e4ffaa593a8b78fcf3f8204.png)
</Frame>

### 3. Opik と Dify を統合

Dify アプリケーションで Opik を設定します。監視するアプリケーションを開き、サイドメニューで **監視** を選択し、ページ上の **アプリケーションパフォーマンスを追跡** をクリックします。

<Frame>
  ![アプリケーションパフォーマンスを追跡](https://assets-docs.dify.ai/2025/01/9d52a244e3b6cef1874ee838cd976111.png)
</Frame>

設定をクリックした後、必要に応じて **API Key** と **プロジェクト** 名を入力します。プロジェクト名が空欄の場合は `Default Project` が使われ、新しいプロジェクトは最初のトレースで作成されます。**Workspace** を空欄にすると、アカウントのデフォルトワークスペースが使われます。セルフホストの Opik では、**Url** に `/api/` で終わる API ベース URL を指定して保存します。デフォルトは `https://www.comet.com/opik/api/` です。

<Frame>
  ![Opik の設定](https://assets-docs.dify.ai/2025/01/7f4c436e2dc9fe94a3ed49219bb3360c.png)
</Frame>

保存に成功すると、現在のページで監視ステータスを確認できます。

## 監視データの確認

設定が完了すると、Dify アプリケーションを通常通りデバッグまたは使用できます。新しい実行を Opik で監視できます。過去の使用履歴はさかのぼって送信されません。

<Frame>
  ![Opik でアプリデータを確認](https://assets-docs.dify.ai/2025/01/a1c5aa80325e6d0223d48a178393baec.png)
</Frame>

Opik に切り替えると、ダッシュボードで Dify アプリケーションの詳細な操作ログを確認できます。

<Frame>
  ![Opik でアプリデータを確認](https://assets-docs.dify.ai/2025/01/09601d45eaf8ed90a4dfb07c34de36ff.png)
</Frame>

Opik の詳細な LLM 操作ログにより、Dify アプリケーションのパフォーマンスを最適化できます。

<Frame>
  ![Opik でアプリデータを確認](https://assets-docs.dify.ai/2025/01/708533b4fc616f852b5601fe602e3ef5.png)
</Frame>

<Note>
設定を保存してトレースを有効にしたら、アプリを再実行し、監視サービスに新しいトレースが表示されるか確認してください。トレースは非同期で送信されます。設定の保存だけでは、トレースの到着は確認できません。

Agent アプリや [新しい Agent ノード](/ja/self-host/use-dify/nodes/agent#new-agent) を使うワークフローでは、デプロイ設定で `OPS_AGENT_TRACE_ENABLED=true` と `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true` の両方を有効にしてください。詳しくは [環境変数](/ja/self-host/deploy/configuration/environments#llmops-トレース配信) を参照してください。これらのアプリでは **内容を収集** がデフォルトでオフになり、ワークフロー全体の入力と出力を制御します。それ以外のアプリでは、入力と出力が送信される場合があります。
</Note>

## モニタリングデータリスト

Dify は処理を階層構造としてエクスポートします。メッセージの下には `llm` 呼び出しがあり、Chatflow のメッセージの下にはワークフローとノードの処理があります。監視サービスのトレース ID とスパン ID は Dify の識別子から生成され、データベースの ID をそのままコピーしたものではありません。トークン使用量のネイティブフィールドは、モデル呼び出しにのみ設定されます。

以下の詳細リストは、Dify の元レコードとメタデータを説明しています。エクスポートされるのは、関連する利用可能な値のみです。元レコード全体をそのまま送信するわけではありません。
