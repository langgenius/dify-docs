## アプリの接続

Dify を設定する前に、[API キー](https://wandb.ai/authorize) で書き込める [W&B プロジェクト](https://docs.wandb.ai/models/track/project-page#create-a-project) を作成します。チームのプロジェクトでは、そのチームを **Entity** に指定します。

Dify アプリで **監視**（Agent アプリでは **モニタリング**）> **アプリのパフォーマンスの追跡** を開きます。Weave の項目（**織る**）で **設定** をクリックし、接続情報を入力してください。

| フィールド | 必須 | 値 |
|:------|:---------|:------|
| **API Key** | はい | W&B の API キー。 |
| **プロジェクト** | はい | 書き込み可能な既存のプロジェクト。ここに `entity/project` を入力して、**Entity** を空欄にしてもかまいません。 |
| **Entity** | いいえ | W&B のチームまたはユーザー。空欄の場合、Dify は API キーの既定のエンティティを取得します。 |
| **Endpoint** | いいえ | Weave のトレースサーバー。既定値は `https://trace.wandb.ai`。HTTPS が必須です。 |
| **Host** | いいえ | W&B の API サーバー。既定値は `https://api.wandb.ai`。HTTP(S) を使用できます。 |

独自のデプロイ先を使う場合は、トレースサーバーの **Endpoint** と W&B API の **Host** を管理者に確認します。指定されたパスプレフィックスも含めてください。

[Dify が送信するデータ](#dify-が送信するデータ) を確認してから、**保存 & 有効に** をクリックします。各アプリで有効にできるトレースプロバイダーは 1 つです。Weave を選ぶと、現在の選択が置き換わります。

保存済みの認証情報は、編集時には表示されません。**Host** と **Endpoint** を変更しない場合、空欄のままにすると保存済みの値を維持できます。どちらかのアドレスを変更した場合は、認証情報を再入力してください。

## Dify が送信するデータ

トレースには、アプリの 1 回の実行が **スパン** と呼ばれる処理単位で記録されます。各スパンには実行時間やステータス、エラーが含まれます。Dify は収集した入出力やモデルの使用量も送信します。メッセージ、ワークフロー、ノードの ID など、識別用のメタデータも含まれます。

Workflow アプリでは、ループやイテレーションのグループを含むノードのスパンを確認できます。チャットのトレースでは、メッセージの下にモデル呼び出しが表示されます。Chatflow アプリのトレースでは、メッセージの下にワークフローが表示されます。

Weave でモデル呼び出しを開くと、収集した入出力を確認できます。取得できた token 数は、呼び出しのモデル別使用量に表示されます。Dify は Weave に標準で用意されている費用フィールドには値を設定しません。

### Agent の呼び出しと内容の収集

<Note>
Agent アプリと [新しい Agent ノード](/ja/self-host/use-dify/nodes/agent#new-agent) のトレースは、既定では無効です。デプロイ先の管理者に、`OPS_AGENT_TRACE_ENABLED=true` と `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true` の両方を設定するよう依頼してください。設定場所は [環境変数](/ja/self-host/deploy/configuration/environments#llmops-トレース配信) を参照してください。
</Note>

アプリのトレース設定にある **Agent データ収集** で、次の項目を設定します。

- **Agent の内部処理を収集**：Agent の判断をデバッグする際、内部のモデル呼び出しやツール呼び出しを確認するにはオンにします。オフにすると内部の呼び出しは省かれますが、トレースには Agent の実行やワークフローノード自体が残ります。
- **内容を収集**：これらの実行の入出力を監視サービスに送信する場合にのみオンにします。オフでも、実行時間や token 情報、ステータスは確認できます。

<Note>
これらの設定は、Agent アプリに適用されます。新しい Agent ノードを含む Workflow または Chatflow アプリも対象です。このようなワークフローでは、他のノードの入出力も **内容を収集** の設定に従います。それ以外のアプリでは、入出力が送信される場合があります。その内容を監視サービスに送信できない場合は、トレースを無効にしておいてください。
</Note>

新しい Agent ノードには、そのノードを含む Workflow または Chatflow アプリのトレース設定が適用されます。ワークフローツール内での Agent 呼び出しは、親の Agent のトレースには含まれません。

## 新しいトレースの確認

1. Dify アプリに新しいリクエストを送信し、実行が完了するまで待ちます。
2. **アプリのパフォーマンスの追跡** で、**織る** の **見る** をクリックして設定したプロジェクトを開きます。
3. 実行時刻を手がかりに新しい呼び出しを探し、開いて子の呼び出しを確認します。

実行が完了してからトレースが表示されるまで、時間がかかる場合があります。

    プライベート HTTP エンドポイントを使う場合は、管理者に [SSRF プロキシの許可リスト](/ja/self-host/deploy/configuration/environments#ssrf-プロキシ) の確認を依頼します。必要な送信先だけを許可してください。
