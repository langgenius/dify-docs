## アプリの接続

Dify の各サービスから接続できる Phoenix インスタンスを使用します。セルフホストでも Phoenix Cloud でも利用できます。認証が必要な場合は、プロジェクトの読み取りとトレースの送信ができる [API キー](https://arize.com/docs/phoenix/settings/api-keys) を取得します。Arize に接続する場合は、[Arize 連携](/ja/self-host/use-dify/monitor/integrations/integrate-arize) の手順に従ってください。

Dify アプリで **監視**（Agent アプリでは **モニタリング**）> **アプリのパフォーマンスの追跡** を開きます。**Phoenix** の **設定** をクリックし、接続情報を入力してください。

| フィールド | 必須 | 値 |
|:------|:---------|:------|
| **API Key** | 認証が有効な場合 | インスタンスまたは Phoenix Cloud スペースのキー。認証なしのサーバーでは空欄にします。 |
| **プロジェクト** | はい | 送信先のプロジェクト名。 |
| **Endpoint** | いいえ | Phoenix のベース URL。既定値の `https://app.phoenix.arize.com` を、Cloud スペースまたはセルフホストのインスタンスの URL に置き換えます。パスプレフィックスも含めてください。 |

Phoenix Cloud では、`https://app.phoenix.arize.com/s/<space>` など、スペースのホスト名をコピーします。取得場所は [Phoenix エンドポイントの確認方法](https://arize.com/docs/phoenix/learn/resources/faqs/what-is-my-phoenix-endpoint) を参照してください。ベース URL に `/v1/traces` は含めません。このパスは Dify が追加します。

[Dify が送信するデータ](#dify-が送信するデータ) を確認してから、**保存 & 有効に** をクリックします。各アプリで有効にできるトレースプロバイダーは 1 つです。Phoenix を選ぶと、現在の選択が置き換わります。

保存済みの認証情報は、編集時には表示されません。**Endpoint** を変更しない場合、空欄のままにすると保存済みの値を維持できます。送信先を変更した場合は、認証情報を再入力してください。

## Dify が送信するデータ

トレースには、アプリの 1 回の実行が **スパン** と呼ばれる処理単位で記録されます。各スパンには実行時間やステータス、エラーが含まれます。Dify は収集した入出力やモデルの使用量も送信します。メッセージ、ワークフロー、ノードの ID など、識別用のメタデータも含まれます。

Workflow アプリでは、ループやイテレーションのグループを含むノードのスパンを確認できます。チャットのトレースでは、メッセージの下にモデル呼び出しが表示されます。Chatflow アプリのトレースでは、メッセージの下にワークフローが表示されます。

Phoenix でモデルのスパンを開くと、収集した入出力や取得できた token 数を確認できます。Dify は Phoenix に標準で用意されている費用フィールドには値を設定しません。

### Agent の呼び出しと内容の収集

<Note>
Agent アプリと [新しい Agent ノード](/ja/self-host/use-dify/nodes/agent#new-agent) のトレースは、既定では無効です。デプロイ先の管理者に、`OPS_AGENT_TRACE_ENABLED=true` と `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true` の両方を設定するよう依頼してください。設定場所は [環境変数](/ja/self-host/deploy/configuration/environments#llmops-トレース配信) を参照してください。
</Note>

アプリのトレース設定にある **Agent データ収集** で、次の項目を設定します。

- **Agent の内部処理を収集**：Agent の判断をデバッグする際、内部のモデル呼び出しやツール呼び出しを確認するにはオンにします。オフにすると内部の呼び出しは省かれますが、トレースには Agent の実行やワークフローノード自体が残ります。
- **内容を収集**：これらの実行の入出力を監視サービスに送信する場合にのみオンにします。オフでも、実行時間や token 情報、ステータスは確認できます。

<Note>
これらの設定は、Agent アプリに適用されます。新しい Agent ノードを含む Workflow または Chatflow アプリも対象です。このようなワークフローでは、他のノードの入出力も **内容を収集** の設定に従います。それ以外のアプリでは、入出力が送信される場合があります。その内容を監視サービスに送信できない場合は、トレースを無効にしておいてください。
</Note>

新しい Agent ノードには、そのノードを含む Workflow または Chatflow アプリのトレース設定が適用されます。ワークフローツール内での Agent 呼び出しは、親の Agent のトレースには含まれません。

## 新しいトレースの確認

1. Dify アプリに新しいリクエストを送信し、実行が完了するまで待ちます。
2. **アプリのパフォーマンスの追跡** で、**Phoenix** の **見る** をクリックして設定したプロジェクトを開きます。
3. 実行時刻を手がかりに新しいトレースを探し、開いて子のスパンを確認します。

実行が完了してからトレースが表示されるまで、時間がかかる場合があります。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="設定を保存したのにトレースが表示されない">
    保存時にはプロジェクトの読み取り権限を確認します。トレースは送信しません。Phoenix が選択され、トレースが有効になっていることを確認してください。アプリを再度実行し、設定したプロジェクトを確認します。

    新しい実行がまだ表示されない場合は、管理者にワーカーログと [トレース配信キュー](/ja/self-host/deploy/configuration/environments#llmops-トレース配信) の確認を依頼してください。
  </Accordion>
  <Accordion title="Dify から監視サーバーに接続できない">
    Dify の API とワーカーから接続できるアドレスを指定する必要があります。コンテナ内の `localhost` は、そのコンテナ自身を指します。監視サーバーに到達できるホスト名を使用してください。

    プライベート HTTP エンドポイントを使う場合は、管理者に [SSRF プロキシの許可リスト](/ja/self-host/deploy/configuration/environments#ssrf-プロキシ) の確認を依頼します。必要な送信先だけを許可してください。
  </Accordion>
</AccordionGroup>

収集したトレースの評価方法については、Arize の [エージェント評価ガイド](https://arize.com/guides/ai-agent-handbook/agent-evaluation/) と [LLM 評価ガイド](https://arize.com/resources/llm-evaluation/) を参照してください。
