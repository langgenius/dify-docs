### 1 Arize とは

[Arize AX](https://arize.com/products/ax/) は、[Arize AI](https://arize.com/?utm_source=dify-docs&utm_medium=partner&utm_campaign=partner-docs&utm_content=integrate-arize-self-host) が提供するフル機能プラットフォームです。LLM やエージェント駆動型アプリケーションの可観測性、オンライン・オフライン評価、モニタリング、実験に対応します。本番運用チームや AI ネイティブ企業、エンタープライズ向けに設計されており、マネージドクラウドまたはエンタープライズ向けセルフホストでデプロイできます。

ローカル開発や実験、単一コンテナでのセルフホストに適したオープンソース構成が必要な場合は、代わりに [Phoenix 統合](/ja/self-host/use-dify/monitor/integrations/integrate-phoenix) を設定してください。

トレースの送信が始まったら、Arize の [エージェント評価ガイド](https://arize.com/guides/ai-agent-handbook/agent-evaluation/) と [LLM 評価ガイド](https://arize.com/resources/llm-evaluation/) を参照してください。障害のデバッグ、エージェント動作の評価、モデル品質のモニタリングにトレースを活用する方法を確認できます。

### 2 Arize の使い方

#### 1. Arize の[公式サイト](https://app.arize.com/auth/join)から登録し、ログインする。

### 2. Arize API キーの取得

右上のユーザーメニューから **API Key** を選択し、API キーを取得・コピーしてください。

<Frame>
  ![Arize API キー](https://i.ibb.co/JwBmQxnf/dify-docs-arize-api-key.png)
</Frame>

### 3. Arize と Dify を統合

Dify アプリケーションで Arize を設定します。監視するアプリケーションを開き、サイドメニューで **監視** を選択し、ページ上の **アプリケーションパフォーマンスを追跡** をクリックします。

<Frame>
  ![アプリケーションパフォーマンスを追跡](https://i.ibb.co/v6cL6rPs/dify-docs-arize-in-use.png)
</Frame>

設定をクリックした後、**API Key**、**Space ID**、**プロジェクト** 名を入力して保存します。**Endpoint** のデフォルトは `https://otlp.arize.com` です。OTLP/gRPC コレクターを指定してください。URL のパスは使われません。HTTP の `/v1/traces` エンドポイントは指定しないでください。

<Frame>
  ![Arize の設定](https://i.ibb.co/m5Xww8gL/dify-docs-arize-config.png)
</Frame>

保存に成功すると、現在のページで監視ステータスを確認できます。

<Frame>
  ![Arize の設定](https://i.ibb.co/xtggVmb7/dify-docs-arize-in-service.png)
</Frame>

<Note>
設定を保存してトレースを有効にしたら、アプリを再実行し、監視サービスに新しいトレースが表示されるか確認してください。トレースは非同期で送信されます。設定の保存だけでは、トレースの到着は確認できません。

Agent アプリや [新しい Agent ノード](/ja/self-host/use-dify/nodes/agent#new-agent) を使うワークフローでは、デプロイ設定で `OPS_AGENT_TRACE_ENABLED=true` と `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true` の両方を有効にしてください。詳しくは [環境変数](/ja/self-host/deploy/configuration/environments#llmops-トレース配信) を参照してください。これらのアプリでは **内容を収集** がデフォルトでオフになり、ワークフロー全体の入力と出力を制御します。それ以外のアプリでは、入力と出力が送信される場合があります。
</Note>

## モニタリングデータリスト

Dify は処理を階層構造としてエクスポートします。メッセージの下には `llm` 呼び出しがあり、Chatflow のメッセージの下にはワークフローとノードの処理があります。監視サービスのトレース ID とスパン ID は Dify の識別子から生成され、データベースの ID をそのままコピーしたものではありません。トークン使用量のネイティブフィールドは、モデル呼び出しにのみ設定されます。

以下の詳細リストは、Dify の元レコードとメタデータを説明しています。エクスポートされるのは、関連する利用可能な値のみです。元レコード全体をそのまま送信するわけではありません。
