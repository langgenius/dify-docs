ナレッジベースごとに、アップロードされたファイルにマルウェアが含まれていないか、インデックス化の前にスキャンできます。まず、ワークスペースのオーナーまたは管理者が、スキャナーを 1 つ以上接続します。スキャナーが接続されると、各ナレッジベースで必要に応じてスキャンを有効にできるようになります。

スキャンの対象は、ナレッジベースにアップロードされたファイルだけです。ナレッジパイプラインでローカルファイルのデータソースから取り込んだファイルも含まれます。Notion、ウェブサイトのクロール、オンラインドキュメント、オンラインドライブから取り込んだコンテンツはスキャンされません。アプリ、ワークフロー、チャットに送信されたファイルも対象外です。

<Note>
ファイルセキュリティスキャンはデフォルトで無効です。有効にするには、`FILE_SCAN_ENABLED` を `true` に設定してください。詳しくは [環境変数](/ja/self-host/deploy/configuration/environments#ファイルセキュリティスキャン) を参照してください。
</Note>

## スキャナーの接続

**連携** > **ファイルセキュリティスキャン** で **スキャナーを追加** をクリックし、ファイルを送信してよい範囲に合わせて種類を選択します。

- **Cloudmersive**、**Scanii**、または **MetaDefender Cloud**：自社のアカウントで使うホスト型サービスです。各ファイルの内容はそのサービスに送信され、アップロードされたファイルをスキャンするたびに、そのサービスのクォータを消費します。

  ナレッジベースの設定を編集できるメンバーなら誰でも、このスキャナーでスキャンを有効にできます。そのため、使う可能性のあるナレッジベースすべての利用量を見込んで、プランを選んでください。

- **カスタム API**：自社のスキャンサービスです。サービスが処理する必要のあるリクエストとレスポンスについては、[カスタム API スキャナーの仕様](/ja/self-host/use-dify/knowledge/file-security-scan-custom-endpoint) を参照してください。

  <Note>
  スキャンサービスが社内ネットワーク上で動作している場合、Dify から接続するには、デプロイ環境でそのアドレスを許可する必要があります。

  Dify が外部に送るリクエストはプロキシを経由します。このプロキシは、Dify を踏み台にして社内システムにアクセスされないよう、デフォルトで内部アドレスへの通信をブロックします。次のいずれかを設定して、エンドポイントを許可してください。

  - `SSRF_PROXY_ALLOW_PRIVATE_IPS` = エンドポイントの IP アドレス
  - `SSRF_PROXY_ALLOW_PRIVATE_DOMAINS` = エンドポイントのホスト名

  詳しくは [環境変数](/ja/self-host/deploy/configuration/environments#ssrf-プロキシ) を参照してください。
  </Note>

## ナレッジベースでのスキャンの有効化

<Info>
スキャンを有効にするには、エディター以上のロールが必要です。
</Info>

ナレッジベースの **設定** で、**ファイルセキュリティスキャン** セクションに移動します。スキャンを有効にして **スキャナー** を選択し、[後述の 2 つの設定](#スキャンで判定できないファイルの扱い) を選択します。最後に **保存** をクリックします。

スキャンは、有効にした後に追加したファイルから適用されます。ナレッジベースにすでにあるドキュメントは、再試行したときやチャンク設定を変更したときなど、次に処理される際にスキャンされます。感染していることがわかると、そのドキュメントには **エラー** と表示されます。

### スキャンで判定できないファイルの扱い

スキャンで判定できないケースは 2 つあります。それぞれについて、ファイルをブロックするか、スキャンせずに受け入れるかを選択します。

- **スキャナーが利用できない場合**：スキャナーに接続できない、タイムアウトする、サーバーエラーを返す、または Dify が解釈できない応答を返す場合です。一時的な障害の場合は、Dify が再試行してからこの設定を適用します。
- **ファイルをスキャンできない場合（暗号化されている、またはサイズが大きすぎる）**：ファイルが暗号化またはパスワードで保護されている場合です。スキャナーが受け付けるサイズを超えている場合や、スキャナーが対応していない形式の場合も含みます。

どちらの設定も、**ファイルを許可** に切り替えるのは、全ファイルのスキャンよりもファイルの取り込みを優先したい場合に限ってください。スキャナーの停止中も最新の状態を保つ必要があるナレッジベースや、スキャナーの上限サイズを超えるファイルを日常的に扱うナレッジベースなどが該当します。この方法で許可されたファイルはスキャンされずにインデックス化され、未スキャンであることを示す表示もありません。

どちらを選んでも、マルウェアが検出されたファイルは必ずブロックされます。認証情報が拒否されたスキャナーや、クォータを使い切ったスキャナーに送られたファイルも同様です。

### スキャンの動作確認

ナレッジベースに EICAR テストファイルをアップロードします。EICAR テストファイルは無害なファイルですが、どのウイルス対策エンジンもマルウェアとして検出します。[eicar.org](https://www.eicar.org) から入手できます。

そのドキュメントには、マルウェアに関するメッセージとともに **エラー** と表示されるはずです。インデックス化されてしまった場合は、このナレッジベースでスキャンが有効になっていて、設定が保存されているかを確認してください。テスト用のドキュメントは、確認後に削除してかまいません。

## ブロックされたファイルへの対処

ドキュメントリストで、ドキュメントの **エラー** の横にあるアイコンにカーソルを合わせると、ブロックされた理由を確認できます。次の 2 つのケースについて補足します。

- **マルウェアが検出された**：ドキュメントを削除してください。再試行しても、同じファイルを再度アップロードしても、またブロックされるだけです。
- **暗号化されている、サイズが大きすぎる、またはスキャナーが対応していない**：このようなファイルは、デフォルトでブロックされます。スキャンせずにナレッジベースに取り込んでもかまわない場合は、そのナレッジベースの設定を変更します。**ファイルをスキャンできない場合（暗号化されている、またはサイズが大きすぎる）** を **ファイルを許可** に切り替えてから、再試行してください。

  この設定は、以降そのナレッジベースに追加されるすべてのファイルに適用されます。このファイルのためだけに変更した場合は、元に戻してください。
