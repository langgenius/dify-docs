アプリをエクスポートすると、コピーを手元に残したり、他の人に渡したり、別の Dify インスタンスやワークスペースに移したりできます。エクスポートしたアプリは、**アプリパッケージ**（`.ifpkg` ファイル）になります。

アプリパッケージをインポートすると、新しいアプリを作成できます。既存のアプリを更新することもでき、たとえばテスト済みで本番公開の準備が整ったバージョンに置き換えられます。

同じワークスペース内でアプリをコピーするだけなら、アプリのメニューから **複製** を選択してください。

<Info>
アプリのエクスポートとインポートには、エディター以上のロールが必要です。
</Info>

## アプリのエクスポート {#export-an-app}

アプリまたは Agent のカードのメニューから、**アプリをエクスポート** または **エージェントをエクスポート** をクリックします。アプリや Agent を開いている場合は、左上のメニューからも操作できます。

Workflow、Chatflow、新しい Agent の場合、エクスポートされるのは現在のドラフトで、未公開の変更も含まれます。公開済みのバージョンをエクスポートするには、[バージョン履歴](/ja/self-host/use-dify/build/version-control) を開きます。そのバージョンのメニューから **アプリをエクスポート** または **エージェントをエクスポート** を選択します。

その他のアプリタイプでは、最後に公開した設定がエクスポートされます。

### エクスポートに含まれないもの {#what-the-export-leaves-behind}

アプリを構成するものは、次を除いてすべてエクスポートされます：

- 使用している統合（インポート時に、不足しているものをワンクリックでまとめてインストールできます）
- 関連付けたナレッジベース
- ワークフロー、Swagger API、MCP のツール
- Agent の [ファイルシステム](/ja/self-host/use-dify/build/new-agent/build#ファイルシステム) にある永続ファイル（ビルドモードでインストールしたプログラムなど）
- サービス API キー
- モデルとツールの認証情報
- ログと注釈
- 過去のバージョン
- インテグレーショントリガーのサブスクリプション

### シークレット値をエクスポートするかの選択

Secret 型の環境変数を持つ Workflow や Chatflow をエクスポートする際は、その値を含めるかどうかを選択できます。

<Info>
バージョン履歴からのエクスポートには、シークレット値は一切含まれません。
</Info>

値を含めるには、**シークレット値を含む** にチェックを入れます。値は平文でアプリパッケージに書き込まれるため、アプリパッケージを手にした人なら誰でも読めます。シークレットそのものと同じくらい厳重に管理するアプリパッケージに限って、この操作を行ってください。

値を含めない場合、該当する変数は空の状態でインポートされ、インポートした人が値を入力します。

## インポートによる新しいアプリの作成

**スタジオ** または **Agents** で、**作成** > **アプリをインポート** をクリックします。

この操作では必ず新しいアプリが作成され、独自の Web アプリ URL が割り当てられます。既存のアプリには影響しません。既存の Workflow や Chatflow に取り込みたい場合は、代わりに [そのアプリを更新](#update-an-existing-app) してください。Web アプリ URL と API キーはそのまま維持されます。

インポート後、エクスポートに [含まれないもの](#what-the-export-leaves-behind) のうち、新しいアプリに必要なものを設定してください。

## インポートによる既存アプリの更新 {#update-an-existing-app}

Workflow または Chatflow を開き、アプリの左上のメニューまたはキャンバスの右クリックメニューから **アプリをインポート** をクリックします。アプリパッケージは、Workflow または Chatflow からエクスポートしたもので、そのアプリで使えるノードだけを含んでいる必要があります。Workflow には回答ノードを、Chatflow には出力ノードやトリガーノードを含めることはできません。

インポートすると、ドラフトに加えて、アプリの名前、説明、アイコンが置き換わります。アプリ自体は同じままで、ログ、注釈、API キー、Web アプリと MCP サーバーの URL も変わりません。更新したドラフトを公開するまで、ユーザーには公開済みのバージョンが提供され続けます。

アプリパッケージにシークレット値が含まれていない場合は、公開前に入力し直してください。

<Warning>
インポートしたアプリの Web アプリ設定（タイトル、アイコン、テーマカラーなど）は、インポートした時点で稼働中の Web アプリに反映されます。**公開前でも反映される** 点に注意してください。

インポート前に、インポートするアプリの Web アプリ設定が、ユーザーに見せるべき内容になっていることを確認してください。
</Warning>

<Tip>
Dify Enterprise では、`staging` や `production` のような独立した環境でアプリを実行できます。ある環境で新しいバージョンをテストしている間も、ユーザーは別の環境で安定したバージョンを使い続けられます。詳しくは [営業担当](https://share-na2.hsforms.com/176RpklY3TLeHo6qmuAdRKQ40s9fk) までお問い合わせください。
</Tip>

## 以前の Dify バージョンへのインポート

アプリパッケージ（`.ifpkg`）をインポートできるのは、Dify 1.18.0 以降のみです。以前の Dify バージョンにアプリを取り込むには、パッケージ（ZIP ファイル）を展開し、中にある `app.yaml` DSL ファイルだけをインポートします。

Web アプリ設定やアップロードしたアイコンなど、一部の設定は引き継がれません。インポート後に確認し、設定し直してください。

<Note>
[新しい Agent ノード](/ja/self-host/use-dify/nodes/agent#new-agent) を使用するワークフローは、Dify 1.18.0 以降にのみインポートできます。
</Note>
