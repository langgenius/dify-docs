App Builder は、対話を通じて Workflow アプリや Chatflow アプリの構築と改善を支援する AI アシスタントです。実現したいことを説明すると、App Builder が計画を提案します。承認すると、下書きにノードと接続を設定します。キャンバスエディタと併用して、新しいアプリの作成や既存アプリの更新に使えます。

<Info>
App Builder でアプリを計画・構築するには、モデルが必要です。**連携** > [**モデルプロバイダー**](/ja/self-host/use-dify/workspace/model-providers) でプロバイダーを設定してください。次に **システムモデル設定** を開き、**システム推論モデル** を選択して保存します。
</Info>

<Note>
[ナレッジ検索](/ja/self-host/use-dify/nodes/knowledge-retrieval)、[人間の入力](/ja/self-host/use-dify/nodes/human-input)、[クラシック Agent](/ja/self-host/use-dify/nodes/agent) ノードが必要な場合は、キャンバスエディタで追加する必要があります。
</Note>

## 要件の説明

<Info>
アプリの作成・テスト・公開には、エディター以上のロールが必要です。
</Info>

スタジオで **作成** を選択し、**ワークフロー** または **チャットフロー** を選びます。アプリに実行させたいことを説明してください。提供する情報、必要な結果、従ってほしいルールを含めます。

<Warning>
プロンプト、App Builder との会話、テスト入力には、API キー、トークン、パスワード、本番環境の機密データを含めないでください。
</Warning>

たとえば、次のように入力します。

```text wrap
返金の対象になるかを判定する Workflow アプリを構築してください。入力は、配達からの経過日数、商品の開封状況、返金理由です。配達から 30 日以内で未開封の場合のみ、返金対象としてください。返金対象になるかどうかと、その理由を出力してください。
```

送信前に説明を整えたい場合は、**AI で最適化** を選択して、修正された文章を確認します。

準備ができたら、**送信** を選択します。エディタ内で App Builder が開き、依頼内容の処理を開始します。

App Builder から詳細を求められたら、不足している情報を補い、誤解している点を訂正してください。

## リソースの確認

アプリ向けに提案されたモデル、ツール、公開済みの [Agent アプリ](/ja/self-host/use-dify/build/new-agent/overview) を確認します。アプリで使いたくないものの選択を解除し、**リソースを確認** を選択してください。

<a id="review-the-proposed-plan"></a>

## 計画の確認

計画を確認し、アプリに実行させたい内容と合っていることを確かめます。

- **入力と出力**：アプリが求める情報を提供でき、必要な結果が得られます。
- **ステップとルール**：アプリは指定したルールに従い、意図した操作だけを実行します。
- **外部サービスでの操作**：メッセージは正しい宛先に送信され、更新は正しいレコードに反映されます。

不足や誤りがあれば、**調整を続ける** を選択し、変更したい内容を説明してください。

計画が目的に合っていれば、**計画を承認** を選択します。App Builder が、アプリの未公開バージョンである **現在の下書き** に変更を適用します。

## テストと調整

<a id="run-and-review-the-test"></a>

<a id="review-test-inputs"></a>

### 下書きのテスト

選択したモデルに設定が必要な場合は、[モデルプロバイダー](/ja/self-host/use-dify/workspace/model-providers) で設定します。必要な [ツールの認証](/ja/self-host/use-dify/workspace/tools) は、テスト前に完了させてください。

App Builder が計画を適用したら、**テストを実行** を選択してテスト入力を確認します。期待する結果が分かる入力を使ってください。

テストフォームに、操作を実際に実行するためのチェックボックスがある場合は、次のように設定します。

- チェックを外したままにすると、メッセージ送信やレコード更新を行わず、操作をシミュレーションします。
- 操作を実際に実行する場合は、アカウント、送信先・更新先、データを確認してからチェックを入れます。

<Warning>
ほかのステップをシミュレーションする場合でも、モデルの呼び出しや読み取り操作では外部サービスにアクセスすることがあります。App Builder のテストでは、データの削除などの破壊的な操作はシミュレーションするか、実行をブロックします。
</Warning>

**テストを実行** を選択し、出力を期待する結果と比較します。エラーや想定外の出力は、**実行の詳細** で調べてください。操作を実際に実行した場合は、接続先のサービスでも結果を確認します。

App Builder が修正を提案した場合は、内容を確認して **修正を適用** を選択します。

<a id="refine-the-draft"></a>

### 下書きの調整

下書きが要件を十分に満たしていなければ、公開前に調整できます。変更後は、もう一度テストしてください。

#### App Builder に変更を依頼する

既存の人間の入力ノードとクラシック Agent ノードも、App Builder で編集できます。

**調整を続ける** を選択し、変更したい内容を説明します。出力が想定と異なる場合は、実際の結果と期待する結果も伝えてください。

更新された計画を確認し、**計画を承認** を選択して適用します。

<a id="continue-after-manual-edits"></a>

#### 自分で変更する

自分でノードを編集したい場合は、キャンバスエディタを使ってください。ナレッジ検索の設定はここで変更する必要があります。

その後 App Builder に戻り、続行方法を尋ねられた場合は、次のいずれかを選びます。

- **続行** を選択すると、App Builder が前回止まったところから再開します。
- **現在の下書きから再開** を選択すると、編集後の下書きを使って最初からやり直します。

どちらを選んでも、手動での編集内容は保持されます。

## 変更内容の確認

**チェックリスト** に表示されたエラーは、**再チェック** を選択して解消を確認します。アプリは実行せず、設定のみをチェックします。
