App Builder は、対話を通じて Workflow アプリや Chatflow アプリの構築と改善を支援する AI アシスタントです。実現したいことを説明すると、App Builder が計画を提案します。承認すると、下書きにノードと接続を設定します。キャンバスエディタと併用して、新しいアプリの作成や既存アプリの更新に使えます。

<Info>
App Builder でアプリを計画・構築するには、モデルが必要です。**連携** > [**モデルプロバイダー**](/ja/self-host/use-dify/workspace/model-providers) でプロバイダーを設定してください。次に **システムモデル設定** を開き、**システム推論モデル** を選択して保存します。
</Info>

<Note>
ナレッジ検索、人間の入力、クラシック Agent ノードが必要な場合は、キャンバスエディタで追加する必要があります。
</Note>

## 要件の説明

<Info>
アプリを作成するには、エディター以上のロールが必要です。
</Info>

スタジオで **作成** を選択し、**ワークフロー** または **チャットフロー** を選びます。受け取る入力、必要な結果、従うべきルールを含めて、アプリに実行させたいことを説明してください。

<Warning>
プロンプト、App Builder との会話、テスト入力には、API キー、トークン、パスワード、本番環境の機密データを含めないでください。
</Warning>

たとえば、次のように入力します。

```text wrap
返金の対象になるかを判定する Workflow アプリを構築してください。入力は、配達からの経過日数、商品の開封状況、返金理由です。配達から 30 日以内で未開封の場合のみ、返金対象としてください。返金対象になるかどうかと、その理由を出力してください。
```

送信前に説明を整えたい場合は、**AI で最適化** を選択して、修正された文章を確認します。

準備ができたら、**送信** を選択します。エディタ内で App Builder が開き、依頼内容の処理を開始します。

App Builder から詳細を求められたら、**要件を確認** フォームを確認して修正します。その後、**要件を送信** を選択してください。

## リソースの確認

提案されたモデル、ツール、公開済みの [Agent アプリ](/ja/self-host/use-dify/build/new-agent/overview) を確認します。使わないものの選択を解除し、**リソースを確認** を選択してください。リソースの提案がない場合も、**リソースを確認** を選択して続行します。

テストの前に、選択したモデルを [モデルプロバイダー](/ja/self-host/use-dify/workspace/model-providers) で設定してください。必要な [ツールの認証](/ja/self-host/use-dify/workspace/tools) も完了させます。

<a id="review-the-proposed-plan"></a>

## 計画の確認

計画を確認し、アプリに実行させたい内容と合っていることを確かめます。

- **入力と出力**：提供できる入力を使い、必要な結果を返すことを確認します。
- **ステップとルール**：各ステップがルールに従い、実行させたい操作だけを含むことを確認します。
- **外部サービスでの操作**：情報の送信やレコードの更新を行う場合は、データと送信先・更新先が正しいことを確認します。

不足や誤りがあれば、**調整を続ける** を選択し、変更したい内容を説明してください。

計画が目的に合っていれば、**計画を承認** を選択します。App Builder が、アプリの未公開バージョンである **現在の下書き** に変更を適用します。

## テストと調整

<Info>
アプリをテストするには、エディター以上のロールが必要です。
</Info>

<a id="run-and-review-the-test"></a>

<a id="review-test-inputs"></a>

### 下書きのテスト

App Builder が計画を適用したら、**テストを実行** を選択します。提案された入力を確認し、必要に応じて調整してください。期待する結果が分かるケースを選びます。

テストフォームに、操作を実際に実行するためのチェックボックスがある場合は、次のように設定します。

- チェックを外したままにすると、メッセージ送信やレコード更新を行わず、操作をシミュレーションします。
- 操作を実際に実行する場合は、アカウント、送信先・更新先、データを確認してからチェックを入れます。

<Warning>
ほかのステップをシミュレーションする場合でも、モデルの呼び出しや読み取り操作では外部サービスにアクセスすることがあります。App Builder のテストでは、データの削除などの破壊的な操作はシミュレーションするか、実行をブロックします。
</Warning>

**テストを実行** を選択し、出力を期待する結果と比較します。エラーや想定外の出力は、**実行の詳細** で調べてください。操作を実際に実行した場合は、接続先のサービスでも結果を確認します。

テストが失敗したら、エラーメッセージを読み、入力や設定に問題がないか確認してください。App Builder が修正を提案した場合は、内容を確認して **修正を適用** を選択します。

さらに調査が必要な場合は、**下書きを保持** を選択し、キャンバスエディタでテストを続けてください。

<a id="refine-the-draft"></a>

### 下書きの調整

下書きが要件を十分に満たしていなければ、**調整を続ける** を選択し、変更したい内容を説明します。出力が想定と異なる場合は、実際の結果と期待する結果も伝えてください。

**要件を送信** を選択し、リソースの確認を求められたら確認します。その後、更新された計画を確認し、**計画を承認** を選択してください。

<a id="continue-after-manual-edits"></a>

下書きはキャンバス上でも直接編集できます。既存の人間の入力ノードとクラシック Agent ノードは、App Builder で編集できます。ナレッジ検索の設定変更には、キャンバスエディタを使ってください。

その後、App Builder から続行方法を尋ねられたら、次のいずれかを選びます。

- **続行** を選択すると、現在の計画を最後まで進めます。
- **現在の下書きから再開** を選択すると、編集後の下書きを基にした新しい計画に置き換えます。

どちらを選んでも、手動での編集内容は保持されます。変更後は、もう一度テストしてください。

<a id="undo-this-attempt"></a>

<a id="revert-the-draft"></a>

### 下書きの復元

**元に戻す** を選択すると、App Builder の直近の復元ポイントに戻ります。復元ポイントは、構築、変更、修正の前に保存された下書きのコピーです。それ以降の下書きへの変更は、手動での編集も含めて破棄されます。

<Warning>
元に戻す操作では、テスト中に外部サービスで実行済みの操作は取り消せません。
</Warning>

## エラー修正の依頼 <a id="get-help-with-errors"></a>

<Info>

</Info>

キャンバスエディタでノードの設定エラーが表示された場合や、Workflow アプリのテストが失敗した場合は、App Builder に修正を依頼できます。

次の場所に **App Builder で修正** が表示されていれば、選択してください。

- **チェックリスト** 内の、ノード設定エラーの横
- 現在の Workflow アプリの **テスト実行** に表示される失敗パネル

## 変更内容の確認

App Builder の診断と修正案を確認します。承認が必要な場合は、**修正を承認** を選択して適用してください。承認が不要な場合は、App Builder が修正を自動で適用します。

**チェックリスト** に表示されたエラーは、**再チェック** を選択して解消を確認します。アプリは実行せず、設定のみをチェックします。
