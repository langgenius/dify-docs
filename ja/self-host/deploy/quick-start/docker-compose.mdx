デフォルトの Docker Compose 構成には、PostgreSQL、Weaviate と、Dify の稼働に必要なサービスが含まれます。サービスのデフォルト設定は自動で読み込まれます。初期設定には `docker/.env` の起動設定を使用します。

<Tip>
一般的なデプロイの問題については [FAQ](/ja/self-host/deploy/quick-start/faqs) を参照してください。
</Tip>

## デプロイ前の準備

### ハードウェア

- CPU：2 コア以上
- RAM：4 GiB 以上

### ソフトウェア

Docker と Docker Compose 2.35.0 以降をインストールし、Docker デーモンを起動してください。Dify のダウンロードには Git、サンドボックストークンの生成には OpenSSL も必要です。

| オペレーティングシステム | インストール |
|:---|:---|
| macOS | 対応する macOS バージョンに [Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/) をインストールします。仮想マシンに 2 つ以上の仮想 CPU と 8 GiB 以上のメモリを割り当ててください。 |
| Linux | ディストリビューションの手順に従い、[Docker Engine](https://docs.docker.com/engine/install/) と [Docker Compose](https://docs.docker.com/compose/install/) をインストールします。 |
| Windows（WSL 2） | [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) をインストールします。ソースコードとコンテナのデータは Linux ファイルシステムに保存してください。 |

開始前に Compose のバージョンを確認します：

```bash
docker compose version
```

## デプロイと起動

既存のデプロイでは、設定とデータを保持するため [アップグレード](#アップグレード) の手順に従ってください。

<Steps>
  <Step title="Dify リリースの取得">
    [Dify のリリース](https://github.com/langgenius/dify/releases) からバージョンを選びます。`<version>` をリリースタグに置き換え、クローンしてください：

    ```bash
    git clone --branch <version> --depth 1 https://github.com/langgenius/dify.git
    cd dify/docker
    ```

  </Step>
  <Step title="起動設定">
    ローカルの設定ファイルを作成します：

    ```bash
    cp .env.example .env
    ```

    デフォルト構成では、`COMPOSE_PROFILES=weaviate,postgresql,collaboration` をそのまま使用します。

    Agent サンドボックス用のトークンを生成します：

    ```bash
    openssl rand -hex 32
    ```

    `.env` の `DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN` に、出力された値を設定します。Agent バックエンドとローカルサンドボックスの起動には、この共有トークンが必要です。
  </Step>
  <Step title="サービスの起動と確認">
    `dify/docker` で次のコマンドを実行します：

    ```bash
    docker compose up -d
    docker compose ps --all
    ```

    常駐サービスに `Up` または `healthy` と表示されていれば正常です。`init_permissions` はストレージの権限を設定するために 1 回だけ実行されます。完了後に `Exited (0)` と表示されることを確認してください。
  </Step>
</Steps>

## アクセス

インターネットに公開する前に、[HTTPS](/ja/self-host/deploy/configuration/environments#nginx-reverse-proxy) を設定してください。[プラグインデーモン設定](/ja/self-host/deploy/configuration/environments#プラグインデーモン設定) と [Agent の設定](/ja/self-host/deploy/configuration/environments#dify_agent_server_secret_key) にある開発用の認証情報も置き換えます。

ブラウザで [http://localhost/install](http://localhost/install) を開き、管理者アカウントを作成します。設定後は [http://localhost](http://localhost) でサインインします。

リモート環境では、`localhost` をサーバーの IP アドレスまたはドメインに置き換えてください。デフォルトの HTTP ポートは `80` です。`docker/.env` の `NEXT_PUBLIC_SOCKET_URL` に、ブラウザからアクセスできる WebSocket アドレスを設定します。HTTPS の例は `wss://dify.example.com` です。`docker compose up -d` で適用してください。エンドポイントの形式は [WebSocket 設定](/ja/self-host/deploy/configuration/environments#cors-設定) を参照してください。

## カスタマイズ

デプロイの設定と共有の認証情報は `docker/.env` に保存します。Compose は、プロファイル、公開ポート、マウントパス、ヘルスチェックの実行間隔などを、コンテナ起動前にこのファイルから読み込みます。

各サービスは、`docker/envs/` 内の同梱の `.defaults` ファイルを自動で読み込みます。設定を変更するには、テンプレートのコメントに記載されたローカルの `.env` ファイルを作成してください。既にある場合は直接編集します。プロバイダーやセキュリティに関するオプション設定には、`.env.example` テンプレートもあります。`.example` を外してコピーしてください。

API、ワーカー、定期タスクで共通の設定には、`envs/core-services/api-worker.defaults` から `api-worker.env` を作成します。必要な設定だけコメントを解除し、**Container variable mappings** の式は変更しないでください。ファイルの優先順位、共有の認証情報、個別の設定については、[環境変数](/ja/self-host/deploy/configuration/environments#設定ファイル) を参照してください。

既存のデプロイをアップグレードする場合は、現在のプロバイダーを維持してください。プロバイダーを変更しても、データは移行されません。

同梱の Qdrant と PostgreSQL で新規デプロイを開始するには、`docker/.env` に両方の値を設定します：

```dotenv
VECTOR_STORE=qdrant
COMPOSE_PROFILES=qdrant,postgresql,collaboration
```

設定を反映するには、`dify/docker` で `docker compose up -d` を実行します。Qdrant の接続設定のデフォルト値は自動で読み込まれるため、プロバイダー用のファイルは不要です。同梱のプロバイダーを選ぶ際は、両方の設定を更新してください。`VECTOR_STORE` は `COMPOSE_PROFILES` を更新しません。

Qdrant の接続設定を変更するには、`envs/vectorstores/qdrant.env` がなければ `envs/vectorstores/qdrant.defaults` からコピーします。そのファイルを編集し、再度 `docker compose up -d` を実行してください。ルートの `docker/.env` は、プロバイダー用ファイルの値より優先されます。他のプロバイダーとデフォルト値は [ベクトルデータベース設定](/ja/self-host/deploy/configuration/environments#vector_store) を参照してください。

たとえば、Nginx のリクエストボディの上限を `200M` にするには、`dify/docker` で次の手順を実行します：

<Steps>
  <Step title="上書き値の設定">
    `envs/infrastructure/nginx.env` がない場合は作成します：

    ```bash
    cp envs/infrastructure/nginx.defaults envs/infrastructure/nginx.env
    ```

    `envs/infrastructure/nginx.env` に次の値を設定します：

    ```dotenv
    NGINX_CLIENT_MAX_BODY_SIZE=200M
    ```

  </Step>
  <Step title="設定の適用">
    設定を検証し、影響を受けるコンテナを再作成します：

    ```bash
    docker compose config --quiet
    docker compose up -d
    ```

    `docker compose restart` は、コンテナの既存の環境変数を保持します。環境変数を変更した場合は `up -d` を使用してください。
  </Step>
  <Step title="適用値の確認">
    Nginx が使用している設定を確認します：

    ```bash
    docker compose exec -T nginx nginx -T 2>&1 | grep client_max_body_size
    ```

    出力に `client_max_body_size 200M;` が含まれていれば正常です。別の値が表示される場合は、まず `docker/.env` の上書き設定を確認します。その後、シェル変数と Compose の明示的な `environment` 設定を確認してください。値がどのように決まるかは、[優先順位](/ja/self-host/deploy/configuration/environments#優先順位) を参照してください。
  </Step>
</Steps>

## アップグレード

[Dify のリリース](https://github.com/langgenius/dify/releases) から対象バージョンを選び、更新前にそのアップグレード手順を確認してください。

<Steps>
  <Step title="デプロイのバックアップ">
    通常のバックアップ手順で、`docker/.env`、ローカルのサービス `.env` ファイル、カスタム Compose ファイル、永続データを保存します。正常稼働時のシークレットとボリュームパスを保持してください。明示的に設定した、またはストレージ内に保存された [SECRET_KEY](/ja/self-host/deploy/configuration/environments#secret_key) も対象です。

    デフォルト構成では、`docker/volumes/` と `local_sandbox` の名前付きボリュームも対象です。名前は `dify_agent_local_sandbox_home` と `dify_agent_local_sandbox_workspace` です。データベースは整合性を保てる方法でバックアップしてください。書き込み中のファイルコピーでは、確実なバックアップになりません。外部のデータベースやストレージを設定している場合は、それらも含めます。

    `dify/docker` で `docker compose config` の出力を保存し、更新後の比較に備えます。出力にはシークレットが含まれるため、非公開の場所で保存・比較してください。
  </Step>
  <Step title="選択したリリースへの更新">
    チェックアウト前に、追跡対象ファイルへの変更を保存します。ローカルの `.env` ファイルは既存のパスに保持してください。

    リポジトリのルートでリリースタグを取得し、選択したバージョンをチェックアウトします：

    ```bash
    git fetch --tags origin
    git checkout <version>
    ```

    Compose のカスタマイズを、リリースのファイルに適用し直してください。Compose ファイルと `envs/` テンプレートは、同じリリースのものを使用します。
  </Step>
  <Step title="設定の確認">
    `docker/.env.example` を既存の `docker/.env` と比較し、必須項目を確認します。各ローカルサービスファイルも、対応する `.defaults` または `.env.example` テンプレートと比較してください。`api-worker.env` または既存の `shared.env` は、`api-worker.defaults` と比較します。

    必要な設定は既存のファイルに追加・変更してください。テンプレートを上書きコピーすると、独自の設定が失われます。現在のテンプレートにある入力名を使い、コンテナのマッピング式は変更しないでください。既存の環境をそのままアップグレードする場合は、現在のデータベースとベクトルストアを維持します。選択値を変更しても、データは移行されません。

    `dify/docker` で `docker compose config` を実行し、保存しておいた設定と比較します。どちらの出力も非公開で扱ってください。認証情報、ボリュームパス、プロファイル、カスタマイズした設定の変更を確認します。
  </Step>
  <Step title="アップグレードの適用と確認">
    `dify/docker` で次のコマンドを実行します：

    ```bash
    docker compose config --quiet
    docker compose pull
    docker compose up -d
    docker compose ps --all
    ```

    常駐サービスが `Up` または `healthy` であることを確認します。`init_permissions` は、完了後に `Exited (0)` と表示されることを確認してください。Dify を開き、カスタマイズした設定を使う機能を確認します。Nginx の変更は、[カスタマイズ](#カスタマイズ) にあるコマンドで適用値を確認してください。
  </Step>
</Steps>
