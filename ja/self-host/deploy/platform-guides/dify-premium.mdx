Dify Premium は、カスタムブランディングを可能にする AWS AMI サービスです。EC2 インスタンスとして AWS VPC にワンクリックでデプロイできます。[AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-t22mebxzwjhu6) にアクセスして購読してください。以下のようなシナリオで有用です：

- 中小企業として 1 つまたは少数のアプリケーションを作成したく、データレジデンシーを重視している。
- [Dify Cloud](https://cloud.dify.ai) に興味があるが、ユースケースが [プラン](https://dify.ai/pricing) でサポートされているよりも多くのリソースを必要とする。
- 組織内で Dify Enterprise を採用する前に POC を実行したい。

## アクセスとセットアップ

AMI がデプロイされた後、EC2 コンソールで確認できるインスタンスのパブリック IP を通じて Dify にアクセスします。デフォルトでは HTTP ポート 80 を使用します。

初めて Dify にアクセスする場合は、管理者初期化パスワード（EC2 のインスタンス ID）を入力してセットアップを開始します。

## カスタマイズ

### 設定

Docker Compose 2.35.0 以降を使用します。`docker compose version` で確認してください。

<Steps>
    <Step title="環境変数の編集">
        [変数の設定](/ja/self-host/deploy/configuration/environments#変数の設定) に従い、各設定を次の場所に記述します：

        - `COMPOSE_PROFILES` や `VECTOR_STORE` など Compose が最初に読み込む設定と、共有の認証情報は、`/dify/.env` に記述します。
        - AWS デプロイですでに `docker-compose.override.yaml` に設定している値は、そこに残します。
        - その他の設定はすべて、`.defaults` ファイルではなく `/dify/envs/` 内のローカル `.env` ファイルに記述します。

        たとえば OpenSearch の設定を変更する場合は、最初に一度だけデフォルトファイルをコピーし、そのコピーを編集します：

        ```bash
        cd /dify
        cp -n envs/vectorstores/opensearch.defaults envs/vectorstores/opensearch.env
        ```

    </Step>
    <Step title="変更の適用">
        `/dify` で設定を検証し、変更対象のサービスを再作成します。両方のコマンドで、既存の AWS 上書きファイルを指定してください。そのファイルがない場合は、`-f docker-compose.override.yaml` を省略します。

        ```bash
        cd /dify
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml config --quiet
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d
        ```

        変更が反映されない場合は、`/dify/.env` や `docker-compose.override.yaml` でも同じ変数を設定していないか確認してください。どちらもローカルファイルより優先されます（[優先順位](/ja/self-host/deploy/configuration/environments#優先順位) を参照）。
    </Step>
</Steps>

### Web アプリのロゴとブランディング

**設定** > **カスタマイズ** で、`Powered by Dify` ブランディングを削除するか、独自のロゴに置き換えられます。

## アップグレード

<Warning>
    [リリースノート](https://github.com/langgenius/dify/releases) から対象のリリースを選び、更新前にそのアップグレードガイドを確認してください。
</Warning>

以下の Compose コマンドはすべて EC2 インスタンス上で実行し、既存のデプロイと同じプロジェクト名とファイルを指定します。`-p` や `COMPOSE_PROJECT_NAME` を使っている場合も、同じ値を指定してください。プロジェクト名が変わると、新しい空の名前付きボリュームで起動してしまいます。`docker-compose.override.yaml` がない場合は、その `-f` オプションを省略します。

<Steps>
    <Step title="デプロイのバックアップ">
        1. ファイルのコピー中にデータベースへの書き込みが発生しないよう、`/dify` でデプロイを停止します：

            ```bash
            docker compose -f docker-compose.yaml -f docker-compose.override.yaml stop
            ```

            停止できない場合は、代わりに各データベースのダンプツールでバックアップします。

        2. `/dify/.env`、`/dify/envs/` 内のすべてのローカル `.env` ファイル、`docker-compose.override.yaml`、その他のカスタムデプロイファイルをバックアップします。続いて、`/dify/volumes/` や外部のデータベース、ストレージを含む永続データをバックアップします。

        3. デプロイに `local_sandbox` が含まれる場合は、その名前付きボリュームもバックアップします。マウント先は `/home/dify` と `/workspace` です。次のコマンドでボリュームを一覧表示できます：

            ```bash
            docker inspect --format '{{range .Mounts}}{{if eq .Type "volume"}}{{println .Name .Destination}}{{end}}{{end}}' "$(docker compose -f docker-compose.yaml -f docker-compose.override.yaml ps --all --quiet local_sandbox)"
            ```

    </Step>
    <Step title="選択したリリースへの更新">
        `<version>` を選択したリリースタグに置き換えます。そのリリースの Docker ファイルとテンプレートをまとめてコピーします。

        ```bash
        release_tag="<version>"
        upgrade_dir="$(mktemp -d)"
        git clone --depth 1 --branch "$release_tag" https://github.com/langgenius/dify.git "$upgrade_dir/dify"
        rsync -av --exclude='.env' --exclude='*.env' \
          --exclude='docker-compose.override.yaml' --exclude='volumes/' \
          "$upgrade_dir/dify/docker/" /dify/
        ```

        除外指定により、ローカルの環境ファイル、AWS 上書きファイル、実行データを保持します。その他のデプロイファイルへの変更は、バックアップから適用し直してください。
    </Step>
    <Step title="設定の確認">
        `/dify/.env` を `/dify/.env.example` と、`/dify/envs/` 内の各ローカルファイルを新しいテンプレートと比較します。差異がある箇所は、次のように対応します：

        - データベースやベクトルストアの設定など、意図して設定した値はそのまま残します。
        - それ以外はテンプレートの値を使います。
        - リリースノートで名前が変更された設定には、新しい名前を使います。

        テンプレートで既存のファイルを上書きしないでください。カスタム設定が失われます。

        <Note>
            `/dify/.env` で [`DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN`](/ja/self-host/deploy/configuration/environments#dify_agent_local_sandbox_auth_token) をまだ設定していない場合は、`openssl rand -hex 32` で値を生成し、`/dify/.env` に設定してください。Agent バックエンドとそのローカルサンドボックスは、この共有トークンがないと起動しません。
        </Note>
    </Step>
    <Step title="アップグレードの適用と確認">

        ```bash
        cd /dify
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml config --quiet
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml pull
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml ps --all
        ```

        常駐サービスが `Up` または `healthy` になっていること、`init_permissions` が `Exited (0)` で終了していることを確認します。その後、Dify を開き、カスタム設定を使う機能を確認してください。
    </Step>
</Steps>
