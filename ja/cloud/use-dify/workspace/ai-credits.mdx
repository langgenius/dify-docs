Dify Cloud の各プランには、Dify がホストする対応モデルで使用できる一定数の AI クレジットが含まれます。各プロバイダーのモデルをすぐに利用できるため、独自の API キーを追加しなくても、アプリの構築やテストを始められます。

AI クレジットを使用してアプリを実行すると、ワークスペースの共有残高からクレジットが差し引かれます。エディター、公開済みの Web アプリ、サービス API、トリガーからの実行も対象です。

## AI クレジットの消費

ワークスペースでは、対応モデルの実行時に AI クレジットを消費する場合があります。主なケースは次のとおりです。

- **LLM を使用するアプリの実行**：チャットボット、テキストジェネレーター、Agent アプリに直接設定したモデルを実行する場合が対象です。Workflow アプリや Chatflow アプリの LLM、質問分類器、パラメータ抽出、Agent ノードも含まれます。
- **アプリエディターでの AI 補助生成**：プロンプト、コード、構造化出力の設定を生成または修正する場合が対象です。Workflow または Chatflow の下書きも含まれます。
- **ナレッジベースのインデックス作成または検索**：インデックス作成やベクトル検索では、埋め込みモデルを実行する場合があります。ソース文書からの Q&A チャンク生成では LLM、リランクが有効な場合はリランクモデルを実行することがあります。
- **アプリでの音声入力の文字起こしまたは音声出力の生成**：音声認識モデルや TTS モデルを使用します。

アプリへの 1 回のリクエスト、Workflow アプリの 1 回の実行、その他のタスクでは、その処理で実行されたすべてのモデルのコストを合計します。各モデルのクレジットコストは固定で、入力や出力の長さに関係なく同じです。

たとえば、1 回の Workflow アプリの実行で、5 クレジットの LLM を 3 回使って 3 件のカスタマーレビューを分析するとします。その後、同じ LLM をもう 1 回使ってレビューを要約します。この実行では、合計 20 AI クレジットを消費します。

## AI クレジット残高の確認

ワークスペース名の下で、AI クレジットの残高を確認できます。残高をクリックすると、**連携** > **モデルプロバイダー** が開き、使用量の詳細を確認できます。

プランごとに含まれる AI クレジット数は次のとおりです。

| プラン | 含まれる AI クレジット | 更新頻度 |
|:-------|:------------------------|:---------|
| Sandbox | 200 | 1 回限り |
| Professional | 5,000 | 毎月 |
| Team | 10,000 | 毎月 |

<Note>
Professional または Team にアップグレードすると、新しいプランの AI クレジットが先に使用されます。残っている Sandbox クレジットはその後に使用されます。1 回のモデル実行に 2 つの残高を合算することはできません。
</Note>

## 使用優先順位の設定

AI クレジット対応プロバイダーに最初の API キーを追加すると、AI クレジットより先にそのキーが自動的に使用されます。順序を変えるには、**連携** > **モデルプロバイダー** でプロバイダーカードの **コンフィグ** をクリックし、**使用優先順位** を設定します。

- **AI クレジットを優先**：AI クレジットがなくなるまで使用し、その後、選択した API キーに切り替えます。残高がそのモデルの必要クレジット数に満たない場合は、使用優先順位を **API キー** に変更します。
- **API キーを優先**：選択した API キーを使用します。そのキーでリクエストを送信できない場合は、利用可能な AI クレジットを使用します。

<Note>
API キーで送信済みのリクエストが失敗した場合、AI クレジットでは再試行されません。API キーまたはプロバイダー側の問題を修正するか、再試行前に優先度を **AI クレジット** に変更してください。
</Note>
