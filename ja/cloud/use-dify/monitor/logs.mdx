任意のアプリの **ログ** ページで、アプリが実際にどう使われたかを確認できます。ユーザーが何を送信し、アプリがどう応答し、どんなフィードバックがあったかが記録されます。

チャット型アプリ（チャットボット、Chatflow、Agent）とテキストジェネレーターアプリは会話を、Workflow アプリは実行を記録します。

## ログに記録される内容

ログは、Web アプリ、API、Dify 内での利用など、実際の利用をすべて記録します。Workflow アプリでは、[トリガー](/ja/cloud/use-dify/nodes/trigger/overview) が開始した実行も記録されます。

エンドユーザーのフィードバック（高評価/低評価とコメント）は、対象のメッセージとあわせて保存されます。

Chatflow と Workflow アプリのエディタでのテスト（**プレビュー** と **テスト実行**）はログに表示されません。それ以外のアプリタイプのテスト会話は記録されます。

## ログの閲覧

各行は 1 件の会話または 1 回の実行です。いくつかの列には補足が必要です：

- **タイトル**：会話の最初のメッセージから自動生成されます。
- **エンドユーザーまたはアカウント**：Web アプリと API の利用はセッション ID、Dify 内での利用はチームメンバーのアカウントを表示します。
- **ユーザーレート** はエンドユーザーの高評価/低評価を、**操作レート** はチームメンバーの評価を集計します。どちらも会話全体で集計されます。
- **トリガー方法**（Workflow アプリ）：実行の起点を表示します（ウェブアプリ、Webhook、スケジュール、インテグレーション、デバッグ）。インテグレーションは、接続済みサービスからのイベントで開始された実行を指します。
  <Info>API から開始した実行もウェブアプリと表示されます。</Info>

キーワード検索はメッセージ内容とエンドユーザーのセッション ID に一致します。Workflow アプリでは、実行の入力・出力と完全な実行 ID にも一致します。

## 会話の確認

行をクリックすると、メッセージ全文が表示されます。

回答にカーソルを合わせると、そのメッセージの token 消費と応答時間を確認できます。あわせて表示されるアイコンから、背後のログも開けます（元のプロンプト、Agent アプリのツール実行過程、Chatflow メッセージのノード単位のトレース）。チームとしての操作は 2 つあります：

- **回答を評価する**：チームのフィードバックとして記録されます。低評価にはコメントを添えられます。チームの評価は **操作レート** 列に集計され、エンドユーザーのフィードバックとは区別されます。
- **注釈を追加する**：質問に改善済みの回答を組み合わせます。注釈の効果は [注釈システム](/ja/cloud/use-dify/monitor/annotation-reply) を参照してください。

会話 ID はページ URL に含まれるため、リンクをコピーするだけで特定のログを同僚に共有できます。

## 実行の確認

Workflow アプリでは、実行をクリックすると、結果、ステータスと token 合計を含む入出力、ノード単位の実行トレースを確認できます。失敗や遅延がどのノードで起きたかを特定できます。

**パラメータ付きテスト** をクリックすると、その実行の入力を使ってエディタでワークフローを再実行でき、問題の再現に役立ちます。

## ログの保持期間

<Warning>
ログには完全なユーザー会話が含まれ、機密情報が含まれる場合があります。アプリが現地のデータプライバシー規制に準拠していることを確認してください。プライバシーポリシーを公開し、必要に応じてユーザーの同意を取得してください。
</Warning>

Sandbox プランでは、すべての種類のログが 30 日間保持されます。それより古いエントリは完全に削除され、後からアップグレードしても復元できません。

<Badge color="blue">Professional</Badge> と <Badge color="blue">Team</Badge> では、保持期間はログの種類によって異なります：

- **会話ログ**（チャットボット、Chatflow、Agent、テキストジェネレーターアプリ）：サブスクリプションの有効期間中、保持されます。
- **ワークフロー実行ログ**（Workflow アプリ）：最近の実行は **ログ** ページに表示されます。約 3 か月を過ぎた実行は月別アーカイブに移り、CSV ファイルとしてダウンロードできます。詳細は [アーカイブされたログのダウンロード](#アーカイブされたログのダウンロード-professional-team) を参照してください。

## アーカイブされたログのダウンロード <Badge color="blue">Professional</Badge> <Badge color="blue">Team</Badge>

アーカイブされた実行が失われることはありません。月に 1 回、約 3 か月を過ぎたワークフロー実行ログがワークスペース単位で月別アーカイブにまとめられます。アーカイブ済みの各月はいつでもダウンロードできます。

アーカイブは、ワークスペースのオーナーと管理者のみが **設定** > **アーカイブされたログ** からダウンロードできます：

1. 対象月の **ダウンロードを準備** をクリックします。準備はバックグラウンドで実行されるため、ページを離れてもかまいません。
2. ボタンが **ダウンロード** に変わったらクリックしてファイルを保存します。準備済みのダウンロードは 24 時間有効です。期限が切れた場合は、再度準備してください。

ダウンロードは ZIP ファイルで、その月のワークスペース内のすべてのワークフロー実行を CSV ファイルとして含みます：

| ファイル | 内容 |
|:---------|:-----|
| `workflow_runs.csv` | 実行ごとに 1 行：ステータス、入力、出力、実行時間、token 使用量 |
| `workflow_app_logs.csv` | 各実行を、そのアプリと実行を開始したエンドユーザーまたはアカウントに関連付け |
| `workflow_node_executions.csv` | 実行ごとの各ノードの実行記録 |
| `workflow_node_execution_offload.csv` | 本体とは別に保存される大きなノード入力・出力 |
| `workflow_pauses.csv`、`workflow_pause_reasons.csv` | 人間の入力を待機した実行の一時停止記録 |
| `workflow_trigger_logs.csv` | 実行を開始したトリガーの呼び出し記録 |

<Tip>
特定のアプリの履歴だけが必要な場合は、`app_id` 列でフィルタリングしてください。この列は実行とアプリログの CSV に含まれます。アプリの ID は、**Studio** のそのアプリの URL に含まれる長い識別子です。
</Tip>
