各ワークスペースが 1 分間に送信できるナレッジベースリクエストの数には、上限があります。上限はプランによって決まります。従来型ナレッジベースと Agent ナレッジベースは、同じ上限を共有します。プランごとの上限は [Dify の料金ページ](https://dify.ai/pricing) を参照してください。

## カウントの対象

アプリからの検索がカウントされるのは、Workflow アプリまたは Chatflow アプリの知識検索ノードが従来型ナレッジベースを検索する場合だけです。

### Agent ナレッジベース

次の操作はカウントされます。

- ナレッジベースの作成と削除、設定の変更、ドキュメントやソース、メタデータフィールドの管理、ドキュメントのダウンロード
- ファイルのアップロード（1 ファイルにつき、追加時と処理開始時の 2 回）
- Dify 上で開始する同期
- 検索テスト、評価用の基準質問の変更、評価の実行。基準質問の編集画面を開いた場合も、保存の有無にかかわらずカウントされます。
- サービス API の呼び出し（読み取りを含むすべて）。ストリーミングクエリは、開始時に 1 回だけカウントされます。

次の操作はカウントされません。

- Agent ナレッジ検索ノードや新しい Agent を通じたアプリからの検索
- スケジュールによる自動同期
- ナレッジベースとそのドキュメントの閲覧
- Dify CLI によるナレッジベースの読み取り

### 従来型ナレッジベース

次の操作はカウントされます。

- ナレッジベースの作成と削除、設定の変更
- ドキュメントのアップロード、置き換え、削除、ダウンロード
- ドキュメントの有効化、無効化、アーカイブ、復元
- ドキュメント処理の一時停止、再開、再試行
- チャンクの追加、編集、有効化、無効化、削除（子チャンクと一括インポートを含む）
- 検索テスト
- 知識検索ノードの実行（イテレーションやループの中にある場合は、反復 1 回ごと）。項目の多いループは、それだけで上限に達することがあります。
- サービス API 経由の検索と、ドキュメント、チャンク、メタデータを変更する呼び出し

次の操作はカウントされません。

- チャットボット、テキストジェネレーター、レガシー Agent アプリからの検索
- Notion ページやウェブサイトの同期、ナレッジパイプラインの実行によるドキュメントの追加
- Dify 上でのドキュメント名の変更や、メタデータフィールドと値の管理。ただし、サービス API 経由のメタデータ変更はカウントされます。
- 従来型ナレッジベースから Agent ナレッジベースへのアップグレード
- 外部ナレッジベースでの検索テスト
- サービス API 経由でのドキュメントステータスの一括変更やタグの管理
- ナレッジベースとそのドキュメントの閲覧

## 上限に達した場合

直近 60 秒間にワークスペースのリクエスト数が上限に達すると、次のナレッジベースリクエストは拒否されます。どう表れるかは、リクエストの送信元によって異なります。

- Dify 上では、操作が失敗し、エラーメッセージが表示されます。
- サービス API では、ナレッジベースへの呼び出しがステータスコード 403 とエラーコード `forbidden` を返します。
- API 経由で実行したワークフローでは、知識検索ノードの失敗は HTTP エラーではなく、実行結果またはイベントストリームに表れます。

拒否されたリクエストもカウントされるため、すぐに再試行するとワークスペースはブロックされたままになります。再試行は、少なくとも 1 分間待ってから行ってください。大量のアップロードや API スクリプトなどの一括処理も、間隔を空けて実行してください。頻繁に上限に達する場合は、プランをアップグレードしてください。
