ナレッジベースを使うと、アプリが独自のコンテンツをもとに回答できるようになります。質問が届くと、最も関連性の高い文章が検索され、質問と一緒にモデルに渡されます。そのため回答は、モデルが学習時に得た知識だけに頼らず、そのコンテンツを踏まえたものになります。

ヘルプセンター、社内規程、製品カタログ、調査資料など、モデルは知らないがアプリには知っておいてほしい情報があれば、ナレッジベースを使います。分野やチームごとに 1 つずつ作成し、必要とするアプリに接続します。

## 2 種類のナレッジベース {#choose}

どちらが適しているかは、主に構築するアプリと、処理をどこまで自分で制御したいかによって決まります。

<Tabs>
  <Tab title="Agent ナレッジベース">
    [Agent ナレッジベース](/ja/cloud/use-dify/knowledge-base/overview) は、セットアップが簡単です。コンテンツを追加するだけで、整理もインデックス作成もすべて自動で行われます。

    次のような機能が必要な場合に選んでください。

    - **難しい質問への深い検索**：[検索の深度](/ja/cloud/use-dify/knowledge-base/retrieval-settings#retrieval-depth) を「高速」「詳細」「リサーチ」から選べます。
    - **コンテンツの自動更新**：接続したウェブサイト、オンラインドキュメント、オンラインドライブが、設定したスケジュールで更新されます。
    - **組み込みの品質チェック**：変更のたびに重要な質問を再テストし、検索で取りこぼした内容を追跡できます。
    - **コーディングエージェントからのアクセス**：Dify CLI を通じてコンテンツを読み取れます。

    Workflow アプリ、Chatflow アプリ、新しい Agent から利用できます。これから始めるプロジェクトには、こちらがおすすめです。
  </Tab>
  <Tab title="従来型ナレッジベース">
    [従来型ナレッジベース](/ja/cloud/use-dify/knowledge/readme) では、コンテンツのチャンキング、インデックス作成、検索の方法を自分で決めます。

    次のような場合に選んでください。

    - **チャットボット、テキストジェネレーター、レガシー Agent アプリ** の回答に使う場合。Workflow アプリと Chatflow アプリは、どちらの種類も利用できます。
    - **処理をより細かく制御したい** 場合。処理の流れ全体を [ナレッジパイプライン](/ja/cloud/use-dify/knowledge/knowledge-pipeline/readme) として構築することもできます。
    - **コンテンツを自社のシステムに置いたまま使いたい** 場合。[外部ナレッジベース](/ja/cloud/use-dify/knowledge/connect-external-knowledge-base) として接続します。
    - **15 MB を超えるファイル** を扱う場合。<Badge color="blue">Professional</Badge> と <Badge color="blue">Team</Badge> では、最大 50 MB まで対応します。
  </Tab>
</Tabs>

<Info>
ほとんどの従来型ナレッジベースは、後から Agent ナレッジベースに [アップグレード](/ja/cloud/use-dify/knowledge-base/upgrade-from-classic) できます。ただし、Agent ナレッジベースを従来型に変換することはできません。
</Info>

## 2 種類の比較 {#compare}

| | Agent ナレッジベース | 従来型ナレッジベース |
|:--|:--|:--|
| アプリ | Workflow アプリ、Chatflow アプリ、新しい Agent | チャットボット、テキストジェネレーター、レガシー Agent、Workflow、Chatflow の各アプリ |
| コンテンツのソース | ファイルのアップロード、ウェブサイトのクロール、オンラインドキュメント、オンラインドライブ | ファイルのアップロード、ウェブサイトのクロール、Notion、ナレッジパイプライン経由のその他のデータソース、外部ナレッジベース |
| ファイルサイズ | 全プランで 1 ファイルあたり最大 15 MB | Sandbox では 1 ファイルあたり最大 15 MB、Professional と Team では最大 50 MB |
| 設定する項目 | モデルと検索の深度、Top K、スコアしきい値（任意） | モデル、チャンクモードとチャンク長、インデックス方法、検索方法、Top K、スコアしきい値（任意）。または、処理の流れ全体をナレッジパイプラインとして構築 |
| 検索 | 意味とキーワードで照合。検索の深度を深くすると、関連する主題をたどったり、質問を複数に分解したりする | 意味、キーワード、またはその両方で照合 |
| インデックス作成に使うモデル | 推論モデルと埋め込みモデル | 埋め込みモデル（高品質インデックス）、またはモデルなし（経済的インデックス） |
| コンテンツの更新 | ソースごとに設定したスケジュールで同期 | Notion とウェブサイトのドキュメントを手動で同期 |
| 品質テスト | 検索テスト、評価用の基準質問、評価、問題ケース | 検索テスト |
| モニタリング | 「概要」ページ（対応が必要な項目と、質問への回答状況を表示） | なし |
| Dify 外からのアクセス | サービス API と [Dify CLI](/ja/cloud/use-dify/knowledge-base/use-knowledge-in-apps#from-your-coding-agent) | サービス API |

2 種類のナレッジベースは、ドキュメント数の上限、リクエストレート制限、ナレッジベースの API キーを共有し、権限の選択肢も同じです。また、どちらもビジョン対応の埋め込みモデルを使えば、画像を検索対象にできます。
