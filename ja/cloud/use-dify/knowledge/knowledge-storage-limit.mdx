各ワークスペースには、ナレッジベースに関する上限が 2 つあります。保存できるドキュメントの数と、保存できるインデックス済みデータの量です。従来型ナレッジベースと Agent ナレッジベースは、どちらの上限も共有します。

ワークスペースのオーナーと管理者は、**設定** > **請求** で使用量を確認できます。それぞれ **ドキュメント・アップロード・クォータ** と **ナレッジベースのデータストレージ** の欄に表示されます。プランごとの上限は [Dify の料金ページ](https://dify.ai/pricing) を参照してください。

## ドキュメント数の上限

ワークスペース内のすべてのナレッジベースを合わせたドキュメントの総数には、上限があります。アップロードしたドキュメントも、ソースからインポートしたドキュメントも対象です。無効化したもの、アーカイブしたもの、処理に失敗したものを含め、すべてのドキュメントがカウントされます。

上限に達すると、ドキュメントが新たに追加されるアップロードやインポートは失敗します。ドキュメントを追加するには、不要なドキュメントを削除するか、プランをアップグレードしてください。

## ナレッジベースのデータストレージ

各ドキュメントはチャンクに分割されます。チャンクとは、検索で返される文章の断片です。ナレッジベースのデータストレージには、これらのチャンクが検索できる形、つまりテキストとベクトルとして保存されます。ベクトルはチャンクを数値で表したもので、セマンティック検索はこれを使って意味の近さで照合します。

元のファイルはカウントされません。そのため使用量は、ファイルサイズではなく、インデックス後にドキュメントから生成されるデータの量で決まります。

### ストレージを消費する要素

従来型ナレッジベースでは、インデックス方法が **高品質** のドキュメントは、チャンクごとにベクトルを 1 つ保存します。親子モードの場合は、子チャンクごとに 1 つです。インデックス方法が **経済的** のドキュメントは、ベクトルではなくキーワードインデックスを使うため、ナレッジベースのデータストレージにはカウントされません。

Agent ナレッジベースでは、すべてのチャンクを 2 つの形で保存します。意味で照合するためのベクトルと、キーワードで照合するためのテキストです。さらにナレッジグラフも、グラフ上の主題と、主題どうしのつながりに対してベクトルを追加します。

どちらの種類でも、ビジョン対応の埋め込みモデルを使うと、画像ごとにベクトルが 1 つ追加されます。各ベクトルのサイズも埋め込みモデルによって決まります。たとえばデフォルト設定では、OpenAI の `text-embedding-3-large` が生成するベクトルは、`text-embedding-3-small` の 2 倍のサイズです。

使用量の数値はリアルタイムではありません。アップロードや削除の後、反映されるまでに数分かかることがあります。

### 従来型ナレッジベースへのアップロードが上限を超える場合

Dify は、インデックス作成の前にストレージ使用量を見積もり、その結果に基づいてアップロードを拒否することがあります。拒否されたドキュメントは **エラー** ステータスのまま一覧に残ります。

インデックスするには、プランをアップグレードするかストレージを解放してから、ドキュメント一覧の上にある **再試行** をクリックします。解放した容量は、すぐには再試行に反映されないことがあります。ワークスペース内でほかのドキュメントのインデックス作成が続いている間は、特に時間がかかります。

別の方法として、ドキュメントを削除し、チャンクサイズを大きくしてから再度アップロードすることもできます。チャンクの数を減らせる場合がありますが、チャンクが大きいほど、検索で返される文章の断片が長くなり、精度が下がることもあります。

### ストレージがいっぱいになった場合

使用量がプランの上限に達すると、どちらの種類のナレッジベースにもコンテンツを追加できなくなります。

- **従来型ナレッジベース** では、ドキュメントのアップロード、チャンクの追加や編集、チャンク設定の変更後などの再インデックスができなくなります。Dify 上では、ドキュメントの有効化、無効化、アーカイブ、復元もできなくなりますが、サービス API からはステータスを変更できます。この制限はワークスペース全体に及ぶため、インデックス方法が **経済的** のナレッジベースでも同じです。
- **Agent ナレッジベース** では、新しいコンテンツや変更されたコンテンツを処理できなくなります。新しいアップロードやインポートはその場で拒否されることがあり、処理中、同期中、再インデックス中のドキュメントは失敗します。埋め込みモデルの変更も実行できません。

    検索と削除は引き続き利用できます。空き容量ができたら、拒否されたコンテンツを追加し直し、失敗したドキュメントを再試行してください。

制限を解除するには、ストレージを解放するか、プランをアップグレードしてください。

ダウングレードやサブスクリプションの期限切れでデータが新しいプランの上限を超えても、データは削除されません。アプリからは、これらのナレッジベースを引き続き検索できます。ただし、使用量が上限内に収まるか、再度アップグレードするまで、コンテンツは追加できません。

### ストレージの解放

不要になったドキュメントやナレッジベースを削除します。Agent ナレッジベースではコンテンツの削除がバックグラウンドで行われるため、容量が戻るまでさらに数分かかることがあります。

コンテンツを追加し直す前や、失敗したドキュメントを再試行する前に、**ナレッジベースのデータストレージ** の使用量が上限を下回っていることを確認してください。下回っていないと、再び失敗することがあります。
