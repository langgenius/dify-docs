アップグレードでは、[従来型ナレッジベース](/ja/cloud/use-dify/knowledge/readme) をもとに [Agent ナレッジベース](/ja/cloud/use-dify/knowledge-base/overview) を作成します。元の従来型ナレッジベースはそのまま残ります。アプリは切り替えるまで従来型ナレッジベースから回答し続けるため、Agent ナレッジベースの確認とテストは自分のペースで進められます。

Agent ナレッジベースは、[Workflow アプリと Chatflow アプリ](/ja/cloud/use-dify/build/workflow-chatflow)、[新しい Agent](/ja/cloud/use-dify/build/new-agent/overview)、[サービス API](/ja/api-reference/guides/knowledge-base)、[Dify CLI](/ja/cloud/use-dify/knowledge-base/use-knowledge-in-apps#from-your-coding-agent) から利用できます。チャットボット、レガシー Agent、テキストジェネレーターのアプリは、引き続き従来型ナレッジベースを使います。

両者の違いについては、[比較表](/ja/cloud/use-dify/knowledge/overview#compare) を参照してください。

## 引き継がれる内容

アップグレードでは、コンテンツを Agent ナレッジベースに取り込み、すべてのドキュメントのインデックスを作成し直します。セクション、要約、チャンクは新たに生成されるため、従来型のものとは一致しません。

次の項目が引き継がれます。

- **ドキュメント**：アップロードしたファイルは、もう一度アップロードされます。Notion ページとクロールしたウェブサイトは、アップグレード時に作成されるソースを通じて取り込まれます。

- **メタデータ**：フィールドと各ドキュメントのラベルが引き継がれるため、Agent ナレッジ検索ノードでも同じフィルターを設定できます。

- **検索設定**：Top K、スコアしきい値、埋め込みモデル、リランクモデルが引き継がれます。どちらかのモデルが存在しないか利用できなくなっている場合は、代わりにワークスペースのデフォルトが使われます。

- **アクセス**：**権限** の設定が引き継がれます。従来型ナレッジベースで **API アクセス** が有効だった場合は、それも引き継がれます。**ワークフローアクセス** は、最初は無効です。ただし、公開済みの Workflow アプリまたは Chatflow アプリが従来型ナレッジベースを使っていた場合は有効になります。

    **すべてのナレッジベース** を対象に作成したキーは Agent ナレッジベースにもアクセスできますが、対象を限定したキーはアクセスできません。どちらの場合も、コードでは Agent ナレッジベースの新しい ID を使い、その [専用 API](/ja/api-reference/guides/knowledge-base) を呼び出す必要があります。

- **基本情報**：名前、説明、タグが引き継がれます。

推論モデルと [検索の深度](/ja/cloud/use-dify/knowledge-base/retrieval-settings#retrieval-depth) には、従来型に対応する設定がありません。推論モデルの初期値はワークスペースのデフォルトで、深度の初期値は「高速」です。後から推論モデルを変更すると、すべてのドキュメントのインデックスが再作成されます。大規模なナレッジベースでは、アップグレードの前に、ワークスペースのデフォルトが希望どおりのモデルか確認してください。

## Agent ナレッジベースへのアップグレード

<Info>
始める前に、次の点を確認してください。

- 従来型ナレッジベースの編集権限があること。
- ワークスペースに、システムのデフォルトの推論モデル、埋め込みモデル、リランクモデルが設定されていること。
- 従来型ナレッジベースが、外部ナレッジベースでも、ナレッジパイプラインで構築したものでもないこと。どちらもアップグレードできません。代わりに [Agent ナレッジベースを作成](/ja/cloud/use-dify/knowledge-base/create-knowledge-base) し、そのコンテンツを追加してください。
- アップロードしたファイルがすべて 15 MB 以下であること。15 MB を超えるファイルや、Agent ナレッジベースが対応していない形式のファイルが 1 つでもあると、アップグレード全体が失敗します。始める前に、従来型ナレッジベース内でそれらのファイルを分割するか、差し替えてください。
- Notion ページを含む場合は、同じ Notion ワークスペースが **連携** > **データソース** で接続されていること。クロールしたウェブサイトを含む場合は、そのとき使ったクロールプロバイダーも同じ場所で接続されていること。

</Info>

アップグレードではすべてのドキュメントのインデックスを作成し直すため、推論モデルと埋め込みモデルのトークンを消費します。大規模なナレッジベースの場合は、モデルの利用コストを管理している担当者に事前に知らせてください。

**ナレッジ** で従来型ナレッジベースのメニューを開き、アップグレードを開始します。アップグレードはバックグラウンドで実行され、進行状況は **Agent** の一覧に表示されます。

サイズによって、数分から数時間かかります。

<Info>
アップグレードで作成されるソースは、手動同期に設定されています。コンテンツを継続して更新する必要がある場合は、ソースごとにスケジュールを設定してください。
</Info>

## アプリの切り替え

切り替える前に、[インデックス済みのドキュメントを確認](/ja/cloud/use-dify/knowledge-base/review-indexed-documents) し、アプリが実際に受ける質問で [検索をテスト](/ja/cloud/use-dify/knowledge-base/test-and-tune) してください。

Agent ナレッジベースの **ワークフローアクセス** がオフになっている場合は、まずその **設定** でオンにします。続いて、ワークフローで次の操作を行います。

1. Agent ナレッジベースを検索する [Agent ナレッジ検索ノード](/ja/cloud/use-dify/nodes/knowledge-retrieval-v2) を追加し、知識検索ノードがあった位置に接続します。同じメタデータフィルターを設定し、LLM の **コンテキスト** など、後続ノードの参照先をこのノードの `result` に変更します。

2. テストを実行し、Agent ナレッジベースから適切に回答できるようになったら知識検索ノードを削除して、公開します。

従来型ナレッジベースは、どのアプリからも使われなくなってから削除してください。チャットボット、レガシー Agent、テキストジェネレーターのアプリは切り替えられないため、これらのアプリで使われていないかも確認が必要です。
