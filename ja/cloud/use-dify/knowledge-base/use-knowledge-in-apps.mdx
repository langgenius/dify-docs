1 つの [Agent ナレッジベース](/ja/cloud/use-dify/knowledge-base/overview) を、複数のアプリで同時に使えます。ナレッジベースをもとに回答させたいワークフロー、Agent、プログラムに接続できます。手元のマシンで動くコーディングエージェントに、Dify CLI 経由でドキュメントを読ませることもできます。

<Info>
チャットボット、レガシー Agent、テキストジェネレーターのアプリは、Agent ナレッジベースを検索できません。Agent ナレッジベースをもとに回答させるには、アプリを Chatflow アプリまたは新しい Agent として作り直してください。
</Info>

## Workflow アプリと Chatflow アプリからの利用

[Agent ナレッジ検索](/ja/cloud/use-dify/nodes/knowledge-retrieval-v2) ノードを追加し、検索するナレッジベースを選びます。閲覧権限のないナレッジベースは、選択肢に表示されません。

検索対象を特定のドキュメントに限定するには、ノードで [メタデータによる絞り込み](/ja/cloud/use-dify/nodes/knowledge-retrieval-v2#filter-by-metadata) を設定します。

テスト実行も含めて、すべてのワークフローからの検索を止めるには、ナレッジベースの **設定** で **ワークフローアクセス** をオフにします。このナレッジベースを使っているワークフローは、オンに戻すまで該当のノードで失敗します。

## 新しい Agent からの利用

[Agent](/ja/cloud/use-dify/build/new-agent/overview) の **設定** で、**[Agent ナレッジベース](/ja/cloud/use-dify/build/new-agent/build#agent-knowledge-base)** にナレッジベースを追加します。

ナレッジベースをいつ検索するかは、Agent がナレッジベースの名前と説明から自分で判断します。検索の深度は常に「高速」です。

公開済みの Agent からの検索を止めるには、ナレッジベースの **設定** で **API アクセス** をオフにします。このナレッジベースを使う Agent は動作を続けますが、ナレッジベースは検索できなくなります。同じスイッチで、サービス API からのアクセスも止まります。

## 独自のコードからの利用

[サービス API](/ja/api-reference/guides/knowledge-base) を使うと、コードからナレッジベースに質問したり、時間のかかる「リサーチ」検索をバックグラウンドで実行したり、ドキュメントを管理したりできます。

API の呼び出し元からのアクセスを止めるには、ナレッジベースの **設定** で **API アクセス** をオフにします。この場合、[Agent](/ja/cloud/use-dify/build/new-agent/overview) からもアクセスできなくなります。

## コーディングエージェントからの利用 {#from-your-coding-agent}

Claude Code や Codex など、手元のマシンで動くコーディングエージェントは、作業中にナレッジベースを参考資料として使えます。Dify CLI を通じて、フォルダ内のファイルと同じ感覚でドキュメントを閲覧して読み取り、語句の完全一致で検索します。

コーディングエージェントからは、ナレッジベースの内容を変更できません。アプリと同じように意味で検索するには、[サービス API](#独自のコードからの利用) を使います。

セットアップは、CLI ドキュメントの [クイックスタート](/ja/cli/get-started) に沿って進めます。`difyctl` をインストールし、Dify アカウントでサインインしてから、コーディングエージェントに `difyctl` スキルをインストールします。

あとは、やりたいことをエージェントに依頼します。その際、次の 2 点を伝えてください。

- 使用するコマンド（`difyctl knowledge_fs`）。`difyctl` スキルには、これらのコマンドが含まれていません。
- ナレッジベースの ID。Dify でナレッジベースを開き、ブラウザのアドレスバーからコピーします。`/datasets/new/` と、その次の `/` の間の部分です。

たとえば、次のように依頼します。

```text wrap
difyctl knowledge_fs を使って、Dify のナレッジベース 5b9e2c71-0d4a-4f3e-9a6b-2c8d1e7f4a30 にある API 設計ガイドラインを読み、私のエンドポイントの変更がそれに沿っているか確認してください。
```

Dify であなたが閲覧できる Agent ナレッジベースであれば、エージェントはどれでも開けます。

エージェントが参照するのは、サインイン時に Dify で開いていたワークスペースです。別のワークスペースにあるナレッジベースを使うには、まず [`difyctl` のワークスペースを切り替えます](/ja/cli/manage-sign-in#switch-your-workspace)。

## アプリの公開後

ドキュメントを同期または再アップロードすると、インデックス作成が完了した時点で新しいバージョンが反映されます。アプリ、Agent、API の呼び出し元、外部のコーディングエージェントのすべてが対象です。

**概要** ページでは、同期が止まったソースや、結果が返らなかった質問に注意してください。それぞれの対処方法は、[Agent ナレッジベースのメンテナンス](/ja/cloud/use-dify/knowledge-base/maintain-knowledge-base) を参照してください。
