各指標は、テストケースごとに 1 つの観点をチェックします。回答がナレッジの内容から外れていないか、Agent が適切なツールを選んだか、といった観点です。

ほとんどの指標は判定モデルが採点します。一部の Ragas の指標は、意味の近さを比べるために、ワークスペースの [デフォルトの埋め込みモデル](/ja/cloud/use-dify/workspace/model-providers#アプリが使うデフォルトモデルの選択) も使います。

## スコアの読み方

スコアは 0 から 1 の範囲で、高いほど良い結果です。ただし、良い回答がどの程度のスコアになるかは、指標とフレームワークによって異なります。たとえば Ragas の [Answer Relevancy](#answer-relevancy) では、正確で質問に沿った回答でも、1 に近いスコアになるとは限りません。

各指標のしきい値は、合格とみなせる回答にその指標が付けるスコアをもとに決めてください。

## フレームワークの選択

オープンソースの評価ライブラリとして、[Ragas](https://docs.ragas.io)（v0.3.2）と [DeepEval](https://deepeval.com)（v4.2.0）の 2 つを利用できます。どちらを選ぶかが影響するのは、LLM 回答の指標と検索の指標だけです。

同じ名前の指標でも、フレームワークによって測る内容が異なる場合があります。評価で最も重視する点に応じて選んでください。

- **回答をナレッジの内容に限定したい**：Ragas。Ragas の [Faithfulness](#faithfulness) は、検索されたコンテキストが裏付ける主張だけを数えます。一方、DeepEval では、コンテキストがまったく触れていない主張も忠実とみなされます。
- **[Semantic Similarity](#semantic-similarity) を使いたい**：Ragas。この指標があるのは Ragas だけです。
- **ワークスペースにデフォルトの埋め込みモデルがない**：DeepEval。埋め込みモデルを必要としません。
- **チャンク単位で関連性を判定したい**：DeepEval。DeepEval の [Context Relevance](#context-relevance) はすべてのチャンクを個別に判定しますが、Ragas は検索された内容全体をまとめて評価します。

フレームワークが異なるとスコアを比較できません。比較する予定の実行では、同じフレームワークを使い続けてください。

## LLM 回答の指標

LLM ノードの回答を採点する指標です。各行で、次の情報を使います。

- **質問**：ユーザーが尋ねた内容だけでなく、システムインストラクションを含め、モデルが受け取ったノードのプロンプト全体
- **回答**：モデルの推論過程（ある場合）を除いた、ノードのテキスト出力
- **検索されたコンテキスト**：LLM ノードの [**コンテキスト**](/ja/cloud/use-dify/nodes/llm#コンテキスト変数) 設定が参照する検索ノードから返されたチャンク
- **参照回答**：テストセットにある、そのノードの `expected_output` 列

状況に合った指標を選んでください。

- **回答が検索結果の範囲を超えている**：Faithfulness
- **回答が質問をはぐらかしたり、質問から逸れたりする**：Answer Relevancy
- **回答の事実に誤りがあり、参照回答を用意できる**：Answer Correctness
- **表現は問わず、回答の意味を参照回答と一致させたい**：Semantic Similarity

### Faithfulness

回答が検索結果の内容に沿っているか、つまり回答の各主張が検索されたコンテキストに裏付けられているかをチェックします。ナレッジの内容だけで答えるべきアプリで、根拠のない回答を見つけるのに使います。

- **必要なもの**：検索されたコンテキスト。次の 2 つの方法のいずれかで渡します。

  - **検索ノードから渡す**：LLM ノードの **コンテキスト** でその検索ノードを指定し、プロンプトに **コンテキスト** 変数を挿入します。
  - **コード実行ノードなど、ほかの種類のノードから渡す**：**コンテキスト** は未設定のままにし、プロンプト内でコンテキストを `<context>` タグで囲みます。

  それ以外の設定では Faithfulness にコンテキストが渡らず、スコアが回答の実態を反映しなくなります。

  - **コンテキストに検索ノード以外を指定している**：DeepEval はすべての回答を 1、Ragas はすべての回答を 0 と採点します。
  - **コンテキストが未設定で、タグもない**：DeepEval は採点できず、行に `EVAL_METRIC_FAILED` が表示されます。Ragas はすべての回答を 0 と採点します。

  Ragas ですべての行が 0 になる場合は、まずこの設定を確認してください。
- **スコア**：回答の主張のうち、コンテキストに照らして成り立つものの割合です。
  - Ragas は、コンテキストが裏付ける主張だけを数えます。
  - DeepEval は、コンテキストと矛盾しない主張をすべて数えます。そのため、コンテキストがまったく触れていない主張も忠実とみなされます。
- **値がない場合**：Ragas で、チェックできる文を判定モデルが回答の中に見つけられなかったとき。この場合、行には `Evaluation failed. Please retry or contact support.` と表示されます。DeepEval では、チェックすべき主張のない回答は 1 と採点されます。

<Note>
DeepEval では、**コンテキスト** に指定した検索ノードが何も返さないと、根拠のない回答であっても Faithfulness は 1 になります。

こうした行を見つけるには、その検索ノードも [Context Precision](#context-precision) または [Context Relevance](#context-relevance) で採点してください。検索ノードが何も返さなかった場合、この 2 つの指標はどちらも 0 になります。そのため、条件を AND で結合していれば、どちらか一方に条件を設定するだけで、そうした行を不合格にできます。
</Note>

### Answer Relevancy

回答が質問に答えているかを示します。はぐらかした回答や、質問から外れた回答はスコアが低くなります。

- **必要なもの**：Ragas では、デフォルトの埋め込みモデル。
- **スコア**：
  - Ragas では、まず判定モデルが、回答から逆算した質問を書き出します。次に、それらの質問とノードのプロンプト全体（システムインストラクションを含む）の意味の近さを測ります。正確で質問に沿った回答でも 1 に近いスコアになるとは限らず、「わかりません」のような曖昧な回答は 0 になります。
  - DeepEval では、判定モデルが回答内の各文を関連あり・なしに分類し、関連ありの割合をスコアとします。文を含まない回答は 1 になります。

### Answer Correctness

回答が参照回答の事実を正しく捉えているかを測ります。

- **必要なもの**：参照回答。Ragas では、デフォルトの埋め込みモデルも必要です。
- **スコア**：
  - Ragas は、回答と参照回答をそれぞれ文に分解します。両方に共通する事実はスコアを上げ、回答が取りこぼした事実や、参照回答にない主張はスコアを下げます。両者の意味の近さも、比重は小さいもののスコアに反映されます。
  - DeepEval では、判定モデルが参照回答と照らして回答を 0 から 10 で採点します。そのため、スコアは 0.1 刻みになります。

### Semantic Similarity

表現が違っても、回答が参照回答と同じ内容を述べているかを測ります。この指標は Ragas でのみ利用できます。

- **必要なもの**：参照回答とデフォルトの埋め込みモデル。スコアは埋め込みモデルだけで算出され、判定モデルは呼び出されません。
- **スコア**：個々の事実が一致するかではなく、全体としての意味がどれだけ近いかを表します。事実の正確さも求められる場合は、[Answer Correctness](#answer-correctness) と組み合わせてください。

## 検索の指標

[知識検索](/ja/cloud/use-dify/nodes/knowledge-retrieval) ノードや [Agent ナレッジ検索](/ja/cloud/use-dify/nodes/knowledge-retrieval-v2) ノードの検索結果を採点する指標です。従来型ナレッジベースを直接評価する場合は、そのナレッジベースの検索結果を採点します。判定の対象は検索だけで、アプリの最終的な回答は対象外です。各行で、次の情報を使います。

- **クエリ**：検索ノードのクエリ入力。ナレッジベースの場合は、その行の `query`
- **検索されたチャンク**：その行で返された、ドキュメントの断片（返された順）
- **参照回答**：テストセット内の、対応する `expected_output` 列

状況に合った指標を選んでください。

- **無関係なチャンクに回答が引きずられる**：Context Precision
- **ナレッジにある事実を回答が取りこぼす**：Context Recall
- **参照回答をまだ用意していない**：Context Relevance

### Context Precision

返されたチャンクが回答に役立つか、そして役立つチャンクが上位に並んでいるかをチェックします。スコアが高いほど、検索結果の上位にノイズが少ないことを示します。

- **必要なもの**：参照回答。
- **スコア**：判定モデルがチャンクを 1 つずつ確認し、参照回答にたどり着くのに役立つかを判断します。役立つチャンクが上位にあるほど、スコアは高くなります。どちらのフレームワークも同じ方法で採点します。何も検索されなかった場合、スコアは 0 です。

### Context Recall

参照回答に必要な情報を、検索ですべて見つけられたかを示します。スコアが高ければ、重要な情報を漏れなく取得できています。

- **必要なもの**：参照回答。
- **スコア**：判定モデルが参照回答の各文を検索されたチャンクと照合し、チャンクでカバーされている文の割合をスコアとします。どちらのフレームワークも同じ方法で採点します。

### Context Relevance

返されたチャンクがクエリにどれだけ関連しているかを評価します。

- **必要なもの**：参照回答は不要です。
- **スコア**：
  - Ragas では、判定モデルが検索された内容全体をまとめて評価します。クエリへの回答に関連する情報が少しでも含まれていれば、最高評価を付けます。評価を 2 回行って平均するため、スコアは 0、0.25、0.5、0.75、1 のいずれかになります。判定モデルが読むのは先頭の 7,000 文字だけなので、それより後ろの検索結果はスコアに反映されません。
  - DeepEval では、判定モデルが各チャンクの文を 1 つずつ関連あり・なしに分類し、関連ありの割合をスコアとします。

  どちらのフレームワークでも、何も検索されなかった場合のスコアは 0 です。

## Agent の指標

Agent ノード、または単体で評価する Agent を採点する指標です。どの指標も、Agent の場合は `query` を、[Agent ノード](/ja/cloud/use-dify/nodes/agent) の場合はタスクまたは指示の入力を、タスクとして読み取ります。

判定モデルは、タスクの進め方として妥当な方法を複数認めます。そのため、Agent のツール呼び出しが特定の順序と一致している必要はありません。

状況に合った指標を選んでください。

- **タスクが完了しないまま終わったり、誤って処理されたりする**：Task Completion
- **Agent が無駄なステップを踏んだり、同じステップを繰り返したりする**：Trajectory Quality
- **Agent が誤ったツールを選ぶ**：Tool Selection Correctness
- **Agent がツールに誤った値を渡す**：Tool Argument Correctness

### Task Completion

最終出力がタスクを正しく、漏れなく達成しているかをチェックします。

- **読み取る情報**：タスク、最終出力、Agent が呼び出したツールとその戻り値、成功基準。
- **必要なもの**：`success_criteria` 列の成功基準（任意）。成功基準がない場合、判定モデルはタスクに書かれていることと、そこから必然的に導かれることだけを基準にします。それ以外に期待することがあれば、成功基準に追加してください。
- **スコア**：最も重視されるのは目標の達成です。次に正確さとツールの戻り値との整合性、最後に網羅性が考慮されます。

  成功基準がある場合、判定モデルは各基準を個別にチェックします。満たされていない基準が 1 つでもあると、スコアは大きく下がります。「会議を予約する」のように操作を表す基準は、対応するツール呼び出しが成功した場合にのみ満たされたとみなされます。最終出力に何と書かれていても変わりません。

### Trajectory Quality

最終的な回答が正しいかとは別に、Agent がたどった過程を評価します。

- **読み取る情報**：タスクと、Agent が実行したすべてのステップ。
- **スコア**：タスクを着実に進めたり、無駄なくステップを踏んだり、ツールの戻り値を活用したり、エラーから回復したりすると、スコアは上がります。

  新しい情報を得られないまま同じ操作を繰り返すと、スコアは下がります。ツールが不要な場面では、ツールを使わずに直接答えても高いスコアになることがあります。

### Tool Selection Correctness

その実行で利用できたツールの中から、Agent がタスクに適したツールを選んだかを確認します。

- **読み取る情報**：タスク、その実行で利用できたツール、Agent が選んだ各ツール。
- **スコア**：判定モデルは、タスクに必要な機能が揃っているか、選んだツールがタスクに合っているか、無関係なツールを使っていないかを確認します。ツールを 1 つも呼び出さないことが正しい選択になる場合もあります。

  引数や呼び出し順序は、この指標では考慮されません。引数をチェックするには、[Tool Argument Correctness](#tool-argument-correctness) を使います。
- **値がない場合**：利用できるツールがなく、どのツールも呼び出されなかったとき。スコアは `-` と表示されます。

### Tool Argument Correctness

Agent が呼び出した各ツールに、正しい値（引数）を渡したかをチェックします。ここでの「正しい」とは、ツールが受け付ける形式に合い、かつタスクに適していることです。タスクに適しているかは、その呼び出しの時点で Agent が把握していた情報を踏まえて判断します。

- **読み取る情報**：タスク、各呼び出しの引数、ツールの説明と受け付けるパラメータ、直近のツール呼び出しで得た戻り値。
- **スコア**：判定モデルが評価できた呼び出しの平均値です。呼び出しが失敗したというだけでは、引数が誤っていたとはみなされません。
- **値がない場合**：ツールが 1 つも呼び出されなかったとき、または評価できる呼び出しがなかったとき。スコアは `-` と表示されます。
