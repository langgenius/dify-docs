評価は、アプリがどれだけうまく動作するかを測る機能です。アプリを本番公開してよいかを判断したり、プロンプト、モデル、検索設定を変えるたびに改善したかを確かめたりするのに使います。

評価ではテストセットをアプリで実行し、判定モデル（採点を担当する LLM）が、選んだ指標で各テストケースを採点します。どのケースを合格とするかは設定した条件で決まるため、誰が実行しても同じ基準で判定されます。

結果は実行ごとに保存されます。変更の効果を確かめるには、変更の前後で同じテストセットを実行し、[スコアを比較](#変更前後の結果の比較) します。

<Tip>
評価は <Badge color="blue" size="sm">Professional</Badge> と <Badge color="blue" size="sm">Team</Badge> で利用できます。詳しくは [料金ページ](https://dify.ai/pricing) を参照してください。
</Tip>

## 評価できる対象

テストする対象のサイドバーで **Evaluation**（Agent では **評価**）を開きます。対象ごとに評価できる内容は次のとおりです。

- **[Workflow アプリ](/ja/cloud/use-dify/build/workflow-chatflow)**：LLM、知識検索、Agent ナレッジ検索、Agent の各ノード

- **[スニペット](/ja/cloud/use-dify/build/snippet)**：LLM と Agent の各ノード

- **[従来型ナレッジベース](/ja/cloud/use-dify/knowledge/readme)**：検索の性能（外部ナレッジベースは対象外）

  <Tip>
  [Agent ナレッジベース](/ja/cloud/use-dify/knowledge-base/overview) を確認するには、代わりに専用の [基準質問による評価](/ja/cloud/use-dify/knowledge-base/test-and-tune#run-an-evaluation) を使ってください。
  </Tip>

- **[Agent](/ja/cloud/use-dify/build/new-agent/overview)**：タスクの達成度とツールの使い方

## 事前準備

- テストする Workflow アプリ、スニペット、Agent を公開しておきます。評価では、ドラフトではなく公開済みのバージョンが実行されます。

- Workflow アプリの場合は、[ユーザー入力](/ja/cloud/use-dify/nodes/user-input) ノードに単一ファイル、ファイルリスト、JSON コードのフィールドがないことを確認します。

- [埋め込みモデルが必要な指標](/ja/cloud/use-dify/evaluate/metrics#各指標に必要なもの) を使う場合は、ワークスペースに [デフォルトの埋め込みモデル](/ja/cloud/use-dify/workspace/model-providers#アプリが使うデフォルトモデルの選択) が設定されていることを確認します。

- まず小さなテストセットで試し、全件を実行したときのコストを見積もります。テストケース 1 件につき、アプリを 1 回実行するコストと、判定モデルを呼び出して採点するコストがかかります。[AI クレジット](/ja/cloud/use-dify/workspace/model-providers#ai-クレジットでのモデル利用) を使うモデルでは、どちらもクレジットから差し引かれます。

## 採点内容の選択

評価ページで、次の項目を設定します。

1. [指標](/ja/cloud/use-dify/evaluate/metrics) を追加します。

    Workflow アプリやスニペットで、回答に求める形式など、必要なルールをチェックできる組み込み指標がない場合は、[カスタム評価器](/ja/cloud/use-dify/evaluate/custom-evaluators) を構築します。

2. [評価フレームワーク](/ja/cloud/use-dify/evaluate/metrics#フレームワークの選択) を選びます。影響するのは、LLM 回答の指標と検索の指標だけです。

3. **Judge Model** には、性能の高いモデルを選びます。そのほうが採点が安定します。

    できれば、アプリで使っているモデルとは別のモデルを選んでください。判定モデルに自分の書いた回答を採点させないためです。

<Note>
保存せずに評価ページを離れると、変更は破棄されます。
</Note>

## 合格基準の設定

すべてのテストケースを自分で決めた基準で判定するには、条件を追加します。

1. **Judgment Conditions** で、テストケースが満たすべきスコアごとに条件を追加します。たとえば、回答を生成するノードの Faithfulness ≥ 0.8 などです。

2. 条件が複数ある場合は、すべてを満たすテストケースだけを合格にするなら **AND**、いずれか 1 つを満たせば合格にするなら **OR** を選びます。

採点の厳しさは指標によって異なるため、最初に決めたしきい値は、調整する前提で考えてください。実行後は実際に回答を読み、合格したテストケースが、自分なら合格にするものと一致しているかを確認します。一致しない場合は、しきい値を調整します。

指標が採点できなかった場合など、エラーで終わったテストケースは、条件にかかわらず ✗ と表示されます。

また、テストケースによっては指標の値がないこともあり、その場合 ≥ 0.8 のような条件は満たされません。たとえば [Tool Argument Correctness](/ja/cloud/use-dify/evaluate/metrics#tool-argument-correctness) は、Agent がツールを 1 つも呼び出さなかった場合に値がありません。この指標に条件を設定するのは、すべてのテストケースでツールを呼び出すはずの場合だけにしてください。

## テストセットの準備

テストケースは、ユーザーが実際に尋ねる質問をもとに作成します。アプリが正しく答えられる質問と、誤って答える質問の両方を含めてください。誤答を直すための変更で、正しかった回答が崩れることがあるためです。

<Note>
テンプレートをダウンロードする前に、採点対象の各ノードに重複しないタイトルを付けて公開してください。テンプレートの `expected_output` 列には、ノードのタイトルが列名として付きます。タイトルが同じノードがあると、それらが 1 つの参照回答を共有してしまいます。
</Note>

1. **Input Fields** で **Download XLSX Template** をクリックします。指標を変更したら、そのたびにダウンロードし直してください。

2. テストケースごとに 1 行ずつ入力します。

    - `index`：行ごとに重複しない整数を入力します。

    - 入力：必須の入力列をすべて埋めます。選択タイプの列には、そのフィールドのオプションのいずれかを表記どおりに入力します。チェックボックスタイプの列には、true/false、yes/no、1/0 のいずれかを入力します。

    - `expected_output`（参照回答と比較する指標の場合）：すべての行に、合格とみなす回答を書きます。ナレッジベースの場合は、代わりに、検索結果に含まれるべき重要な事実を列挙しても構いません。

    - `success_criteria`（Task Completion の場合）：Agent が達成すべきことを、1 行に 1 つずつ列挙します。判定モデルは各項目を個別にチェックします。たとえば旅行予約の Agent なら、ある行には次のような内容が入ります。

      ```text
      ユーザーが指定した日付のフライトを予約します
      予約確認番号をユーザーに伝えます
      ```

      空欄にした場合、判定モデルはタスクの内容だけをもとに判定します。

3. 各列の説明が書かれた 2 行目を削除します。

4. ファイルを XLSX 形式、または UTF-8 の CSV 形式で保存します。シートは 1 枚にまとめ、行数は 500 行までにしてください。

## テストセットの実行

**Upload & Run Test** をクリックしてファイルを選び、**Run Test** をクリックします。実行はバックグラウンドで進み、**Test History** で状況を確認できます。

待機中と実行中の評価は、1 つのワークスペースにつき合わせて 3 件までです。

<Note>
Workflow アプリでは、評価による実行もアプリの通常の実行として扱われます。そのため、次の場所で実際の実行に混ざって表示されます。

- [**ログ**](/ja/cloud/use-dify/monitor/logs)：アプリの作成者による `ウェブアプリ` の実行として表示
- [**監視**](/ja/cloud/use-dify/monitor/analysis) と、接続しているトレースサービス
- Workflow アプリが検索する従来型ナレッジベースの **検索テスト** > **記録**：クエリのソースとして `App` を表示

</Note>

### 実行が開始されない場合

実行が開始されない主な原因は次のとおりです。

- `Dataset headers must not be empty.`：テンプレートの 2 行目（各列の説明の行）がファイルに残っています。削除してから、もう一度アップロードしてください。
- `Dataset headers must be unique.`：同じ名前の列が 2 つあります。どちらかの名前を変更するか、削除してください。
- `The selected metrics require a non-empty expected_output; invalid rows: …`：選択した指標には参照回答が必要ですが、表示された行には参照回答がありません。それらの行に参照回答を入力してください。
- `Maximum concurrent runs (3) reached.`：チームメンバーが開始したものも含め、ワークスペースで待機中または実行中の評価がすでに 3 件あります。いずれかが終わるのを待つか、1 件をキャンセルしてください。
- `The customized evaluator must be a published evaluation workflow.`：追加したカスタム評価器が、標準ワークフローに戻されています。もう一度評価ワークフローに切り替えるか、別の評価器を使ってください。

### 実行のキャンセルと再試行

待機中または実行中の評価を中止するには、**Test History** で **Cancel run** をクリックします。採点済みの行は **Test Details** に残りますが、キャンセルした実行には結果ファイルがありません。

実行が `Running` のまま進まないように見える場合は、数分待ってください。実際に停止した実行は、自動的に `Failed` に変わります。

途中で止まった実行を最後まで終えるには、**Test History** で **Retry run** をクリックします。まだ結果のない行だけが採点されます。エラーで終わった行については、原因を修正してから新しい実行を開始してください。

## 結果の確認

**Test History** で実行をクリックすると、**Test Details** が開きます。スニペットの場合は、代わりに実行のメニューから **Download result** を選びます。

スコアの代わりに表示される `-` や、結果ファイルの空欄は、その行で指標に値がなかったことを示します。各指標のスコアを左右する要因については、[評価指標](/ja/cloud/use-dify/evaluate/metrics) を参照してください。

行に本来の結果ではなくエラーが表示された場合は、エラーコードで [トラブルシューティング](#トラブルシューティング) の該当項目を探してください。ただし、コードが付かないエラーもあります。

- `Evaluation failed. Please retry or contact support.`：多くの場合、Ragas の指標がこの行を採点できなかったことを示します。各指標が採点できないケースについては、[評価指標](/ja/cloud/use-dify/evaluate/metrics) を参照してください。
- `No evaluation metrics were generated for this row.`：分岐でスキップされたなどの理由で、この行では採点対象のノードが 1 つも正常に実行されませんでした。Workflow アプリでは、**ログ** でこの行の実行を探し、どの経路をたどったかを確認してください。

結果を共有したり、スプレッドシートで扱ったりするには、ファイルをダウンロードします。実行のメニューから **Download result** を選ぶか、**Test Details** で **Export** をクリックしてください。

## 変更前後の結果の比較

1. テストセットを実行します。

2. プロンプト、モデル、検索設定など、1 か所だけを変更して公開します。

    評価のフレームワーク、指標、条件、判定モデルはそのままにしておきます。そうすれば、スコアの差はすべて今回の変更によるものと判断できます。

3. 同じファイルでもう一度実行します。ファイルが手元にない場合は、最初の実行のメニューから **Download test file** を選びます。

4. それぞれの実行を **Test Details** で開くか、結果ファイルの行を `index` で突き合わせて比較します。

    Workflow アプリやスニペットの場合、この行の実行を開始できませんでした。まず行の入力を確認してください。必須の数値タイプやチェックボックスタイプの入力が空だったり、選択タイプの値がフィールドのオプションになかったりすると、その行は実行前に止まります。テキストがフィールドで許可された長さを超えている場合も同様です。

    すべての行がこのエラーで失敗する場合は、アプリまたはスニペットの作成者がワークスペースを離れていないか確認してください。
  </Accordion>
