## アップデート {#update}

<Note>
  サーバーが 1.17.x 以前から 1.18.0 以降に移行すると、古いビルドはそのサーバーでは動作しなくなります。やり直す作業と変更されたコマンドについては、[Dify 1.18.0 へのアップグレード](/ja/cli/upgrade-across-1-18) を参照してください。
</Note>

サーバーが新しい Dify リリースに移行したら、そのたびに `difyctl` もアップデートします：

1. 対応するサーバーのバージョンに合わせて [インストールコマンド](/ja/cli/get-started#インストール) を再実行します。`DIFYCTL_PREFIX` を使用した場合は、同じ値も指定します。既存のビルドは、そのまま新しいビルドに置き換わります。
2. `difyctl version` を実行し、ビルドのバージョンがサーバーのバージョンと一致していることを確認します。
3. コーディングエージェントが `difyctl` を使う場合は、difyctl スキルを [再インストール](/ja/cli/get-started#コーディングエージェントのセットアップ) します。再インストールしないと、エージェントは古いビルドの手順に従い続けます。

`difyctl` はサーバーの新しいコマンドを自動で取得します。`difyctl help` に古い一覧が表示される場合は、`difyctl refresh cache` を実行してください。

## アンインストール

1. `difyctl` がまだインストールされているうちに、[サインアウト](/ja/cli/manage-sign-in#サインアウト) します。サインアウトするとサーバー上のセッションが終了し、保存済みのトークンも削除されます。バイナリを削除するだけでは、どちらも行われません：

    ```bash
    difyctl logout
    ```

2. バイナリを削除します：

    <CodeGroup>

    ```bash macOS / Linux
    rm ~/.local/bin/difyctl
    ```

    ```powershell Windows
    Remove-Item -Recurse "$env:LOCALAPPDATA\difyctl"
    ```

    </CodeGroup>

    `DIFYCTL_PREFIX` を指定してインストールした場合、バイナリは `<prefix>/bin` にあります。

3. 設定も削除する場合は、設定フォルダを削除します：

    <CodeGroup>

    ```bash macOS
    rm -rf ~/.config/difyctl
    ```

    ```bash Linux
    rm -rf "${XDG_CONFIG_HOME:-$HOME/.config}/difyctl"
    ```

    ```powershell Windows
    Remove-Item -Recurse "$env:APPDATA\difyctl"
    ```

    </CodeGroup>

    `DIFY_CONFIG_DIR` を設定している場合は、代わりにそのフォルダを削除します。

4. コーディングエージェントに difyctl スキルをインストールしていた場合は、[そのエージェントのスキルフォルダ](/ja/cli/get-started#コーディングエージェントのセットアップ) から `difyctl` フォルダを削除します。
