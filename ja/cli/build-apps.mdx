アプリの構築は、コーディングエージェントに任せることをおすすめします。あなたが行うのは、作りたいアプリの説明、質問への回答、エージェントにできない準備だけです。

## 前提条件

- エージェントが [セットアップ済み](/ja/cli/get-started#コーディングエージェントのセットアップ) で、`difyctl` スキルを持ち、Dify サーバーにサインインしていること。
- エージェントがサインインしているアカウントに、エディター以上のロールがあること。
- アプリで使うモデルの API キーが、Dify に設定されていること。
- エージェントを実行するマシンに、`jq` がインストールされていること。
- 既存のアプリを変更する場合は、そのアプリのサービス API アクセスがオンになっていること。

## エージェントにできること

新しいアプリの内容を説明するか、既存のアプリ名を挙げて変更点を伝えます。エージェントは、アプリが何をすべきか、どうテストするかをあなたと相談して決めてから、アプリを構築してテストします。公開については、あなたの了承を得たときだけ行うよう `difyctl` スキルが指示しています。

たとえば：

```text wrap
ヘルプセンターのナレッジベースを使って、顧客からの質問に答える Chatflow を構築してください。
```

```text wrap
サポートチケットを読み取って緊急度で分類し、返信の下書きを作成する Workflow を構築してください。
```

次のような作業も依頼できます：

- **動作の確認**：単一ノードやドラフト全体をテストしたり、公開済みアプリを試しに実行したりします。実行が失敗したときは、どのノードがなぜ失敗したかを調べます。

- **公開**：アプリを公開できる状態か、前回公開したバージョンから何が変わったかを確認してから、公開します。

- **ロールバック**：以前に公開したバージョンを復元し、もう一度公開します。

  <Warning>
    復元すると、ドラフトにある未公開の変更はすべて上書きされます。残しておきたい作業がドラフトにある場合は、先にエクスポートするようエージェントに依頼してください。
  </Warning>

- **アプリに必要な準備**：マーケットプレイスから統合をインストールし（ワークスペースで許可されている場合）、アプリの環境変数を設定します。

- **アプリの管理**：DSL のエクスポート、Web アプリのオン・オフの切り替え、基本情報（名前、アイコン、説明）の変更を行います。アカウントのロールが管理者またはオーナーであれば、アプリのサービス API アクセスのオン・オフも切り替えられます。

## エージェントにできないこと

エージェントが構築・変更できるのは、Workflow アプリと Chatflow アプリだけです。トリガーで始まるワークフローは構築できますが、テストや実行はできません。

アプリに次のいずれかが必要な場合は、Dify で自分で行ってください：

- OAuth でサインインするツールの認可
- GitHub またはパッケージファイルからの統合のインストール
- ナレッジベースの作成とドキュメントのアップロード

## エージェントの作業中

エージェントの作業が終わるまでは、スタジオでアプリを編集しないでください。チームメンバーにも、アプリに触れないよう伝えてください。スタジオで変更を保存すると、エージェントの次の更新が止まります。

エージェントは、起動したフォルダ内の `difyctl/` の下に、アプリごとのフォルダを作って作業内容を保存します。このフォルダは消さずに残し、次回も同じ場所からエージェントを起動してください。そうすれば、エージェントは途中で終わった構築を再開できます。変更を依頼したときも、以前の作業を引き継いで構築できます。
