## 前提条件

- Dify サーバーのバージョンが 1.18.0 以降であること。1.17.x 以前の場合は、[その Dify バージョンのドキュメント](https://github.com/langgenius/dify-docs/branches/all?query=release%2F) を参照してください。
- サーバーで [`OPENAPI_ENABLED` と `ENABLE_OAUTH_BEARER`](/ja/self-host/deploy/configuration/environments#dify-cli-とプログラマティック-api) が `true` に設定されていること。

## インストール

<Info>
`brew install dify` でインストールされるのは、`difyctl` ではなく [Dify のプラグイン開発用 CLI](/ja/develop-plugin/getting-started/cli) です。
</Info>

<Steps>
  <Step title="インストーラーの実行">
    <Tabs>
      <Tab title="macOS / Linux">

        x64 と arm64 をサポートしています。

        ```bash
        curl -fsSL https://raw.githubusercontent.com/langgenius/dify/main/cli/scripts/install-cli.sh | sh
        ```

        このコマンドは、Dify の最新リリースのビルドをインストールします。サーバーが以前のリリースで稼働している場合は、`DIFY_VERSION` にそのバージョンを指定します：

        ```bash
        curl -fsSL https://raw.githubusercontent.com/langgenius/dify/main/cli/scripts/install-cli.sh | DIFY_VERSION=1.18.0 sh
        ```

        スクリプトはダウンロードしたファイルのチェックサムを検証し、`~/.local/bin/difyctl` にインストールします。
      </Tab>
      <Tab title="Windows">

        対応プラットフォーム：x64。

        ```powershell
        irm https://raw.githubusercontent.com/langgenius/dify/main/cli/scripts/install.ps1 | iex
        ```

        このコマンドは、Dify の最新リリースのビルドをインストールします。サーバーが以前のリリースで稼働している場合は、先に `DIFY_VERSION` にそのバージョンを設定します：

        ```powershell
        # この PowerShell セッションの間は有効
        $env:DIFY_VERSION = "1.18.0"
        irm https://raw.githubusercontent.com/langgenius/dify/main/cli/scripts/install.ps1 | iex
        ```

        スクリプトはダウンロードしたファイルのチェックサムを検証し、`%LOCALAPPDATA%\difyctl\bin\difyctl.exe` にインストールします。

      </Tab>
      <Tab title="手動ダウンロード">

        1. [Dify の GitHub Releases](https://github.com/langgenius/dify/releases) から、サーバーの Dify バージョンに合うリリースを選び、2 つのアセットをダウンロードします：

            - お使いのプラットフォーム向けのバイナリ（`difyctl-v<version>-<os>-<arch>`）
            - チェックサムマニフェスト（`difyctl-v<version>-checksums.txt`）

        2. バイナリの SHA-256 ハッシュを計算し、チェックサムファイル内の対応するエントリと比較します。

            値が一致しない場合、ダウンロードしたファイルは破損しているか改ざんされています。削除して再度ダウンロードしてください。

            <CodeGroup>

            ```bash macOS
            shasum -a 256 difyctl-v<version>-darwin-<arch>
            ```

            ```bash Linux
            sha256sum difyctl-v<version>-linux-<arch>
            ```

            ```powershell Windows
            Get-FileHash difyctl-v<version>-windows-x64.exe
            ```

            </CodeGroup>

        3. バイナリを `PATH` の通ったディレクトリに配置します：

            <CodeGroup>

            ```bash macOS / Linux
            chmod +x difyctl-v<version>-<os>-<arch>
            mkdir -p ~/.local/bin
            mv difyctl-v<version>-<os>-<arch> ~/.local/bin/difyctl
            ```

            ```powershell Windows
            New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\difyctl\bin" | Out-Null
            Move-Item difyctl-v<version>-windows-x64.exe "$env:LOCALAPPDATA\difyctl\bin\difyctl.exe"
            ```

            </CodeGroup>
      </Tab>
    </Tabs>

    <Tip>
    別のフォルダにインストールする場合や、その他のインストール設定を変更する場合は、[設定](/ja/cli/reference/configuration) を参照してください。
    </Tip>
  </Step>
  <Step title="インストールの確認">

    ```bash
    difyctl version
    ```

    `command not found` が表示される場合は、インストールディレクトリが `PATH` に含まれていません。次のように追加します：

    <CodeGroup>

    ```bash macOS / Linux
    # ~/.zshrc または ~/.bashrc に追加する。その場で実行しただけでは、セッションが終わるまでしか有効にならない
    export PATH="$HOME/.local/bin:$PATH"
    ```

    ```powershell Windows
    [Environment]::SetEnvironmentVariable('PATH', "$env:LOCALAPPDATA\difyctl\bin;" + [Environment]::GetEnvironmentVariable('PATH', 'User'), 'User')
    # その後、新しいターミナルを開く
    ```

    </CodeGroup>
  </Step>
</Steps>

## サインイン

`difyctl` はブラウザ経由でサインインします。サインインの有効期間は既定で 14 日間です（[`OAUTH_TTL_DAYS`](/ja/self-host/deploy/configuration/environments#dify-cli-とプログラマティック-api) で変更できます）。

<Steps>
  <Step title="サインインの開始">
    ブラウザで Dify を開く際のアドレスを指定します：

    ```bash
    difyctl login --server https://dify.example.com
    ```

    SSH 経由での実行時などブラウザが開かない場合は、`difyctl` が表示した URL を任意のデバイスで開いてください。

    ローカルサーバーが `http://` や自己署名証明書を使っている場合は、`--insecure` を追加します。この設定は、`--insecure` なしでサインインし直すまで、以降のすべてのコマンドに適用されます。ローカル開発以外では使わないでください。
  </Step>
  <Step title="ブラウザでの承認">
    **difyctl を認証** ページでコードを入力し、**続ける** をクリックします。コードの有効期限は 15 分です。

    ページにアカウントが表示されたら、そのアカウントが正しいことを確認してから **認証する** をクリックします。`difyctl` とコーディングエージェントは、このアカウントとして動作します。このアカウントでできることは、すべて実行できます。意図しないアカウントの場合は、**キャンセル** をクリックし、正しいアカウントで Dify にサインインしてから、もう一度サインインを開始します。
  </Step>
</Steps>

後でサインインし直す場合やサインアウトする場合は、[サインインの管理](/ja/cli/manage-sign-in) を参照してください。サインインに失敗した場合は、[トラブルシューティング](#トラブルシューティング) を参照してください。

## アプリの一覧表示

ワークスペース内のアプリを一覧表示して、`difyctl` が動作することを確認します：

```bash
difyctl get console_app
```

一覧に表示されるのは、サービス API アクセスがオンになっているアプリだけです。

## コーディングエージェントのセットアップ

`difyctl` スキルは、コーディングエージェントに `difyctl` の使い方を教えます。使用するコーディングエージェントごとに、そのエージェントのスキルフォルダにスキルをインストールします：

```bash
# Claude Code
difyctl install skills ~/.claude/skills

# Codex、Cursor、Gemini CLI、GitHub Copilot、OpenCode など、ほとんどのエージェント
difyctl install skills ~/.agents/skills
```

その他のエージェントの場合は、スキルフォルダの場所をそのエージェントのドキュメントで確認してください。エージェントがスキルを認識しない場合は、再起動してください。

### コマンドと API キーの管理

シェルコマンドの実行前に承認を求めるエージェント側の設定は、オンのままにしておいてください。`difyctl` 自体は、コマンドを実行する前に確認を求めません。スキルは、削除、統合のインストール、アプリの公開を行う前にあなたに確認するよう、エージェントに指示しています。ただし、実際に確認するかどうかは、エージェントが使う AI モデル次第です。

<Tip>
  エージェントに確認なしで情報を調べさせるには、`difyctl get`、`difyctl describe`、`difyctl knowledge_fs` <Badge color="blue" size="sm">Cloud</Badge> を許可します。いずれもサーバーからの読み取りしか行いません。
</Tip>

モデルプロバイダーの API キーなど、チャットに入力した内容はすべてエージェントのモデルを経由します。キーをモデルに渡したくない場合は、事前に自分で Dify にキーを追加しておくか、求められた時点で自分で追加するとエージェントに伝えてください。

## 自分でコマンドを探す方法

作業内容を短い言葉で `help` に伝えると、一致するコマンドが一覧表示されます。たとえば、アプリを公開するコマンドを探すには、次のように実行します：

```bash
difyctl help publish app
```

一覧から探す場合は、`difyctl help` を実行します。コマンドへの値の渡し方や、結果に含まれるヒントに従う方法については、[コマンドの検索と実行](/ja/cli/find-and-run-commands) を参照してください。

## トラブルシューティング

| メッセージ | 対処方法 |
|:--|:--|
| `only https:// hosts are accepted` | `https://` のアドレスを使う。ローカルの `http://` サーバーでは、`--insecure` を追加する。 |
| `network error calling POST <server>/openapi/v1/oauth/device/code` | サーバーのアドレスとネットワークを確認する。<br/><br/>サーバーの証明書を `difyctl` が検証できない場合も、同じエラーで失敗する。自己署名証明書を使うローカルサーバーでは、`--insecure` を追加する。 |
| `this Dify host does not implement the OAuth device flow` | サーバーのアドレスを確認する。アドレスが正しい場合は、サーバーで `OPENAPI_ENABLED` と `ENABLE_OAUTH_BEARER` を `true` に設定する。 |
| ブラウザ：`こちら側で問題が発生しました。しばらくしてからもう一度お試しください。` | サーバーで `ENABLE_OAUTH_BEARER` を `true` に設定する。 |
| `authorization denied` | ブラウザで **キャンセル** がクリックされた。もう一度 `login` を実行する。 |
| `code expired before authorization` | 15 分以内にコードが承認されなかった。もう一度 `login` を実行する。 |
| `OS keychain is unreachable` | `--no-keyring` を付けてサインインし直し、トークンをファイルに保存する。 |
