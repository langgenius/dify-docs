## クイックスタート

### ダウンロード

特定のバージョンを Dify Enterprise の [リポジトリ](https://langgenius.github.io/dify-enterprise-docker-compose/) からダウンロードします。

`wget` を使用する場合：

```bash
wget https://langgenius.github.io/dify-enterprise-docker-compose/dify-docker-compose-<version>.tgz
```

`curl` を使用する場合：

```bash
curl -O https://langgenius.github.io/dify-enterprise-docker-compose/dify-docker-compose-<version>.tgz
```

## インストール

1. ダウンロードしたファイルをデプロイ用ディレクトリに展開します：

```bash
mkdir dify-enterprise
tar -xzf dify-docker-compose-<version>.tgz -C ./dify-enterprise/
```

2. 環境変数テンプレートをコピーし、デプロイ用ディレクトリで Docker Compose を起動します：

```bash
cd dify-enterprise
cp .env.example .env
docker compose up -d
```

3. Dify Enterprise へのアクセス：

サーバーの IP アドレスを取得し、ローカル PC の `/etc/hosts` に以下のように追加してください。

```bash
4.152.1.216 console.dify.local  
4.152.1.216 app.dify.local  
4.152.1.216 api.dify.local  
4.152.1.216 upload.dify.local  
4.152.1.216 enterprise.dify.local
```

4. [Dify サービスの状態を確認する](/ja/3.14.x/deploy/verify-services-status)

5. [ライセンス認証を行う](/ja/3.14.x/deploy/license-activation)

## コミュニティ版からのアップグレード

<Note>
**3.10 で環境変数の構成が再編されました**：単一だった `.env.example` は、スリム化された `.env.example` と任意の `envs/*.env.example` ファイルに分割され、エンタープライズ設定は有効な状態で `envs/enterprise/` 配下に同梱されます。バックアップした `.env` の復元は安全です。Docker Compose は `.env` を**最後**に読み込むため、既存の値が優先され、移行せずにそのままデプロイは動作し続けます。3.10 の新しいデフォルト値や新規追加の変数を取り込みたい場合は、任意で `.env` を新しい `.env.example` に合わせて調整できます。同梱の `dify-env-sync.sh` は `.env.example` から `.env` への一方向同期を行います（カスタム値を保持し、事前にバックアップを取り、削除されたキーを報告します）。
</Note>

1. Enterprise データベースを作成（コミュニティ版が起動中である必要があります）：

```bash
docker exec -it dify-db-1 psql -U postgres -c "CREATE DATABASE enterprise;"
```

**ヒント**：`docker container ls` コマンドで `db` コンテナ名を確認して適宜調整してください。

2. コミュニティ版を停止します：

```bash
docker compose down
```

3. データと設定をバックアップします（`sudo` が必要な場合があります）：

```bash
tar -czf backup.tgz volumes .env
```

4. `backup.tgz` と `dify-docker-compose-<version>.tgz` 以外のファイルをすべて削除します。

5. 新しいファイルを展開します：

```bash
tar -xzf dify-docker-compose-<version>.tgz -C /path/to/directory
```

6. バックアップから復元：

```bash
rm -rf volumes
tar -xzf backup.tgz
```

7. `docker-compose.yaml` や `nginx/conf.d/default.conf` などのカスタム設定がある場合、内容を反映してください。

8. Docker Compose を再起動します：

```bash
docker compose up -d
```

9. `/etc/hosts` にドメインと IP を追加：

```bash
4.152.1.216 console.dify.local  
4.152.1.216 app.dify.local  
4.152.1.216 api.dify.local  
4.152.1.216 upload.dify.local  
4.152.1.216 enterprise.dify.local
```

10. [Dify サービスの状態を確認](/ja/3.14.x/deploy/verify-services-status)
11. [ライセンス認証を行う](/ja/3.14.x/deploy/license-activation)

## 高度な設定

### 設定ファイル

設定はデプロイ用ディレクトリ内の複数のファイルに分かれています：

- **`.env`**：実際に有効な設定です。初回起動の前に `.env.example` からコピーしてください（`cp .env.example .env`）。すべての上書き設定はここに記述します。Docker Compose はこのファイルを**最後**に読み込むため、`.env` の値が最も優先され、他のすべてを上書きします。
- **`envs/enterprise/*.env`**：エンタープライズ向けサービス設定です。**有効な状態**で同梱され自動的に組み込まれるため、標準的なデプロイではコピーや編集は不要です。
- **`envs/*.env.example`**：テーマ別（データベース、ベクトルストア、インフラなど）にまとめられた任意の高度な設定です。あるグループを有効にするには、`.example` 接尾辞を外してファイルをコピーします（例：`cp envs/databases/redis.env.example envs/databases/redis.env`）。

以下の各設定については、変数を `.env` に追加するだけで十分です。上記ファイルのデフォルト値を上書きします。

### ドメイン要件

Dify Enterprise では以下の5つのドメイン設定が必要です：

* Console: `console.dify.local`
* Services API: `api.dify.local`
* APP: `app.dify.local`
* Files: `upload.dify.local`
* Enterprise: `enterprise.dify.local`

`.env` ファイルに以下のように設定：

```bash
# .env

CONSOLE_API_URL="http://console.dify.local"
CONSOLE_WEB_URL="http://console.dify.local"
SERVICE_API_URL="http://api.dify.local"
APP_API_URL="http://app.dify.local"
APP_WEB_URL="http://app.dify.local"
FILES_URL="http://upload.dify.local"
ENTERPRISE_URL="http://enterprise.dify.local"
```

### Agent サンドボックスバックエンド

Agent のサンドボックスは 2 種類のバックエンドのどちらかで動作し、`.env` ファイルの `DIFY_AGENT_RUNTIME_BACKEND` で選択します。バックエンドを 1 つ選び、対応する変数ファミリーを設定してください。この選択は、Agent の Home Snapshot（永続ファイル）の保存先も決めます。

デフォルトでは、デプロイに同梱の `local_sandbox` コンテナを使用します：

```bash
# .env

DIFY_AGENT_RUNTIME_BACKEND=local
DIFY_AGENT_LOCAL_SANDBOX_ENDPOINT=http://local_sandbox:5004
DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN=
```

旧名称の `DIFY_AGENT_SHELLCTL_ENTRYPOINT` と `DIFY_AGENT_SHELLCTL_AUTH_TOKEN` は、既存デプロイ向けのフォールバックとして引き続き受け付けられます。

サンドボックスを [E2B](https://e2b.dev/) で実行するには、`docker-compose.e2b.yaml` オーバーレイを重ねて起動し、E2B の変数ファミリーを設定します：

```bash
# .env

DIFY_AGENT_E2B_API_KEY=your-e2b-api-key
DIFY_AGENT_E2B_TEMPLATE=difys-default-team/dify-agent-local-sandbox
DIFY_AGENT_E2B_ACTIVE_TIMEOUT_SECONDS=3600
DIFY_AGENT_E2B_SHELLCTL_PORT=5004
```

- `DIFY_AGENT_E2B_API_KEY`：E2B の API キー。`E2B_API_KEY` と `E2B_API_TOKEN` もデプロイレベルのフォールバックとして使えます。
- `DIFY_AGENT_E2B_TEMPLATE`：E2B のサンドボックステンプレート。デフォルトは `difys-default-team/dify-agent-local-sandbox`。
- `DIFY_AGENT_E2B_ACTIVE_TIMEOUT_SECONDS`：1 つのサンドボックスリースの最長連続稼働時間。デフォルト `3600` で、独立して設定できる Agent 実行期限（`DIFY_AGENT_RUN_TIMEOUT_SECONDS`）のデフォルトと一致します。
- `DIFY_AGENT_E2B_SHELLCTL_PORT`：サンドボックスランタイムが待ち受けるポート。デフォルト `5004`。
