Let's look back the upgrades we've made for our email assistants.

- Learned to Read: It can search a Knowledge Base
- Learned to Choose: It uses Conditions to make decisions
- Learned to Multitask: It handles multiple questions via Iteration
- Learned to Use Tools: It can access the Internet via Google Search

These nodes work, but we have had to describe every step in advance. What if we could give the job to an AI teammate that already knows how to reason, use its resources, and improve over time?

Meet your AI teammate: the **Agent**.

## From Workflow to Agentic Workflow

A traditional workflow follows a path designed by its builder. An Agentic workflow combines that dependable structure with an Agent that can decide how to complete a task inside the boundaries you set.

Think of the workflow as the shared operating procedure and the Agent as the teammate performing part of it:

- The **workflow** supplies inputs, order, checks, fallbacks, and outputs.
- The **Agent** works toward a goal, uses its available knowledge and tools, and returns a result.
- The **Agent node** is where that Agent appears in this particular workflow.

The same Agent can be invited into several workflows, or even appear more than once in one workflow. Its core identity and capabilities belong to the Agent. The instructions you add in an Agent node describe only its job at that point in the workflow.

You do not need to install or select a reasoning strategy. The Agent manages its own reasoning loop. Your job is to give it the right assignment, inputs, and expected outputs.

## Agent & Agent Node

For adding an agent to a workflow, there’re two ways to get started:

- **Invite from Agents:** Reuse an existing Agent that you or your team has already built.
- **Create Blank Agent:** Create a temporary Agent directly on the canvas. This is useful for a role that exists only in this workflow. You can save it to the Agent Roster later if it becomes reusable.

In the earlier lessons, we did not create an agent, so we will use a Blank Agent so this tutorial works from a clean workspace. At the end, you can save it to the Agents page and reuse it elsewhere.

After this lesson, the workflow will have only three nodes: <br />`Start - Knowledge Retrieval - Product Support Agent - Output`

## Two Ways to Add an Agent

When adding an Agent to a workflow, you can: **Invite an existing Agent:** Reuse an Agent that you or your team has already created. **Start from Scratch:** Create an Agent directly inside the workflow.

Since we have not created a reusable Agent, so we will start from scratch. This agent will be stored as part of this workflow, and you can optionally save it to the agent console as a separate agent.

## Hands-on 1: Create an Agent

Our goal is to replace the entire manually orchestrated middle section with one Agent. The Agent will receive the complete customer email, identify and answer every question, and return one coherent email body.

<Steps>
  <Step title="Remove Extra Nodes">
    Go to the sub-process of the Iteration. Keep knowledge retrieval node, and delete other nodes in side it.
  </Step>
  <Step title="Add Knowledge Retrieval">
    After Start, click \+ and add a Knowledge Retrieval node. Select the Dify product Knowledge Base used in the previous lessons.

    <Frame>
      ![Difyworkflow101 Lesson08 Addknowledgeretrieval](/images/difyworkflow101-lesson08-addknowledgeretrieval.png "Difyworkflow101 Lesson08 Addknowledgeretrieval")
    </Frame>
  </Step>
  <Step title="Add an Agent Node">
    After **Knowledge Retrieval**, click **\+**, choose **Agent**, and select **Start from Scratch**.

    <Frame>
      ![Difyworkflow101 Lesson08 Createagentnode](/images/difyworkflow101-lesson08-createagentnode.png "Difyworkflow101 Lesson08 Createagentnode")
    </Frame>

    This opens the agent builder window over the workflow canvas:

    - The **Configure** panel on the left contains the model, prompt, skills, files, tools, etc. You can set them up manually.
    - **Build** on the right lets you build your agent by chatting, and Dify fills the configuration automatically.
    - **Preview** lets you try the Agent before returning to the workflow.

    <Frame>
      ![Difyworkflow101 Lesson08 Buildmode](/images/difyworkflow101-lesson08-buildmode.png "Difyworkflow101 Lesson08 Buildmode")
    </Frame>
  </Step>
  <Step title="Connect to the Required Resources">
    Before entering Build Mode, let’s do a quick setup.<br />**Model:** select a compatible model if the current model is missing or marked incompatible.<br />**Tools:** add Google Search.
  </Step>
  <Step title="Build the Agent by Chatting (Build Mode)  ">
    In Build Mode, enter the following request.

    ```text wrap
    Create a Dify Product Support Agent.  
    Configure the Agent to use context provided by the workflow first and search only when that context is insufficient or current information is required.  
    Do not create duplicate search capabilities.
    ```

    <Frame>
      ![Difyworkflow101 Lesson08 Buildbychatting](/images/difyworkflow101-lesson08-buildbychatting.png "Difyworkflow101 Lesson08 Buildbychatting")
    </Frame>

    After Build finishes, Dify automatically generates the essential Agent assets:  

    product-support: An embedded Skill containing the Agent’s support behavior and source-use rules.  

    build\_note.md: A generated note summarizing what was created during the building process.
  </Step>
  <Step title="Add the Main Prompt">
    After you click Apply, Build mode closes and the Configure panel becomes editable again. Add the following instruction to the main Prompt:

    ```text wrap
    Answer accurately using the context provided with each assignment. Treat that context as the primary source. Use Google Search only when the context is insufficient, irrelevant, or outdated.
    ```

    The generated Skill defines the Agent’s reusable product-support expertise. The main Prompt adds a clear rule for when the Agent should use Google Search.

    <Frame>
      ![Difyworkflow101 Lesson08 Generatedskills](/images/difyworkflow101-lesson08-generatedskills.png "Difyworkflow101 Lesson08 Generatedskills")
    </Frame>
  </Step>
  <Step title="Preview the Agent">
    Switch to Preview and ask a Dify product question to confirm if the agent responds with concise answer or use Google Search when necessary. When the setup looks correct, close the Agent Builder and return to the workflow canvas.
  </Step>
</Steps>

## Hands-on 2: Assign the Workflow Task

Now, the Agent has a reusable role, support expertise, and searching tool. Next, let’s give it an assignment of what to do in this workflow. 

<Steps>
  <Step title="Provide the Email and Retrieved Knowledge">
    Select the agent node, and navigate to agent task, enter:

    Answer every question or request in `User Input / (x) email_content`  

    Use this retrieved product knowledge first `Knowledge Retrieval / (x) result`.	

    Combine all answers into an email.

    <Frame>
      ![Difyworkflow101 Lesson08 Agenttask](/images/difyworkflow101-lesson08-agenttask.png "Difyworkflow101 Lesson08 Agenttask")
    </Frame>
  </Step>
</Steps>

<Check>
  🎉 The Iteration node is now upgraded.
</Check>

Since the Iteration node generates a list of answers, we need to stitch them back together into one email.

## Hands-on 2: Final Assembly

<Steps>
  <Step title="The Final Editor (LLM)">
    1. Add an LLM node after the Iteration node.
    2. Click on it and add prompt into the system. Feel free to check on the prompt below, or edit by yourself.

       Combine all answers for the original email.
       Write a complete, clear, and friendly reply to the customer.
       Signature: Anne
