App Builder is an AI assistant that helps you build and refine Workflow and Chatflow apps through conversation. When you build or modify an app, App Builder proposes a plan and updates the draft after your approval. Use it to start a new app or update an existing one, alongside the canvas editor.

<Info>
App Builder needs a model to plan and build your app. In **Integrations** > [**Model Provider**](/en/self-host/use-dify/workspace/model-providers), configure a provider, then open **Default Models** to select and save a **System Reasoning Model**.
</Info>

<Note>
If your app needs [Knowledge Retrieval](/en/self-host/use-dify/nodes/knowledge-retrieval), [Human Input](/en/self-host/use-dify/nodes/human-input), or [classic Agent](/en/self-host/use-dify/nodes/agent) nodes, you need to add them in the canvas editor.
</Note>

## Describe What You Need

<Info>
You need the Editor role or above to create, test, and publish an app.
</Info>

In Studio, select **Create**, then choose **Workflow** or **Chatflow**. Describe what you want the app to do: what information you’ll provide, what result you need, and any rules it should follow.

<Warning>
Do not include API keys, tokens, passwords, or sensitive production data in your prompts, App Builder conversations, or test inputs.
</Warning>

For example, you might enter:

```text wrap
Build a refund eligibility Workflow. The inputs are the number of days since delivery, whether the item has been opened, and the refund reason. A request is eligible only if the item was delivered within the last 30 days and is unopened. State whether the request is eligible for a refund and explain why.
```

To refine your description before sending, select **Optimize with AI** and review the revised text.

When ready, select **Send**. App Builder opens in the editor and starts working on your request.

If App Builder asks for more details, add any missing information and correct anything it misunderstood.

<a id="review-resources"></a>

## Review Resources

Review the models, tools, or published [Agent apps](/en/self-host/use-dify/build/new-agent/overview) recommended for your app. Deselect any you don’t want the app to use, then select **Confirm resources**.

<a id="review-the-proposed-plan"></a>

## Review the Plan

Review the plan to make sure it matches what you want the app to do:

- **Inputs and output**: The app will ask for information you can provide and produce the result you need.
- **Steps and rules**: The app will follow your rules and only take actions you want.
- **External actions**: Messages will go to the right recipients, and updates will affect the right records.

If anything is missing or incorrect, select **Continue adjusting** and describe what you want to change.

When the plan matches your goal, select **Approve plan**. App Builder applies the changes to **Current Draft**, the unpublished version of the app.

<a id="test-the-draft"></a>

## Test and Refine

<a id="run-and-review-the-test"></a>

<a id="review-test-inputs"></a>

### Test the Draft

If a selected model needs setup, configure it in [Model Providers](/en/self-host/use-dify/workspace/model-providers). Complete any required [tool authorization](/en/self-host/use-dify/workspace/tools) before testing.

After App Builder applies the plan, select **Run test** to review the test inputs. Use inputs for which you know the expected result.

If the test form includes checkboxes for real actions:

- Leave them unchecked to simulate the actions without sending messages or updating records.
- To run an action for real, check its account, destination, and data before selecting its checkbox.

<Warning>
Model calls and read operations can still contact external services, even when other steps are simulated. App Builder tests simulate or block destructive actions, such as deleting data.
</Warning>

Select **Run the test** and compare the output with what you expected. Use **Run details** to investigate errors or unexpected output. If you enabled a real action, verify its result in the connected service.

If App Builder suggests a fix, review it and select **Apply the fix**.

<a id="refine-the-draft"></a>

### Refine the Draft

If the draft isn’t quite what you need, you can refine it before publishing. Test it again after making changes.

#### Have App Builder Make the Changes

App Builder can also edit existing Human Input and classic Agent nodes.

Select **Continue adjusting** and describe what you want to change. For unexpected output, include what you got and what you expected.

Review the updated plan, then select **Approve plan** to apply it.

<a id="continue-after-manual-edits"></a>

#### Make the Changes Yourself

If you prefer to edit nodes yourself, use the canvas editor. Knowledge Retrieval settings must be changed here.

If you then return to App Builder and it asks how to proceed:

- Select **Continue** to pick up where App Builder left off.
- Select **Restart from current draft** to start over using your edited draft.

Both options keep your manual edits.

<a id="undo-this-attempt"></a>

<a id="revert-the-draft"></a>

### Revert the Draft

<Warning>
Actions performed in external services during tests remain in effect after you select **Revert**.
</Warning>

Select **Revert** to return to App Builder’s latest restore point, a copy of the draft saved before a build, change, or fix. Any later draft changes, including manual edits, are discarded.

<a id="decide-whether-to-publish"></a>

## Publish

When the results meet your needs and the current draft has passed a test without simulated steps, select **Publish** to make it live.

If you need more review or testing, or your test used simulated steps, select **Keep draft**. In the canvas editor, use **Test Run** for a Workflow or **Preview** for a Chatflow. When the results meet your needs, select **Publish** in the top toolbar.

</Tab>

## Describe Your Changes

<Info>
You need the Editor role or above to edit, test, and publish an app.
</Info>

You can modify any existing Workflow or Chatflow app, including one built entirely in the canvas editor.

Open your app in the editor, then select the **App Builder** icon in the upper-right canvas toolbar. Describe what you want to change and what should stay the same.

<Warning>
Do not include API keys, tokens, passwords, or sensitive production data in your prompts, App Builder conversations, or test inputs.
</Warning>

If App Builder asks you to review your changes, correct anything it misunderstood and check any model or tool selections.

<a id="modify-review-the-proposed-plan"></a>

## Review the Plan

Review the plan to make sure it matches what you want the app to do:

- **Inputs and output**: The app will ask for information you can provide and produce the result you need.
- **Steps and rules**: The app will include your requested changes and keep what should stay the same.
- **External actions**: Messages will go to the right recipients, and updates will affect the right records.

If anything is missing or incorrect, select **Continue adjusting** and describe what you want to change.

When the plan matches your goal, select **Approve changes**. App Builder applies the changes to **Current Draft**, the unpublished version of the app.

## Get Help with an Error <a id="get-help-with-errors"></a>

<Info>
You need the Editor role or above to fix, test, and publish an app.
</Info>

If the canvas editor reports a node configuration error or a Workflow test fails, you can ask App Builder to help resolve it.

Some fixes update the draft without asking for approval.

Select **Fix with App Builder**, when available:

- In **Checklist**, next to the node configuration error.
- In the failure panel for the current Workflow **Test Run**.

## Review the Changes

Review App Builder’s diagnosis and suggested fix. If approval is required, select **Approve fix** to apply it. Otherwise, App Builder applies the fix automatically.

For errors reported in **Checklist**, select **Re-check** to confirm that the configuration error is resolved. This checks the configuration without running the app.
