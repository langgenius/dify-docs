App Builder is an AI assistant that helps you build and refine Workflow and Chatflow apps through conversation. Describe what you want to achieve, and App Builder proposes a plan and configures nodes and connections in the draft after your approval. Use it to start a new app or update an existing one, alongside the canvas editor.

<Note>
If your app needs Knowledge Retrieval, Human Input, or classic Agent nodes, add them in the canvas editor. You can edit existing Human Input and classic Agent nodes with App Builder. To adjust Knowledge Retrieval settings, use the canvas editor.
</Note>

<Info>
App Builder needs a model to plan and build your app. In **Integrations** > [**Model Provider**](/en/self-host/use-dify/workspace/model-providers), configure a provider, then open **Default Models** to select and save a **System Reasoning Model**.
</Info>

## Describe What You Need

<Info>
Creating an app requires the Editor role or above.
</Info>

In Studio, select **Create**, then choose **Workflow** or **Chatflow**. Describe what you want the app to do, including the inputs it will receive, the result you need, and any rules it should follow.

<Warning>
Do not include API keys, tokens, passwords, or sensitive production data in your prompts, App Builder conversations, or test inputs.
</Warning>

For example, you might enter:

```text wrap
Build a refund eligibility Workflow. The inputs are the number of days since delivery, whether the item has been opened, and the refund reason. A request is eligible only if the item was delivered within the last 30 days and is unopened. State whether the request is eligible for a refund and explain why.
```

To refine your description before sending, select **Optimize with AI** and review the revised text.

When ready, select **Send**. App Builder opens in the editor and starts working on your request.

If App Builder asks for more details, review and update the **Review the requirements** form, then select **Submit requirements**.

<a id="review-resources"></a>

## Review Resources

Review the suggested models, tools, or published [Agent apps](/en/self-host/use-dify/build/new-agent/overview). Deselect any you do not want to use, then select **Confirm resources**. If no resources are recommended, select **Confirm resources** to continue.

Before testing, configure the selected models in [Model Providers](/en/self-host/use-dify/workspace/model-providers) and complete any required [tool authorization](/en/self-host/use-dify/workspace/tools).

<a id="review-the-proposed-plan"></a>

## Review the Plan

Review the plan to make sure it matches what you want the app to do:

- **Inputs and output**: The app uses inputs you can provide and returns the result you need.
- **Steps and rules**: The steps follow your rules and include only actions you want the app to take.
- **External actions**: If the app sends information or updates records, the data and destinations are correct.

If anything is missing or incorrect, select **Continue adjusting** and describe what you want to change.

When the plan matches your goal, select **Approve plan**. App Builder applies the changes to **Current Draft**, the unpublished version of the app.

<a id="test-the-draft"></a>

## Test and Refine

<Info>
Testing an app requires the Editor role or above.
</Info>

<a id="run-and-review-the-test"></a>

<a id="review-test-inputs"></a>

### Test the Draft

After App Builder applies the plan, select **Run test**. Review the suggested inputs and adjust them if needed. Choose a case where you know what result to expect.

If the test form includes checkboxes for real actions:

- Leave them unchecked to simulate the actions without sending messages or updating records.
- To run an action for real, check its account, destination, and data before selecting its checkbox.

<Warning>
Model calls and read operations can still contact external services, even when other steps are simulated. App Builder tests simulate or block destructive actions, such as deleting data.
</Warning>

Select **Run the test** and compare the output with what you expected. Use **Run details** to investigate errors or unexpected output. If you enabled a real action, verify its result in the connected service.

If the test fails, check the error message for input or configuration problems. If App Builder proposes a repair, review it and select **Apply the fix**.

If you need to investigate further, select **Keep draft** and continue testing in the canvas editor.

<a id="refine-the-draft"></a>

### Refine the Draft

If the draft isn’t quite what you need, select **Continue adjusting** and describe what you want to change. For unexpected output, include what you got and what you expected.

Select **Submit requirements**, confirm resources if prompted, then review the updated plan and select **Approve plan**.

<a id="continue-after-manual-edits"></a>

You can also edit the draft directly on the canvas. If App Builder then asks how to proceed:

- Select **Continue** to finish the current plan.
- Select **Restart from current draft** to replace the current plan with a new one based on your edited draft.

Both options keep your manual edits. Test again after making changes.

<a id="undo-this-attempt"></a>

<a id="revert-the-draft"></a>

### Revert the Draft

To undo recent draft changes, select **Revert**. App Builder restores its latest restore point and discards changes made since then, including manual edits.

<Warning>
Revert doesn’t undo actions already performed in external services during tests.
</Warning>

<a id="decide-whether-to-publish"></a>

## Publish

<Info>
Publishing an app requires the Editor role or above.
</Info>

When the results meet your needs and the current draft has passed a test without simulated steps, select **Publish** to make it live.

If you need more review or testing, or your test used simulated steps, select **Keep draft**. In the canvas editor, use **Test Run** for a Workflow or **Preview** for a Chatflow. When the results meet your needs, select **Publish** in the top toolbar.

</Tab>

## Describe Your Changes

<Info>
Editing an app requires the Editor role or above.
</Info>

You can modify any existing Workflow or Chatflow app, including one built entirely in the canvas editor.

Open your app in the editor, then select the **App Builder** icon in the upper-right canvas toolbar. Describe what you want to change and what should stay the same.

<Warning>
Do not include API keys, tokens, passwords, or sensitive production data in your prompts, App Builder conversations, or test inputs.
</Warning>

If the **Review the requested changes** form appears, check that it matches your request and review any model or tool selections. Then select **Submit rules**.

## Get Help with an Error <a id="get-help-with-errors"></a>

<Info>
Fixing and testing an app requires the Editor role or above.
</Info>

If the canvas editor reports a node configuration error or a Workflow test fails, you can ask App Builder to help resolve it.

Select **Fix with App Builder**, when available:

- In **Checklist**, next to the node configuration error.
- In the failure panel for the current Workflow **Test Run**.

## Review the Changes

Review App Builder’s diagnosis and suggested fix. If approval is required, select **Approve fix** to apply it. Otherwise, App Builder applies the fix automatically.

For errors reported in **Checklist**, select **Re-check** to confirm that the configuration error is resolved. This checks the configuration without running the app.

## Test the Updated App

Select **Run validation** to prepare a test. Review the suggested inputs and adjust them for a case where you know what result to expect.

If the test form includes checkboxes for real actions:

- Leave them unchecked to simulate the actions without sending messages or updating records.
- To run an action for real, check its account, destination, and data before selecting its checkbox.

<Warning>
Model calls and read operations can still contact external services, even when other steps are simulated. App Builder tests simulate or block destructive actions, such as deleting data.
</Warning>

Select **Run the test** and check whether the app now produces the expected result. Use **Run details** to investigate errors or unexpected output. If you enabled a real action, verify its result in the connected service.

If the error remains, select **Fix again** to try another repair.

## Revert the Draft

To undo recent draft changes, select **Revert**. App Builder restores its latest restore point and discards changes made since then, including manual edits.

<Warning>
Revert doesn’t undo actions already performed in external services during tests.
