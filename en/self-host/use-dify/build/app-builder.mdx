App Builder is an AI assistant that helps you build and refine Workflow and Chatflow apps through conversation. Describe what you want to achieve, and App Builder proposes a plan and configures nodes and connections in the draft after your approval. Use it to start a new app or update an existing one, alongside the canvas editor.

<Note>
If your app needs Knowledge Retrieval, Human Input, or classic Agent nodes, add them in the canvas editor.
</Note>

<Info>
App Builder needs a model to plan and build your app. In **Integrations** > **Model Provider**, configure a provider, then open **Default Models** to select and save a **System Reasoning Model**.
</Info>

## Describe What You Need

<Info>
Creating an app requires the Editor role or above.
</Info>

In Studio, select **Create**, then choose **Workflow** or **Chatflow**. Describe what you want to build in the dialog that opens.

<Warning>
Do not include API keys, tokens, passwords, or sensitive production data in your prompts, App Builder conversations, or test inputs.
</Warning>

Start with the outcome you need. You can include the inputs the app will receive, the output you want, and any rules it should follow.

For example, you might enter:

```text wrap
Build a refund eligibility Workflow. The inputs are the number of days since delivery, whether the item has been opened, and the refund reason. A request is eligible only if the item was delivered within the last 30 days and is unopened. State whether the request is eligible for a refund and explain why.
```

To refine your description before sending, select **Optimize with AI** and review the revised text.

When ready, select **Send**. App Builder opens in the editor and starts working on your request.

If App Builder asks for more details before recommending resources, review and update the requirements, then select **Submit requirements**.

<a id="review-resources"></a>

## Review Resources

Review the suggested models, tools, or published [Agent apps](/en/self-host/use-dify/build/new-agent/overview). Deselect any you do not want to use, then select **Confirm resources**. If no resources are recommended, select **Confirm resources** to continue.

Before testing, complete any required setup or authorization for the resources you selected.

## Describe Your Changes

<Info>
Editing an app requires the Editor role or above.
</Info>

You can use App Builder to update an existing app, including one built entirely in the canvas editor.

Open your app in the editor, then select the **App Builder** icon in the upper-right canvas toolbar. Describe what you want to change and what should stay the same.

<Warning>
Do not include API keys, tokens, passwords, or sensitive production data in your prompts, App Builder conversations, or test inputs.
</Warning>

If the **Review the requested changes** form appears, check that it matches your request and review any model or tool selections. Then select **Submit rules**.

<a id="get-help-with-errors"></a>

<Tip>
To fix a node error, in **Checklist** or the current Workflow **Test Run** failure panel, select **Fix with App Builder** when available. Follow the prompts to fix the error and test the updated app.
</Tip>

## Review the Plan {#review-the-proposed-plan}

Review the plan to make sure it matches what you want the app to do:

- **Inputs and output**: The app uses inputs you can provide and returns the result you need.
- **Steps and rules**: The steps follow your rules and include only actions you want the app to take.
- **External actions**: If the app sends information or updates records, the data and destinations are correct.

If anything is missing or incorrect, select **Continue adjusting** and describe what you want to change.

When the plan matches your goal, approve it. App Builder applies the changes to **Current Draft**, the unpublished version of the app.

## Test and Refine {#test-the-draft}

<Info>
Testing an app requires the Editor role or above.
</Info>

After App Builder applies the plan, select **Run test** or **Run affected tests** to review the suggested test inputs.

<a id="run-and-review-the-test"></a>

### Test the Draft {#review-test-inputs}

Review the suggested inputs and adjust them if needed. Choose a case where you know what result to expect.

If the test form asks you to confirm real actions:

- Leave their checkboxes unchecked to simulate the actions without sending messages or updating records.
- To perform an action for real, review its account, destination, and data, then select its checkbox.

<Warning>
Model calls and read operations can still contact external services, even when other steps are simulated. Destructive actions, such as deleting data, are always simulated in App Builder tests.
</Warning>

Select **Run the test** and compare the output with what you expected. Open **Run details** to inspect individual steps. If you enabled a real action, check its result in the connected service.

If the test fails, check the error message for input or configuration problems. If App Builder proposes a repair, review it and select **Apply the fix**.

### Refine the Draft

If the app doesn’t do what you need, select **Continue adjusting** and describe the changes you want in the form. For unexpected output, include what you got and what you expected.

Submit the form, confirm resources if prompted, then review the revised plan before approving it. After the changes are applied, test again.

<Accordion title="Continue After Manual Edits">
You can edit existing Human Input and classic Agent nodes with App Builder. To adjust Knowledge Retrieval settings, use the canvas editor.

After you edit the canvas manually, App Builder may ask how to proceed:

- Select **Continue** to keep working with the current plan.
- Select **Restart from current draft** to create a new plan based on your edited draft. Your manual edits are kept.

</Accordion>

<a id="undo-this-attempt"></a>

### Revert the Draft

Select **Revert** to restore the draft to its state before App Builder applied the plan.

<Warning>
This discards all changes made since the plan was applied, including manual edits. It doesn’t undo actions already performed in external services during tests.
</Warning>

## Publish {#decide-whether-to-publish}

<Info>
Publishing an app requires the Editor role or above.
</Info>

To publish through App Builder, the current draft must pass a test without simulated steps. When the results meet your needs, select **Publish** to make **Current Draft** live.

If your test includes simulated steps, or you need more review or testing, select **Keep draft**. In the canvas editor, use **Test Run** for a Workflow or **Preview** for a Chatflow. When the results meet your needs, select **Publish** in the top toolbar.
