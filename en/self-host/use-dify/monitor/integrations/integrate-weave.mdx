## Connect Your App

Create a [W&B project](https://docs.wandb.ai/models/track/project-page#create-a-project) that your [API key](https://wandb.ai/authorize) can write to before configuring Dify. For a team project, use that team as the **Entity**.

In the Dify app, open **Monitoring** > **Tracing app performance**. For **Weave**, click **Config** and enter the connection details:

| Field | Required | Value |
|:------|:---------|:------|
| **API Key** | Yes | Your W&B API key. |
| **Project** | Yes | An existing, writable project. You can enter `entity/project` here and leave **Entity** blank. |
| **Entity** | No | The W&B team or user. If blank, Dify resolves the API key's default entity. |
| **Endpoint** | No | The Weave trace server. Defaults to `https://trace.wandb.ai`; HTTPS is required. |
| **Host** | No | The W&B API server. Defaults to `https://api.wandb.ai`; HTTP(S) is accepted. |

For a custom deployment, ask its administrator for the trace-server **Endpoint** and W&B API **Host**. Keep any path prefix they provide.

Review [what Dify sends](#what-dify-sends), then click **Save & Enable**. Each app has one active tracing provider; selecting Weave replaces the current selection.

Saved credentials are hidden when you edit. Leave them blank to keep their saved values while **Host** and **Endpoint** are unchanged. Re-enter them if you change either address.

## What Dify Sends

A trace records an app execution as timed operations called *spans*. Each span includes its status and any error. Dify also sends captured inputs and outputs, model usage, and identifying metadata such as message, workflow, and node IDs.

For a Workflow, inspect its node spans, including loop and iteration groups. Chat traces include the model call under the message. In a Chatflow trace, the workflow sits under the message.

In Weave, open a model call to inspect its captured inputs and outputs. Available token counts appear in the call's per-model usage. Dify doesn't fill Weave's built-in cost field.

### Include Agent Calls and Content

<Note>
Tracing for Agent apps and the [new Agent node](/en/self-host/use-dify/nodes/agent#new-agent) is off by default. Ask your deployment administrator to set both `OPS_AGENT_TRACE_ENABLED=true` and `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true`. See [Environment Variables](/en/self-host/deploy/configuration/environments#llmops-trace-delivery) for where to set them.
</Note>

Under **Agent data capture** in the app's tracing settings:

- **Capture Agent internals**: Keep this on to inspect the Agent's internal model and tool calls when debugging its decisions. Turn it off to omit those internal calls while keeping the Agent run or workflow node itself.
- **Capture content**: Turn this on only if the monitoring service should receive inputs and outputs from these runs. With it off, timings, token information, and status remain available.

<Note>
These controls apply to Agent apps and Workflow or Chatflow apps that contain the new Agent node. For those workflows, **Capture content** also controls the other nodes' inputs and outputs. Other apps can still send inputs and outputs; leave tracing disabled if you can't send that content to the monitoring service.
</Note>

The new Agent node uses the containing Workflow or Chatflow app's tracing settings. Agent calls inside a workflow tool aren't included in the parent Agent's trace.

## Verify a New Trace

1. Run a new request in your Dify app and let it finish.
2. In **Tracing app performance**, click **View** for **Weave** to open the configured project.
3. Find the new call by its run time and open it to inspect its child calls.

Traces may take time to appear after the run finishes.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The configuration saved, but no trace appears">
    Saving checks that the project exists, is writable, and that the trace server is accessible. Confirm that Weave is selected and tracing is enabled. In Weave, open the configured entity and project. Then run the app again.

    Ask your administrator to check worker logs and the [trace delivery queue](/en/self-host/deploy/configuration/environments#llmops-trace-delivery) if the new run is still missing.
  </Accordion>
  <Accordion title="Dify can't connect to my monitoring server">
    The address must be reachable from Dify's API and workers. In a container, `localhost` points to that container, so use the monitoring server's reachable hostname instead.

    For a private HTTP endpoint, ask your administrator to check the [SSRF proxy allowlist](/en/self-host/deploy/configuration/environments#ssrf-proxy) and allow only the required destination.
  </Accordion>
</AccordionGroup>
