## Connect Your App

Create a Langfuse project and get its [API keys](https://langfuse.com/faq/all/where-are-langfuse-api-keys) from **Project Settings** > **API Keys**. For Langfuse Cloud, choose the [base URL for your region](https://langfuse.com/docs/api-and-data-platform/features/public-api#select-the-regional-base-url) without the `/api/public` suffix. For a self-hosted instance, ask its administrator for the base URL.

In the Dify app, open **Monitoring** > **Tracing app performance**. For **Langfuse**, click **Config** and enter the connection details:

| Field | Required | Value |
|:------|:---------|:------|
| **Secret Key** | Yes | The project's secret key. |
| **Public Key** | Yes | The matching public key. |
| **Host** | Yes | Your Langfuse instance's HTTP(S) base URL. |

<Note>
This integration requires Langfuse's legacy ingestion API, `/api/public/ingestion`, to receive trace data. Langfuse v4 deployments using `events_only` mode don't accept these traces. Check [Langfuse's ingestion compatibility](https://langfuse.com/docs/api-and-data-platform/features/public-api#ingest-traces-via-the-api) with your Langfuse administrator before connecting.
</Note>

Review [what Dify sends](#what-dify-sends), then click **Save & Enable**. Each app has one active tracing provider; selecting Langfuse replaces the current selection.

Saved credentials are hidden when you edit. Leave them blank to keep their saved values while **Host** is unchanged. Re-enter them if you change the destination.

## What Dify Sends

A trace records an app execution as timed operations called *spans*. Each span includes its status and any error. Dify also sends captured inputs and outputs, model usage, and identifying metadata such as message, workflow, and node IDs.

For a Workflow, inspect its node spans, including loop and iteration groups. Chat traces include the model call under the message. In a Chatflow trace, the workflow sits under the message.

In Langfuse, open a generation to inspect a model call's captured inputs and outputs. Token counts and USD costs appear in its usage and cost fields when available.

### Include Agent Calls and Content

<Note>
Tracing for Agent apps and the [new Agent node](/en/self-host/use-dify/nodes/agent#new-agent) is off by default. Ask your deployment administrator to set both `OPS_AGENT_TRACE_ENABLED=true` and `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true`. See [Environment Variables](/en/self-host/deploy/configuration/environments#llmops-trace-delivery) for where to set them.
</Note>

Under **Agent data capture** in the app's tracing settings:

- **Capture Agent internals**: Keep this on to inspect the Agent's internal model and tool calls when debugging its decisions. Turn it off to omit those internal calls while keeping the Agent run or workflow node itself.
- **Capture content**: Turn this on only if the monitoring service should receive inputs and outputs from these runs. With it off, timings, token information, and status remain available.

<Note>
These controls apply to Agent apps and Workflow or Chatflow apps that contain the new Agent node. For those workflows, **Capture content** also controls the other nodes' inputs and outputs. Other apps can still send inputs and outputs; leave tracing disabled if you can't send that content to the monitoring service.
</Note>

The new Agent node uses the containing Workflow or Chatflow app's tracing settings. Agent calls inside a workflow tool aren't included in the parent Agent's trace.

## Verify a New Trace

1. Run a new request in your Dify app and let it finish.
2. In **Tracing app performance**, click **View** for **Langfuse** to open the configured project.
3. Find the new trace by its run time. Open it to inspect the model generations or node spans.

Traces may take time to appear after the run finishes.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The configuration saved, but no trace appears">
    Saving the configuration checks project access. Confirm that Langfuse is selected and tracing is enabled. Then run the app again and check the same project.

    Ask your administrator to check worker logs for ingestion errors and confirm that Langfuse accepts data through `/api/public/ingestion`. They should also check the [trace delivery queue](/en/self-host/deploy/configuration/environments#llmops-trace-delivery) if the new run is still missing.
  </Accordion>
  <Accordion title="Dify can't connect to my monitoring server">
    The address must be reachable from Dify's API and workers. In a container, `localhost` points to that container, so use the monitoring server's reachable hostname instead.

    For a private HTTP endpoint, ask your administrator to check the [SSRF proxy allowlist](/en/self-host/deploy/configuration/environments#ssrf-proxy) and allow only the required destination.
  </Accordion>
</AccordionGroup>

To use prompts managed in Langfuse, see the community-maintained [Langfuse Prompt Management Plugin](https://github.com/gao-ai-com/dify-plugin-langfuse) for installation and usage.
