## Connect Your App

In Arize, get the API key and current Space ID from **Settings** > **API Keys**; see the [Arize quickstart](https://arize.com/docs/ax/quickstarts) for details. Choose a destination project name. To connect Phoenix instead, use the [Phoenix integration](/en/self-host/use-dify/monitor/integrations/integrate-phoenix).

In the Dify app, open **Monitoring** > **Tracing app performance**. For **Arize**, click **Config** and enter the connection details:

| Field | Required | Value |
|:------|:---------|:------|
| **API Key** | Yes | An Arize API key with ingestion access. |
| **Space ID** | Yes | The Arize space receiving the traces. |
| **Project** | Yes | The destination project name. |
| **Endpoint** | No | Defaults to `https://otlp.arize.com`. For a custom collector, use the address your administrator provides. |

A custom **Endpoint** must accept OTLP/gRPC. Ask your administrator for its hostname and port, without an HTTP path such as `/v1/traces`.

Review [what Dify sends](#what-dify-sends), then click **Save & Enable**. Each app has one active tracing provider; selecting Arize replaces the current selection.

Saved credentials are hidden when you edit. Leave **API Key** and **Space ID** blank to keep their saved values while **Endpoint** is unchanged. Re-enter both if you change the endpoint.

## What Dify Sends

A trace records an app execution as timed operations called *spans*. Each span includes its status and any error. Dify also sends captured inputs and outputs, model usage, and identifying metadata such as message, workflow, and node IDs.

For a Workflow, inspect its node spans, including loop and iteration groups. Chat traces include the model call under the message. In a Chatflow trace, the workflow sits under the message.

In Arize, open a model span to inspect its captured inputs and outputs and available token counts. Dify doesn't fill Arize's built-in cost fields.

### Include Agent Calls and Content

<Note>
Tracing for Agent apps and the [new Agent node](/en/self-host/use-dify/nodes/agent#new-agent) is off by default. Ask your deployment administrator to set both `OPS_AGENT_TRACE_ENABLED=true` and `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true`. See [Environment Variables](/en/self-host/deploy/configuration/environments#llmops-trace-delivery) for where to set them.
</Note>

Under **Agent data capture** in the app's tracing settings:

- **Capture Agent internals**: Keep this on to inspect the Agent's internal model and tool calls when debugging its decisions. Turn it off to omit those internal calls while keeping the Agent run or workflow node itself.
- **Capture content**: Turn this on only if the monitoring service should receive inputs and outputs from these runs. With it off, timings, token information, and status remain available.

<Note>
These controls apply to Agent apps and Workflow or Chatflow apps that contain the new Agent node. For those workflows, **Capture content** also controls the other nodes' inputs and outputs. Other apps can still send inputs and outputs; leave tracing disabled if you can't send that content to the monitoring service.
</Note>

The new Agent node uses the containing Workflow or Chatflow app's tracing settings. Agent calls inside a workflow tool aren't included in the parent Agent's trace.

## Verify a New Trace

1. Run a new request in your Dify app and let it finish.
2. In **Tracing app performance**, click **View** for **Arize**. If the shortcut is unavailable, open your Arize space and project directly.
3. Find the new trace by its run time and open it to inspect its child spans.

Traces may take time to appear after the run finishes.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The configuration saved, but no trace appears">
    Saving tests collector access without creating a real trace. Confirm that Arize is selected and tracing is enabled. In Arize, open the configured space and project. Then run the app again.

    Ask your administrator to check worker logs and the [trace delivery queue](/en/self-host/deploy/configuration/environments#llmops-trace-delivery) if the new run is still missing.
  </Accordion>
  <Accordion title="Dify can't connect to my collector">
    The gRPC collector must be reachable from Dify's API and workers. Ask your administrator to check its hostname, port, and network access. Use a reachable server address: loopback addresses such as `localhost` aren't accepted.
  </Accordion>
</AccordionGroup>

For help evaluating the traces you collect, see Arize's [agent evaluation guide](https://arize.com/guides/ai-agent-handbook/agent-evaluation/) and [LLM evaluation guide](https://arize.com/resources/llm-evaluation/).
