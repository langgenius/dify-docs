Go to **Knowledge**, switch to the **New** tab, and click **Create**.

## Set Up the Basics

Give the knowledge base a name and a description, and set who can view it and connect it to their apps. All of these can be changed later in the knowledge base's settings.

The knowledge base uses your workspace's default models. If any are missing at creation, you'll be prompted to set them up first.

<Tip>

- For what each model does in indexing and retrieval, see [Retrieval Settings](/en/3.14.x/use/knowledge-base/retrieval-settings).

- For which models make images searchable, see [Multimodal Retrieval](/en/3.14.x/use/knowledge-base/multimodal-retrieval).

</Tip>

## Add Content

Connect a source when the content lives somewhere else and keeps changing, or upload files when you have standalone documents. A knowledge base can hold a mix of both.

<Tip>
Start with a small, representative set of documents and import the rest once retrieval is well tuned. A later model change re-indexes every document, which costs fewer tokens while the knowledge base is small.
</Tip>

### Connect a Source

A source brings content in from a website, a document platform, or a cloud drive through a data source integration such as Firecrawl, Notion, or Google Drive. 

Each integration is installed once and shared by every knowledge base in the workspace.

<Steps>
  <Step title="Choose a Provider">
    Select one of the data source integrations installed in your workspace, or click **More providers** to install one.

    <Tip>
    If no integration covers your needs, [build one](/en/3.14.x/develop/plugins/dev-guides-and-walkthroughs/datasource-plugin) or [request one](https://github.com/langgenius/dify-plugins/issues/new?template=plugin_request.yaml) from the community.
    </Tip>

    Set up the connection in **Integrations** > **Data Source** by entering its API key or authorizing an account.

  </Step>
  <Step title="Select What to Sync">
    <Tabs>
      <Tab title="Website crawl">
        Name the source and paste the URL. Under **Crawl options**, include subpages when later syncs should pick up new pages under the URL; otherwise the source stays at the pages you select now.

        Click **Crawl & preview** and select which pages to import from the results.
      </Tab>
      <Tab title="Online documents">
        Choose the pages to import from your connected account.
      </Tab>
      <Tab title="Online drive">
        Choose the files or folders to import from the connected drive or bucket.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Set the Sync Policy">
    Pick a preset schedule, set a custom interval (1 hour to 30 days), or switch to manual sync. 
    
    Match it to how often the content changes. A sync that finds changes re-indexes them, which costs tokens, so syncing hourly content that changes monthly buys nothing.

    <Info>
    What a sync picks up depends on the source type:

    - A website source imports new pages under the URL if the crawl includes subpages.
    - Online document and drive sources sync only the items you selected. Edit the selection to bring in new ones.
    </Info>
  </Step>
</Steps>

### Upload Files

Each file becomes its own document, up to 15 MB.

DOC, PPT, and other legacy Office formats require the Unstructured parsing service. See [Unstructured Parser](/en/3.14.x/deploy/advanced-configuration/environment-variables#unstructured-parser) in Environment Variables for the setup.

## Next Steps

Once your documents show **Ready** in the **Document** tab, three steps remain before the knowledge base should serve real users:

1. [Review indexed documents](/en/3.14.x/use/knowledge-base/review-indexed-documents): open a document and check that its sections, summaries, and chunks came through well.

2. [Test retrieval and tune settings](/en/3.14.x/use/knowledge-base/test-and-tune): ask the questions your app will face and tune until the results hold up.

3. [Connect to your apps](/en/3.14.x/use/knowledge-base/use-knowledge-in-apps): attach the knowledge base to the apps that should answer from it.
