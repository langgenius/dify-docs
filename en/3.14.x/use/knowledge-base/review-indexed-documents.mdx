Open a document from the **Document** tab once it shows **Ready** to see what indexing produced.

## Check the Sections and Summaries {#sections-and-summaries}

The reasoning model builds the outline on the left itself. It keeps the headings it could trust from the source document and adds or merges sections by meaning, so the outline can differ from the document's own table of contents.

Each section carries a summary. [Research searches](/en/3.14.x/use/knowledge-base/retrieval-settings#retrieval-depth) use these summaries to decide which sections to read, so a summary that misses the point can keep relevant content out at the Research retrieval depth.

**What to look for**: sections that merged two unrelated topics, or a summary that doesn't capture what the section is about.

**How to fix it**: make the source content's headings clearer and its topic sentences more explicit, so the model has better signals for where sections start and what each one is about.

## Check the Chunks {#chunks}

Below the sections, the text is split into chunks—the units retrieval searches and returns. Each chunk should hold one complete topic.

The model breaks chunks at headings and topic changes and never splits mid-sentence. A list stays whole under its heading when it fits, and each table record gets its own chunk. Chunks are capped at about 1,200 characters.

**What to look for**: chunks that mix two topics, or a procedure, definition, or table cut in half.

**How to fix it**: restructure the source content so each heading covers one topic, each paragraph holds one idea, and anything that must be retrieved together sits under one heading within the maximum chunk length.

## Check the Images

With text-only reasoning and embedding models, images are kept as placeholders without the image itself, and retrieval finds them only through attached text like a caption or alt text.

**What to look for**: images your users will ask about that carry no caption or alt text in the source.

**How to fix it**: add a caption or alt text in the source content, or switch to vision-capable models so images become searchable by what they show. See [Multimodal Retrieval](/en/3.14.x/use/knowledge-base/multimodal-retrieval) for which models make that work.

## Apply a Fix {#apply-a-fix}

After editing the source content, bring the new version in:

- For a source, the next sync picks it up.

- For an uploaded file, delete the old document and upload the new one. The updated document is re-indexed in full.

    Uploading a file with the same name adds a second document instead of replacing the first.

You can also try another reasoning model under **Settings** > **Retrieval**, since each model splits and summarizes in its own way. Changing it re-indexes every document in the knowledge base.
