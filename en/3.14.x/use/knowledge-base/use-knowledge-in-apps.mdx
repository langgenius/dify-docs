Once a knowledge base has content and retrieval is tuned, connect it to the apps that should answer from it.

<Tip>
    For access outside Dify, query the knowledge base through the [Service API](/en/3.14.x/develop/api/guides/knowledge-base) or browse its documents with the [Dify CLI](/en/3.14.x/develop/cli/reference/knowledge).
</Tip>

## Connect to Your Apps

In a Workflow or Chatflow app, add a new [Knowledge Retrieval node](/en/3.14.x/use/nodes/knowledge-retrieval-v2) to the canvas, then select the knowledge bases it should search.

Every run uses the latest searchable documents from the selected knowledge bases, with no need to republish the app after a change.

To stop retrieval from all workflows (including test runs), turn off **Workflow access** in the knowledge base's settings.

Once the app is live, watch the knowledge base's **Overview** tab for sources that stopped syncing and questions that came back empty. See [Maintain a Knowledge Base](/en/3.14.x/use/knowledge-base/maintain-knowledge-base) for what to do about each.

## Scope Retrieval to Specific Documents {#scope-retrieval-to-specific-documents}

Retrieval normally searches every document in a knowledge base, but with metadata you can narrow a search to only the documents that match a condition. This matters most when one knowledge base serves several apps.

Say an internal knowledge base of company policies holds regional guidelines for different countries, and each region has an assistant app for its employees built on it. Without a filter, the EU assistant can answer a parental-leave question from the US guideline.

Metadata fixes this. You label each document with facts about it, and searches can then be filtered by those labels:

1. In the knowledge base's **Document** tab, click **Meta Data** and add a field for each fact you'll filter on. For the policy knowledge base, that's one `region` field of type string.

    Pick the type with the filter in mind, since it can't be changed later: number for values you'll compare, time for dates you'll filter before or after.

2. Open each document, click **Start labeling**, pick the field, and enter its value. The EU guidelines get `eu`, the US ones `us`.

    Labels survive source syncs that update a document's content.

3. In your app, set **Metadata Filtering** to **Manual** and add the condition: *`region` is `eu`* for the EU assistant, whose answers now come from EU guidelines alone.

    You can also choose **Automatic** and let a model work out the conditions from each question. Searches run unfiltered when it can't determine one, so use **Manual** wherever the filter must hold.

    If several knowledge bases are retrieved at once, give shared fields the same name and type in each. Filters can only use fields that exist in all of them.
