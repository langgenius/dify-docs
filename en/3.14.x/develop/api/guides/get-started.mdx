Every app you publish in Dify doubles as a REST API, and so do your knowledge bases. You call the same app your end users interact with, from your own backend, with an API key.

## Get an API Key

<Warning>
Call the API from your backend only. A key embedded in frontend code or a client app can be extracted and abused.
</Warning>

- For an app, create an API key from inside the app itself. The key is scoped to that one app, and one key serves all your end users.

    <Info>
    Your calls tell people apart with a per-person `user` value. See [End User Identity](/en/3.14.x/develop/api/guides/end-user-identity) for details.
    </Info>

- For knowledge bases, follow the key setup for the [new Knowledge API](/en/3.14.x/develop/api/guides/knowledge-base#get-your-api-endpoint-and-key) or the [classic Knowledge API](/en/3.14.x/develop/api/guides/knowledge). New knowledge base keys can be scoped to selected knowledge bases.

## Make Your First Call

App requests carry the key as a Bearer token. The base URL is your deployment's API endpoint, such as `https://api.example.com/v1`; you can copy it from the app's API access page.

The fastest first call needs no code: open [Get App Info](/en/3.14.x/develop/api/applications/get-app-info), click **Try it**, paste your key into the **Authorization** field, and press **Send**. It works for every app type.

The same call from a terminal:

```bash
curl https://api.example.com/v1/info \
  -H "Authorization: Bearer $DIFY_API_KEY"
```

A response like this confirms the key works and shows which app it belongs to:

```json
{
  "name": "My Chat App",
  "description": "A helpful assistant",
  "tags": ["assistant"],
  "mode": "chat",
  "author_name": "Dify Team"
}
```

Using a knowledge base API key? Its endpoints are a separate family:

- For a new knowledge base, start with [Get Knowledge Base Settings](/en/3.14.x/develop/api/settings/get-knowledge-base-settings) and the [Knowledge API](/en/3.14.x/develop/api/guides/knowledge-base) guide.
- For a classic knowledge base, start with [List Knowledge Bases](/en/3.14.x/develop/api/knowledge-bases/list-knowledge-bases) and the classic [Knowledge API](/en/3.14.x/develop/api/guides/knowledge) guide.
