## Update {#update}

<Note>
  If the server moves from 1.17.x or earlier to 1.18.0 or later, the old build stops working with it. See [Upgrade Across Dify 1.18.0](/en/cli/upgrade-across-1-18) for what to redo and which commands changed.
</Note>

Update `difyctl` whenever your server moves to a new Dify release:

1. Re-run the [install command](/en/cli/get-started#install) for the corresponding server version, with the same `DIFYCTL_PREFIX` if you used one. The new build replaces the old one in place.
2. Run `difyctl version` and check that your build's version matches the server's.
3. If a coding agent uses `difyctl`, [reinstall](/en/cli/get-started#set-up-your-coding-agent) the difyctl skill. Otherwise the agent keeps following the old build's instructions.

`difyctl` fetches the server's new commands on its own. If `difyctl help` still shows the old list, run `difyctl refresh cache`.

## Uninstall

1. [Sign out](/en/cli/manage-sign-in#sign-out) while `difyctl` is still installed. Signing out ends your session on the server and deletes your saved token. Removing the binary does neither:

    ```bash
    difyctl logout
    ```

2. Remove the binary:

    <CodeGroup>

    ```bash macOS / Linux
    rm ~/.local/bin/difyctl
    ```

    ```powershell Windows
    Remove-Item -Recurse "$env:LOCALAPPDATA\difyctl"
    ```

    </CodeGroup>

    If you installed with `DIFYCTL_PREFIX`, the binary is in `<prefix>/bin` instead.

3. To remove your settings too, delete the config folder:

    <CodeGroup>

    ```bash macOS
    rm -rf ~/.config/difyctl
    ```

    ```bash Linux
    rm -rf "${XDG_CONFIG_HOME:-$HOME/.config}/difyctl"
    ```

    ```powershell Windows
    Remove-Item -Recurse "$env:APPDATA\difyctl"
    ```

    </CodeGroup>

    If you set `DIFY_CONFIG_DIR`, delete that folder instead.

4. If you installed the difyctl skill for a coding agent, delete the `difyctl` folder from [that agent's skills folder](/en/cli/get-started#set-up-your-coding-agent).
