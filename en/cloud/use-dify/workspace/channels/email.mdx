Dify emails requests from the new [Human Input](/en/cloud/use-dify/nodes/human-input) node through your workspace's own account with Resend, an email-sending service.

One connection covers every request email in the workspace, including Debug Mode and **Test message** emails.

## Before You Start

You need a [Resend](https://resend.com) account with:

- **A domain verified in Resend**: request emails are sent from an address on it. Resend gives you [DNS records to add](https://resend.com/docs/add-a-domain) at your domain provider. If someone else manages your domain, send them the records. Verification can take up to 72 hours, so start early.
- **An API key**: **Sending access** is enough. Resend shows a key only once, so copy it when you create it.

## Connect and Test in Dify

1. In **Settings** > **Channels**, find Email and click **Connect**.

2. In **Configure Email**, enter:

    - **Sender email address**: any address on the domain you verified in Resend, such as `approvals@example.com`.
    - **Sender name**: a name recipients will recognize, such as your company or team name.
    - **API Key**: the key you copied from Resend.

3. Click **Test connection**, and once it succeeds, click **Save**. If the test fails, see [what its error means](#test-connection-fails).

4. Send yourself a test request. Turn on Debug Mode in a workflow's Human Input node, pick **Email**, and test-run the workflow.

   Debug Mode sends the request only to you, at your Dify account's email address, from the sender you set. If it doesn't arrive, see [Troubleshooting](#troubleshooting).

<Note>
When you change the key or the sender later, click **Test connection** again before **Save**. To replace the key without interrupting request emails, create the new one in Resend first, and delete the old one only after saving the new one in Dify.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Test connection fails" id="test-connection-fails">
    Look for the HTTP status in the error message:

    - **401**: the API key is wrong, or was deleted in Resend. Enter the key again, or create a new one.
    - **403**: the sender's domain isn't verified in Resend. Check that the **Sender email address** is on your verified domain, or finish verifying the domain in Resend.
    - **429**: you've reached a Resend sending limit. If the API error code is `daily_quota_exceeded` or `monthly_quota_exceeded`, wait for the quota to reset, or move to a higher Resend plan. Otherwise, wait a moment and test again.
  </Accordion>
  <Accordion title="Request emails don't arrive, though Channels shows Configured">
    Open the Email settings in **Channels** and click **Test connection**. If the test fails, see [what its error means](#test-connection-fails).

    If it succeeds, find the request in **Emails** in your Resend dashboard:

    - It's marked **Delivered**: the recipient's mail server accepted it, but may have filed it as spam. Ask the recipient to check their spam folder.
    - It's marked **Bounced**: the recipient's mail server rejected it. Check that the address is correct, or open the email and hover over **Bounced** to see why.
    - It isn't there: check the node's **Recipients**. An address taken from a variable is skipped when the variable is empty or invalid.
  </Accordion>
</AccordionGroup>
