每个指标只检查测试用例的一个方面，例如回答是否忠于你提供的资料，或 Agent 是否选对了工具。

大多数指标由判定模型打分。少数 Ragas 指标还会用工作空间的 [默认嵌入模型](/zh/cloud/use-dify/workspace/model-providers#选择应用默认使用的模型) 比较语义。

<Tip>
评测适用于 <Badge color="blue" size="sm">Professional</Badge> 和 <Badge color="blue" size="sm">Team</Badge> 套餐。[了解更多](https://dify.ai/pricing)。
</Tip>

## 解读得分

得分范围为 0～1，越高越好。但好的回答能得多少分，要看具体的指标和框架。例如在 Ragas 的 [Answer Relevancy](#answer-relevancy) 下，正确且切题的回答也不一定接近 1 分。

设定各指标的阈值时，参考它给你认可的回答打出的分数。

## 选择判定框架

可选的开源评测库有两个：[Ragas](https://docs.ragas.io)（v0.3.2）和 [DeepEval](https://deepeval.com)（v4.2.0）。这一选择只影响 LLM 回答指标和检索指标。

同一个指标在两个框架下，衡量的内容可能不同。按评测中你最看重的方面来选：

- **回答必须忠于你提供的资料**：选 Ragas。它的 [Faithfulness](#faithfulness) 只认可检索上下文能支持的陈述，而 DeepEval 的 Faithfulness 对上下文从未提及的陈述也照样放行。
- **需要 [Semantic Similarity](#semantic-similarity)**：选 Ragas，只有它提供这个指标。
- **工作空间没有默认嵌入模型**：选 DeepEval，它不需要嵌入模型。
- **希望逐个分段判断相关性**：选 DeepEval。它的 [Context Relevance](#context-relevance) 会逐一判断每个分段，而 Ragas 是对检索到的内容整体打分。

要相互对比的各次运行，应始终使用同一个框架，因为不同框架下的得分没有可比性。

## 各指标需要什么

选择指标前，先确认它需要什么，以及对测试集的每一行、每个被评分的节点，它要调用几次判定模型。每次调用都会增加运行的开销。

适用于 LLM 节点的指标：

| 指标 | 需要参考答案 | 需要嵌入模型 | 每行调用判定模型的次数 |
|:--|:--|:--|:--|
| [Faithfulness](#faithfulness) | 否（需要检索到的上下文） | 否 | Ragas 2 次，DeepEval 4 次 |
| [Answer Relevancy](#answer-relevancy) | 否 | 仅 Ragas 需要 | Ragas 3 次，DeepEval 3 次 |
| [Answer Correctness](#answer-correctness) | 是 | 仅 Ragas 需要 | Ragas 3 次，DeepEval 1 次 |
| [Semantic Similarity](#semantic-similarity)（仅 Ragas） | 是 | 是 | 不调用 |

适用于知识检索节点、Agent 知识检索节点和知识库的指标：

| 指标 | 需要参考答案 | 需要嵌入模型 | 每行调用判定模型的次数 |
|:--|:--|:--|:--|
| [Context Precision](#context-precision) | 是 | 否 | Ragas 每个分段 1 次，DeepEval 2 次 |
| [Context Recall](#context-recall) | 是 | 否 | Ragas 1 次，DeepEval 2 次 |
| [Context Relevance](#context-relevance) | 否 | 否 | Ragas 2 次，DeepEval 每个分段 1 次再加 1 次 |

适用于 Agent 节点和 Agent 的指标：

| 指标 | 需要参考答案 | 需要嵌入模型 | 每行调用判定模型的次数 |
|:--|:--|:--|:--|
| [Task Completion](#task-completion) | 否（成功标准可选） | 否 | 1 次 |
| [Trajectory Quality](#trajectory-quality) | 否 | 否 | 1 次 |
| [Tool Selection Correctness](#tool-selection-correctness) | 否 | 否 | 1 次 |
| [Tool Argument Correctness](#tool-argument-correctness) | 否 | 否 | 1 次 |

## LLM 回答指标

这类指标为 LLM 节点的回答打分，每一行的打分依据如下：

- **问题**：模型实际收到的完整节点提示词，包括系统指令，而不只是用户的提问。
- **回答**：节点输出的文本，不含模型的推理过程（如有）。
- **检索到的上下文**：LLM 节点的 [**上下文**](/zh/cloud/use-dify/nodes/llm#上下文变量) 指向某个检索节点，这个节点返回的分段就是上下文。
- **参考答案**：测试集中该节点对应的 `expected_output` 列。

按你遇到的情况选择：

- **回答超出了检索到的内容**：Faithfulness。
- **回答回避问题或偏离问题**：Answer Relevancy。
- **回答弄错了事实，而你有参考答案**：Answer Correctness。
- **回答应与参考答案意思一致，措辞不限**：Semantic Similarity。

### Faithfulness

检查回答是否忠于检索到的内容：回答中的每条陈述都应以检索上下文为依据。如果应用只应依据你提供的资料作答，可用它找出编造的回答。

- **需要**：检索到的上下文，可通过以下两种方式之一提供：

  - **来自检索节点**：让 LLM 节点的 **上下文** 指向该检索节点，再将 **上下文** 变量插入提示词。
  - **来自其他类型的节点**，例如代码执行节点：不设置 **上下文**，在提示词中用 `<context>` 标签包住上下文内容。

  其他任何配置都会让 Faithfulness 拿不到上下文，得分也就不再反映回答的实际情况：

  - **上下文指向其他类型的节点**：DeepEval 给每个回答都打 1 分，Ragas 则都打 0 分。
  - **未设置上下文，也没有标签**：DeepEval 无法打分，该行显示 `EVAL_METRIC_FAILED`。Ragas 给每个回答都打 0 分。

  如果在 Ragas 下每一行都是 0 分，先检查这项设置。
- **得分**：回答中经得起上下文检验的陈述所占的比例。
  - Ragas 只计入上下文能支持的陈述。
  - DeepEval 计入所有不与上下文矛盾的陈述，因此上下文中只字未提的陈述也算忠实。
- **无值**：在 Ragas 下，判定模型在回答中找不到可检查的陈述时没有值，该行会显示 `Evaluation failed. Please retry or contact support.`。在 DeepEval 下，没有可检查陈述的回答得 1 分。

<Note>
在 DeepEval 下，如果 **上下文** 指向的检索节点什么也没返回，即使回答是编造的，Faithfulness 也会打 1 分。

要找出这些行，可同时用 [Context Precision](#context-precision) 或 [Context Relevance](#context-relevance) 为该检索节点打分。没有返回内容时，这两个指标都打 0 分。条件用 **且** 连接时，只要为其中一个指标设了条件，这些行就不会通过。
</Note>

### Answer Relevancy

判断回答是否回应了所提的问题。回避问题或答非所问的回答得分较低。

- **需要**：默认嵌入模型（Ragas 下）。
- **得分**：
  - Ragas 让判定模型根据回答反推出对应的问题，再衡量这些问题与节点的完整提示词（包括系统指令）在语义上有多接近。正确且切题的回答不一定接近 1 分，而「我不知道」这类不置可否的回答得 0 分。
  - DeepEval 让判定模型把回答中的每条陈述标记为相关或不相关，以相关陈述所占的比例作为得分。没有陈述的回答得 1 分。

### Answer Correctness

衡量回答是否说对了参考答案中的事实。

- **需要**：参考答案，以及默认嵌入模型（Ragas 下）。
- **得分**：
  - Ragas 把回答和参考答案都拆成陈述。两者共有的事实会提高得分，回答遗漏的事实和参考答案中没有的说法则会拉低得分。得分中还有较小的一部分，取决于两者在语义上有多接近。
  - DeepEval 让判定模型对照参考答案，按 0～10 分为回答评分，因此得分以 0.1 为单位变化。

### Semantic Similarity

衡量回答与参考答案表达的意思是否相同，不论措辞如何。只有 Ragas 提供此指标。

- **需要**：参考答案和默认嵌入模型。得分完全由嵌入模型计算，不调用判定模型。
- **得分**：两者在整体意思上的接近程度，而不是各个事实是否一致。如果事实必须正确，可搭配 [Answer Correctness](#answer-correctness) 使用。

## 检索指标

这类指标为 [知识检索](/zh/cloud/use-dify/nodes/knowledge-retrieval) 或 [Agent 知识检索](/zh/cloud/use-dify/nodes/knowledge-retrieval-v2) 节点返回的内容打分；直接评测经典知识库时，则为知识库返回的内容打分。它们只评判检索本身，从不评判应用的最终回答。每一行的打分依据如下：

- **查询**：检索节点的查询输入；对于知识库，则是该行的 `query`。
- **检索到的分段**：该行检索返回的文档片段，按返回顺序排列。
- **参考答案**：测试集中对应的 `expected_output` 列。

按你遇到的情况选择：

- **回答被无关的分段干扰**：Context Precision。
- **回答遗漏了知识库中已有的事实**：Context Recall。
- **还没有参考答案**：Context Relevance。

### Context Precision

检查返回的分段是否有助于作答，以及有用的分段是否排在前面。得分高，说明结果靠前的部分噪声少。

- **需要**：参考答案。
- **得分**：判定模型逐个判断每个分段是否有助于得出参考答案。有用的分段排得越靠前，得分越高。两个框架都按这种方式打分。没有检索到任何内容时，得分为 0。

### Context Recall

判断检索是否找到了参考答案所需的全部内容。得分高，说明没有遗漏重要信息。

- **需要**：参考答案。
- **得分**：判定模型把参考答案的每个句子与检索到的分段逐一对照，得分为被覆盖的句子所占的比例。两个框架都按这种方式打分。

### Context Relevance

评估返回的分段与查询的相关程度。

- **需要**：不依赖参考答案。
- **得分**：
  - Ragas 让判定模型对检索到的全部内容整体评分，只要内容中含有任何有助于回答查询的信息，就给出最高评分。它会评分两次并取平均值，因此得分只会是 0、0.25、0.5、0.75 或 1。判定模型只读取前 7000 个字符，超出的部分不计入。
  - DeepEval 让判定模型把每个分段中的每条陈述标记为相关或不相关，以相关陈述所占的比例作为得分。

  无论哪个框架，没有检索到任何内容时，得分都为 0。

## Agent 指标

这类指标为 Agent 节点打分，或为单独评测的 Agent 打分。它们读取的任务，都来自 Agent 的 `query`，或 [Agent 节点](/zh/cloud/use-dify/nodes/agent) 的任务或指令输入。

判定模型认可完成任务的多种合理做法，因此 Agent 不必遵循某个唯一的工具调用顺序。

按你遇到的情况选择：

- **任务没完成或做错了**：Task Completion。
- **Agent 浪费或重复步骤**：Trajectory Quality。
- **Agent 选错了工具**：Tool Selection Correctness。
- **Agent 向工具传了错误的值**：Tool Argument Correctness。

### Task Completion

检查最终输出是否正确、完整地完成了任务。

- **读取**：任务、最终输出、Agent 调用的工具及其返回结果，以及你的成功标准。
- **需要**：可选，在 `success_criteria` 列中填写成功标准。没有成功标准时，判定模型只按任务中写明或必然隐含的要求来衡量 Agent，其他期望都应写进成功标准。
- **得分**：达成目标最重要，其次是正确性以及与工具返回结果的一致性，最后是完整性。

  有成功标准时，判定模型会逐条单独检查，漏掉任何一条，得分都会大幅下降。描述某个动作的标准（例如「预订会议」），只有在对应的工具调用成功时才算达成，不管最终输出怎么说。

### Trajectory Quality

评估 Agent 完成任务所走的路径，与最终回答是否正确分开评判。

- **读取**：任务，以及 Agent 执行的每一步。
- **得分**：稳步推进、步骤高效、用好工具返回的结果、能从错误中恢复，都会提高得分。

  重复某个动作却没有获得新信息，会拉低得分。不需要工具时直接作答，也可能得高分。

### Tool Selection Correctness

判断 Agent 是否从该次运行实际可用的工具中，为任务选对了工具。

- **读取**：任务、该次运行中可用的工具，以及 Agent 选择的每个工具。
- **得分**：判定模型会考察任务所需的能力是否都有工具覆盖、所选工具是否适合任务，以及 Agent 是否避开了无关的工具。不调用任何工具也可能是正确的选择。

  参数和调用顺序不计入此项。要检查参数，可使用 [Tool Argument Correctness](#tool-argument-correctness)。
- **无值**：没有可用工具，也没有调用任何工具时，没有值。得分显示为 `-`。

### Tool Argument Correctness

检查 Agent 每次调用工具时传入的值（即参数）是否正确。正确是指参数符合工具的要求，并且结合 Agent 在这次调用前已掌握的信息来看，适合当前任务。

- **读取**：任务，以及每次调用的相关信息：调用参数、工具的描述及其接受的参数、Agent 最近几次工具调用的返回结果。
- **得分**：判定模型能评估的各次调用的平均分。调用失败本身并不意味着参数有误。
- **无值**：没有调用任何工具，或没有可评估的调用时，没有值。得分显示为 `-`。
