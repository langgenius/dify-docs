Dify 通过工作空间自己的 Resend 账户发送 [新版人工介入节点](/zh/cloud/use-dify/nodes/human-input) 的请求邮件。Resend 是一项邮件发送服务。

工作空间里的所有请求邮件都通过这一个连接发送，调试模式和 **测试消息** 发出的邮件也不例外。

## 开始之前

你需要一个 [Resend](https://resend.com) 账户，并在其中准备好：

- **已在 Resend 中验证的域名**：请求邮件会从该域名下的某个地址发出。Resend 会给出一组 [DNS 记录](https://resend.com/docs/add-a-domain)，你需要在域名服务商处添加。如果域名由他人管理，把这些记录发给对方。验证最长可能需要 72 小时，最好尽早开始。
- **API 密钥**：权限选择 **Sending access** 即可。Resend 只显示一次 API 密钥，创建时就要复制下来。

## 在 Dify 中连接并测试

1. 在 **设置** > **渠道** 中找到 Email，点击 **连接**。

2. 在 **配置 Email** 中填写以下信息：

    - **发件人 Email 地址**：在 Resend 中验证过的域名下任选一个地址，例如 `approvals@example.com`。
    - **发件人名称**：收件人一看就能认出的名称，例如公司或团队名称。
    - **API Key**：从 Resend 复制的 API 密钥。

3. 点击 **测试连接**，测试通过后点击 **保存**。如果测试失败，参见 [报错的含义](#test-connection-fails)。

4. 给自己发一条测试请求：在工作流的人工介入节点中开启调试模式，选择 **邮件**，再测试运行工作流。

   调试模式下，请求只会发到你 Dify 账户的邮箱，发件人就是刚才设置的那个。如果没有收到，参见 [故障排除](#故障排除)。

<Note>
以后更改 API 密钥或发件人时，同样要先点击 **测试连接**，再点击 **保存**。如果要更换 API 密钥，又不想中断请求邮件，先在 Resend 中创建新的 API 密钥，在 Dify 中保存之后，再删除旧的。
</Note>

## 故障排除

<AccordionGroup>
  <Accordion title="测试连接失败" id="test-connection-fails">
    查看错误信息中的 HTTP 状态码：

    - **401**：API 密钥有误，或已在 Resend 中删除。重新填写 API 密钥，或创建一个新的。
    - **403**：发件人所用的域名未在 Resend 中通过验证。确认 **发件人 Email 地址** 属于已验证的域名，或在 Resend 中完成该域名的验证。
    - **429**：已达到 Resend 的发送上限。如果 API 错误码是 `daily_quota_exceeded` 或 `monthly_quota_exceeded`，等待配额重置，或升级到更高的 Resend 套餐。其他情况下，稍等片刻后重新测试。
  </Accordion>
  <Accordion title="渠道中显示「已配置」，但请求邮件没有送达">
    在 **渠道** 中打开 Email 的设置，点击 **测试连接**。如果测试失败，参见 [报错的含义](#test-connection-fails)。

    如果测试通过，在 Resend 控制台的 **Emails** 中找到这封请求邮件：

    - 标记为 **Delivered**：收件人的邮件服务器已接收，但可能将其归入了垃圾邮件。让收件人查看一下垃圾邮件文件夹。
    - 标记为 **Bounced**：收件人的邮件服务器拒收了这封邮件。检查收件地址是否正确，或打开这封邮件，将鼠标悬停在 **Bounced** 上查看原因。
    - 找不到这封邮件：检查节点的 **收件人**。如果收件地址取自变量，而变量为空或无效，Dify 会跳过这个地址。
  </Accordion>
</AccordionGroup>
