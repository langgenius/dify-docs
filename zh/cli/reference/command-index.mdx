要查看某条命令的标志，运行 `difyctl help <command>`。

命令中的 `<mode>` 表示应用类型，例如 `workflow` 或 `advanced_chat`。每条命令支持哪些类型，可用 `help` 查看。每个类型对应哪种应用，参见 [查找应用](/zh/cli/run-apps#查找应用)。

## 构建和修改应用

| 命令 | 作用 | 使用条件 |
|:--|:--|:--|
| `create console_app <mode>` | 创建空白 Workflow 应用，或带初始草稿的 Chatflow 应用 | 编辑及以上角色 |
| `set app_info <mode>` | 修改应用的名称、描述或图标 | 编辑及以上角色 |
| `import console_app dsl` | 通过 DSL 文件创建或更新应用 | 编辑及以上角色 |
| `check console_app dsl` | 检查 DSL 文件中的问题，不导入 | 编辑及以上角色 |
| `confirm console_app dsl_import` | 完成等待你确认的导入，例如导入来自较新 Dify 版本的文件 | 编辑及以上角色 |
| `export console_app dsl` | 导出应用的 DSL | 已开启服务 API 访问、编辑及以上角色 |
| `check console_app dependency` | 列出应用需要但工作空间缺少的集成 | 已开启服务 API 访问、编辑及以上角色 |
| `get console_app env` | 列出草稿的环境变量，Secret 类型的值以掩码显示 | 已开启服务 API 访问、编辑及以上角色，仅限 Workflow 和 Chatflow 应用 |
| `set console_app env` | 添加或修改环境变量 | 已开启服务 API 访问、编辑及以上角色，仅限 Workflow 和 Chatflow 应用 |
| `delete console_app env` | 删除环境变量 | 已开启服务 API 访问、编辑及以上角色，仅限 Workflow 和 Chatflow 应用 |
| `test console_app <mode>` | 测试运行草稿。运行在人工介入表单处暂停后，无法通过 `difyctl` 继续 | 已开启服务 API 访问、编辑及以上角色 |
| `test node <mode>` | 测试草稿中的单个节点 | 已开启服务 API 访问、编辑及以上角色 |
| `get node_type` | 列出服务器可运行的节点类型 | |
| `describe node_type` | 显示节点类型的设置项和默认值 | |
| `get knowledge_base` | 列出可在工作流中使用的知识库 | |
