## 要求

- 发布日志：https://langgenius.github.io/dify-enterprise-docker-compose/
- Docker
- Docker Compose
- Linux 服务器
  - **警告**：不支持 Windows 和 Mac 上的 Docker Desktop
  - 最低配置要求：4 核 CPU、16 GB 内存、100 GB 磁盘空间

## 快速开始

### 下载

你可以从 Dify Enterprise 的 [仓库](https://langgenius.github.io/dify-enterprise-docker-compose/) 中下载特定版本。

使用 wget：

```bash
wget https://langgenius.github.io/dify-enterprise-docker-compose/dify-docker-compose-<version>.tgz
```

使用 curl：

```bash
curl -O https://langgenius.github.io/dify-enterprise-docker-compose/dify-docker-compose-<version>.tgz
```

## 安装步骤

1. 解压下载的文件到你的部署目录：

   ```bash
   mkdir dify-enterprise
   tar -xzf dify-docker-compose-<version>.tgz -C ./dify-enterprise/
   ```

2. 复制环境变量模板，然后启动 Docker Compose：

   ```bash
   cd dify-enterprise
   cp .env.example .env
   docker compose up -d
   ```

3. 如何访问 Dify Enterprise
   - 获取服务器的 IP，并在本地修改 hosts 文件，将域名指向该 IP，例如：
   ```bash
   4.152.1.216 console.dify.local
   4.152.1.216 app.dify.local
   4.152.1.216 api.dify.local
   4.152.1.216 upload.dify.local
   4.152.1.216 enterprise.dify.local
   ```

4. [验证服务状态](/zh/3.14.x/deploy/verify-services-status)

5. [激活许可证](/zh/3.14.x/deploy/license-activation)

## 从社区版升级

<Note>
**3.10 重构了环境变量配置**：原先单一的 `.env.example` 现已拆分为精简的 `.env.example` 加上可选的 `envs/*.env.example` 文件，企业版设置则以激活状态置于 `envs/enterprise/` 下。还原你备份的 `.env` 是安全的：Docker Compose 会 **最后** 读取 `.env`，因此你的现有值优先生效，部署无需迁移即可继续工作。如需采用 3.10 的新默认值或新增的变量，可选择将 `.env` 与新的 `.env.example` 对齐；随包提供的 `dify-env-sync.sh` 会执行从 `.env.example` 到 `.env` 的单向同步（保留你的自定义值、先行备份，并报告已移除的键）。
</Note>

1. 创建企业版数据库（确保社区版正在运行）：

   ```bash
   docker exec -it dify-db-1 psql -U postgres -c "CREATE DATABASE enterprise;"
   ```

   **提示**：你可能需要根据实际运行的容器名称做调整，可使用 `docker container ls` 查看 `db` 容器名称。

2. 停止社区版服务：

   ```bash
   docker compose down
   ```

3. 备份数据和配置（可能需要 sudo）：

   ```bash
   tar -czf backup.tgz volumes .env  # 如有其他自定义文件夹请一并备份
   ```

4. 删除社区版的所有文件和文件夹，仅保留 `backup.tgz` 和 `dify-docker-compose-<version>.tgz`

5. 解压企业版安装包到部署目录：

   ```bash
   tar -xzf dify-docker-compose-<version>.tgz -C /path/to/directory
   ```

6. 恢复备份：先删除 volumes 文件夹

   ```bash
   rm -rf volumes
   ```

   然后执行：

   ```bash
   tar -xzf backup.tgz
   ```

7. 如果你有自定义配置（如 `docker-compose.yaml`、`ssrf_proxy/squid.conf`、或 `nginx/conf.d/default.conf`），请手动合并修改。

8. 启动 Docker Compose：

   ```bash
   docker compose up -d
   ```

9. 如何访问 Dify Enterprise:
   - 获取服务器的 IP，并在本地修改 hosts 文件，将域名指向该 IP，例如：
   ```bash
   4.152.1.216 console.dify.local
   4.152.1.216 app.dify.local
   4.152.1.216 api.dify.local
   4.152.1.216 upload.dify.local
   4.152.1.216 enterprise.dify.local
   ```

10. [验证服务状态](/zh/3.14.x/deploy/verify-services-status)

11. [激活许可证](/zh/3.14.x/deploy/license-activation)

## 高级配置

### 配置文件

部署目录中的配置分散在以下几类文件中：

- **`.env`**：你的生效配置。首次启动前请从 `.env.example` 复制（`cp .env.example .env`）。所有自定义项都写在这里；Docker Compose **最后** 读取该文件，因此 `.env` 中的值优先级最高，会覆盖其他所有文件。
- **`envs/enterprise/*.env`**：企业版服务配置。随包**已激活**并自动接入，标准部署无需复制或修改。
- **`envs/*.env.example`**：按主题分组的可选高级配置（数据库、向量库、基础设施等）。如需启用某组，请去掉 `.example` 后缀复制该文件（例如 `cp envs/databases/redis.env.example envs/databases/redis.env`）。

对于下文的各项设置，只需将变量加入 `.env` 即可，它们会覆盖上述文件中的任何默认值。

### 域名要求

Dify Enterprise 要求配置以下 5 个域名：

- Console: console.dify.local
- Services API: api.dify.local
- APP: app.dify.local
- Files: upload.dify.local
- Enterprise: enterprise.dify.local

你可以在 `.env` 文件中配置这些域名：

```bash
# .env

CONSOLE_API_URL="http://console.dify.local"
CONSOLE_WEB_URL="http://console.dify.local"
SERVICE_API_URL="http://api.dify.local"
APP_API_URL="http://app.dify.local"
APP_WEB_URL="http://app.dify.local"
FILES_URL="http://upload.dify.local"
ENTERPRISE_URL="http://enterprise.dify.local"
```

### 持久化存储配置

默认使用本地存储。如需修改，可在 `.env` 文件中配置。例如使用 **AWS S3**：

```bash
# .env

STORAGE_TYPE=s3

S3_USE_AWS_MANAGED_IAM=
S3_ENDPOINT=
S3_REGION=
S3_BUCKET_NAME=
S3_ACCESS_KEY=
S3_SECRET_KEY=
```

更多存储选项配置，请参考：[文件存储配置指南](https://docs.dify.ai/zh/self-host/deploy/configuration/environments#文件存储配置)

### Postgres 数据库配置

```bash
# .env

DB_USERNAME=postgres

DB_PORT=5432

```

更多数据库配置，请参考：[数据库配置指南](https://docs.dify.ai/zh/self-host/deploy/configuration/environments#数据库配置)

更多配置，请参考：[Redis 配置指南](https://docs.dify.ai/zh/self-host/deploy/configuration/environments#redis-配置)

### 向量数据库配置

默认使用 **Weaviate**，如需切换为 **Qdrant**，可以在 `.env` 文件中配置如下：

```bash
# .env

VECTOR_STORE=qdrant

QDRANT_URL=http://qdrant:6333
QDRANT_API_KEY=difyai123456
QDRANT_CLIENT_TIMEOUT=20
QDRANT_GRPC_ENABLED=false
QDRANT_GRPC_PORT=6334
```

更多向量数据库配置，请参考：[向量数据库配置指南](https://docs.dify.ai/zh/self-host/deploy/configuration/environments#向量数据库配置)

### Agent 沙箱后端

Agent 的沙箱可运行在两种后端之一，由 `.env` 文件中的 `DIFY_AGENT_RUNTIME_BACKEND` 选择。请选定一种后端并配置对应的变量组；这一选择同时决定 Agent 的 Home Snapshot（长期文件）存放在哪里。

默认使用随部署打包的 `local_sandbox` 容器：

```bash
# .env

DIFY_AGENT_RUNTIME_BACKEND=local
DIFY_AGENT_LOCAL_SANDBOX_ENDPOINT=http://local_sandbox:5004
DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN=
```

旧变量名 `DIFY_AGENT_SHELLCTL_ENTRYPOINT` 和 `DIFY_AGENT_SHELLCTL_AUTH_TOKEN` 仍作为回退值兼容既有部署。

如需改用 [E2B](https://e2b.dev/) 运行沙箱，启动时叠加 `docker-compose.e2b.yaml`，并配置 E2B 变量组：

```bash
# .env

DIFY_AGENT_E2B_API_KEY=your-e2b-api-key
DIFY_AGENT_E2B_TEMPLATE=difys-default-team/dify-agent-local-sandbox
DIFY_AGENT_E2B_ACTIVE_TIMEOUT_SECONDS=3600
DIFY_AGENT_E2B_SHELLCTL_PORT=5004
```

- `DIFY_AGENT_E2B_API_KEY`：你的 E2B API 密钥。`E2B_API_KEY` 和 `E2B_API_TOKEN` 仍可作为部署级回退值。
- `DIFY_AGENT_E2B_TEMPLATE`：E2B 沙箱模板，默认 `difys-default-team/dify-agent-local-sandbox`。
- `DIFY_AGENT_E2B_ACTIVE_TIMEOUT_SECONDS`：单个沙箱租约的最长连续活跃时间，默认 `3600`。其默认值与可独立配置的 Agent 运行截止时间（`DIFY_AGENT_RUN_TIMEOUT_SECONDS`）一致。
- `DIFY_AGENT_E2B_SHELLCTL_PORT`：沙箱运行时监听的端口，默认 `5004`。
