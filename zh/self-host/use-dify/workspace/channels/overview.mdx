在 **设置** > **渠道** 中连接团队的 IM（即时通讯应用）后，工作空间成员除了通过邮件，还能在 IM 中收到 [人工介入](/zh/self-host/use-dify/nodes/human-input) 请求。每个工作空间只能连接一个 IM。

<Info>
  只有工作空间所有者和管理员能看到 **渠道**，也只有他们可以连接或更改 IM。
</Info>

成员如何响应取决于所用的 IM。有些 IM 把每个请求显示为可交互的卡片，表单直接出现在聊天中，成员当场就能响应。另一些 IM 发送带链接的消息，成员点击链接后在 Dify 中响应。

## 连接 IM

先在 IM 中为 Dify 创建一个自建应用，授权它以机器人身份发送消息、读取成员通讯录，以便 Dify 按邮箱匹配成员。然后在 **渠道** 中填入该应用的凭据。如果 IM 以卡片展示请求，还要设置应用把按钮点击传回 Dify。

按所用 IM 的指南操作：

| IM | 请求的送达形式 |
|:---|:---|
| [Slack](/zh/self-host/use-dify/workspace/channels/slack) | 卡片 |
| [飞书 / Lark](/zh/self-host/use-dify/workspace/channels/feishu-lark) | 卡片 |
| Microsoft Teams | 卡片 |
| [钉钉](/zh/self-host/use-dify/workspace/channels/dingtalk) | 链接消息 |
| [企业微信](/zh/self-host/use-dify/workspace/channels/wecom) | 链接消息 |

## 同步成员

连接后，点击 **立即同步** 绑定成员的 IM 身份。Dify 会读取 IM 的成员通讯录（以 IM 应用有权查看的范围为限），并将每个 IM 身份绑定到邮箱相同的工作空间成员。

只有绑定了 IM 身份的成员，才会在 IM 中收到请求。同步遗漏的人，可以 [手动绑定](/zh/self-host/use-dify/workspace/contacts#手动绑定)。

只有点击 **立即同步** 时才会同步，因此有人加入工作空间或 IM，或有人更改邮箱后，需要再同步一次。

同步完成后，点击 **查看详情** 查看本次同步的变更：

- **新增**：新绑定到成员的 IM 身份。
- **未匹配**：同步时未能与成员配对的 IM 身份。IM 中所有不在工作空间里的人都会归入此类。如果某位成员本应匹配却出现在这里，原因和解决方法参见 [联系人](/zh/self-host/use-dify/workspace/contacts#与-im-同步)。
- **失败**：整次同步失败，没有任何变更。检查 IM 应用的凭据及其读取通讯录的权限，然后重新同步。
- **已移除**：同步删除的绑定，原因是对应的 IM 身份已不在通讯录中，例如账号已停用，或 IM 应用已无权查看该账号。每个 IM 身份下会注明原因：
  - 「已不在通讯录中」：没有其他 IM 身份取代它，该成员现已解除绑定，只能通过邮件收到请求。如果对方仍在使用 IM，确认 IM 应用能看到此人，再同步一次；如果同步仍未匹配，就 [手动绑定](/zh/self-host/use-dify/workspace/contacts#手动绑定)。
  - 「绑定已替换」：使用该成员邮箱的新 IM 身份取代了它，该成员也会出现在 **新增** 中。
- **已跳过**：此前已通过同步或手动绑定的 IM 身份。同步会保留这些绑定。

## 替换或移除 IM

如需换用其他 IM，在 **渠道** 中点击目标 IM 上的 **替换**。如果不再使用 IM，将其删除即可。

<Warning>
替换或删除 IM 会：

- 清除所有 IM 绑定（包括手动绑定）以及同步历史。
- 使已发出的卡片失效：卡片上的按钮无法再使用，有人通过其他途径响应后，卡片也不会更新。已发出的邮件和链接消息仍然有效，大家仍可通过它们响应等待中的请求。

</Warning>

更新同一组织的凭据（例如重置了 App Secret）时，连接和绑定都会保留。在同一个 IM 中保存另一个组织的凭据（例如从飞书测试企业换到公司的正式企业），则会替换连接。

替换后，重新同步，并重新完成手动绑定。如果 IM 以卡片展示请求，还要在其应用中设置新的回调 URL。

删除后，人工介入节点的收件人和设置保持不变，新请求只通过邮件发送。

## 故障排除

<AccordionGroup>
  <Accordion title="IM 中始终没有收到请求">
    检查以下几项：

    - 此人的联系人信息显示已绑定 IM。如果没有，重新同步或 [手动绑定](/zh/self-host/use-dify/workspace/contacts#手动绑定)。
    - IM 在 **渠道** 中仍处于连接状态。
    - IM 应用的凭据仍然有效。凭据失效后，**渠道** 仍会显示 IM 已连接，因此要在 **渠道** 中打开该 IM 的设置，点击 **测试连接** 确认。
    - IM 应用有发送消息的权限，并且已向此人开放（发布或安装）。

    在此期间，如果部署已完成 [邮件配置](/zh/self-host/deploy/configuration/environments#邮件配置)，此人仍可通过邮件收到请求。
  </Accordion>
  <Accordion title="卡片上的按钮无效">
    - 请求已关闭：已有人响应、请求已超时，或运行已停止。如果仍需要有人做出决定，重新发起一次运行。
    - IM 应用中的回调 URL 缺失、已过期或无法访问。从 **渠道** 复制当前的回调 URL 填入应用。[`TRIGGER_URL`](/zh/self-host/deploy/configuration/environments#trigger_url) 每次变化，回调 URL 都会随之改变。如果已是最新地址，检查 `TRIGGER_URL` 是否已设为 IM 能通过互联网访问的地址。
    - 卡片是在你替换 IM 或重新绑定此人的 IM 身份之前发出的。这些卡片无法恢复，但如果部署已完成 [邮件配置](/zh/self-host/deploy/configuration/environments#邮件配置)，此人仍可通过邮件响应。
  </Accordion>
</AccordionGroup>

各 IM 特有的问题，参见 [连接 IM](#连接-im) 下对应指南中的故障排除。
