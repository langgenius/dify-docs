App Builder 是一个 AI 助手，可通过对话帮助你构建和完善 Workflow 与 Chatflow 应用。描述你想实现的目标，App Builder 会提出计划，并在你批准后配置草稿中的节点和连线。创建新应用或修改已有应用时，都可将它与画布编辑器配合使用。

<Info>
App Builder 需要模型来规划和构建应用。在 **集成** > [**模型供应商**](/zh/self-host/use-dify/workspace/model-providers) 中配置供应商，然后打开 **默认模型设置**，选择并保存 **系统推理模型**。
</Info>

<Note>
如果应用需要知识检索、人工介入或经典 Agent 节点，你需要在画布编辑器中添加。
</Note>

## 描述需求

<Info>
创建应用需要编辑或更高角色。
</Info>

在工作室中选择 **创建**，然后选择 **工作流** 或 **Chatflow**。描述你希望应用完成的任务，包括接收哪些输入、需要什么结果，以及应遵循哪些规则。

<Warning>
不要在提示词、App Builder 对话或测试输入中包含 API 密钥、令牌、密码或敏感的生产数据。
</Warning>

例如，输入：

```text wrap
构建一个判断退款资格的 Workflow 应用。输入包括签收至今的天数、商品是否已拆封，以及退款原因。只有签收不超过 30 天且未拆封的商品才符合退款条件。说明申请是否符合退款条件，并解释原因。
```

发送前如需优化描述，选择 **使用 AI 优化**，并检查修改后的文本。

准备好后，选择 **发送**。App Builder 会在编辑器中打开，并开始处理你的请求。

如果 App Builder 需要更多细节，检查并更新 **检查需求** 表单，然后选择 **提交需求**。

<a id="review-resources"></a>

## 检查资源

检查推荐的模型、工具或已发布的 [Agent 应用](/zh/self-host/use-dify/build/new-agent/overview)。取消勾选不想使用的资源，然后选择 **确认资源**。如果没有推荐资源，也选择 **确认资源** 继续。

测试前，在 [模型供应商](/zh/self-host/use-dify/workspace/model-providers) 中配置所选模型，并完成必要的 [工具授权](/zh/self-host/use-dify/workspace/tools)。

<a id="review-the-proposed-plan"></a>

## 检查计划

检查计划，确认它符合你对应用的要求：

- **输入和输出**：应用使用的输入是你能提供的，返回的结果符合你的需求。
- **步骤和规则**：各步骤遵循你的规则，且只执行你希望应用执行的操作。
- **外部操作**：如果应用会发送信息或更新记录，确认数据和目标位置正确。

如有遗漏或错误，选择 **继续调整**，并描述需要修改的内容。

计划符合目标后，选择 **批准计划**。App Builder 会将更改应用到 **当前草稿**，即应用尚未发布的版本。

## 测试并完善

<Info>
测试应用需要编辑或更高角色。
</Info>

<a id="run-and-review-the-test"></a>

<a id="review-test-inputs"></a>

### 测试草稿

App Builder 按计划更新草稿后，选择 **运行测试**。检查建议的输入，按需调整。选择一个你明确知道预期结果的用例。

如果测试表单中有用于确认真实操作的复选框：

- 不勾选时，测试会模拟这些操作，不会发送消息或更新记录。
- 如需真实执行某项操作，先核对其账号、目标位置和数据，再勾选对应的复选框。

<Warning>
即使其他步骤使用模拟结果，模型调用和读取操作仍可能访问外部服务。对于删除数据等破坏性操作，App Builder 测试会模拟或阻止执行。
</Warning>

选择 **运行测试**，将输出与预期结果对比。使用 **运行详情** 排查错误或不符合预期的输出。如果启用了真实操作，在所连接的服务中核实结果。

如果测试失败，根据错误消息检查输入或配置是否有问题。如果 App Builder 提出修复建议，检查后选择 **应用修复**。

如需进一步排查，选择 **保留草稿**，在画布编辑器中继续测试。

<a id="refine-the-draft"></a>

### 完善草稿

如果草稿还不能满足需求，选择 **继续调整**，描述需要修改的内容。如果输出不符合预期，说明实际结果和预期结果。

选择 **提交需求**，按提示确认资源，然后检查更新后的计划并选择 **批准计划**。

<a id="continue-after-manual-edits"></a>

你也可直接在画布上编辑草稿。已有的人工介入和经典 Agent 节点也可以通过 App Builder 修改。知识检索设置请在画布编辑器中调整。

如果随后 App Builder 询问如何继续：

- 选择 **继续**，完成当前计划。
- 选择 **从当前草稿重新开始**，基于你编辑后的草稿制定新计划，替换当前计划。

这两个选项都会保留手动修改。修改后再次测试。

<a id="undo-this-attempt"></a>

<a id="revert-the-draft"></a>

### 回退草稿

选择 **回退**，恢复到 App Builder 最近的还原点，即构建、修改或修复前保存的草稿副本。系统会丢弃此后的草稿修改，包括手动修改。

<Warning>
回退不会撤销测试期间已在外部服务中执行的操作。
</Warning>

<a id="decide-whether-to-publish"></a>

## 发布

<Info>
发布应用需要编辑或更高角色。
</Info>

结果符合需求，且当前草稿已通过不含模拟步骤的测试后，选择 **发布**，让应用上线。

如需继续检查或测试，或测试中使用了模拟步骤，选择 **保留草稿**。在画布编辑器中，Workflow 应用使用 **测试运行**，Chatflow 应用使用 **预览**。结果符合需求后，选择顶部工具栏中的 **发布**。

</Tab>

<Info>
编辑应用需要编辑或更高角色。

在编辑器中打开应用，然后选择画布右上角工具栏中的 **App Builder** 图标。描述需要修改的内容，以及应保持不变的部分。

</Warning>

## 获取错误修复帮助 <a id="get-help-with-errors"></a>

<Info>
修复和测试应用需要编辑或更高角色。
</Info>

如果画布编辑器报告节点配置错误，或 Workflow 应用测试失败，可让 App Builder 协助解决。

以下位置如果显示 **使用 App Builder 修复**，选择该按钮：

- **检查清单** 中的节点配置错误旁。
- 当前 Workflow 应用 **测试运行** 的失败面板中。

## 检查更改

检查 App Builder 的诊断结果和修复建议。如果需要批准，选择 **批准修复** 以应用更改。否则，App Builder 会自动应用修复。

对于 **检查清单** 中报告的错误，选择 **重新检查**，确认配置错误已解决。这只会检查配置，不会运行应用。

<a id="test-the-updated-app"></a>

## 测试草稿

选择 **运行验证**，准备测试。检查建议的输入，将其调整为你明确知道预期结果的用例。

如果测试表单中有用于确认真实操作的复选框：

- 不勾选时，测试会模拟这些操作，不会发送消息或更新记录。
- 如需真实执行某项操作，先核对其账号、目标位置和数据，再勾选对应的复选框。

<Warning>
即使其他步骤使用模拟结果，模型调用和读取操作仍可能访问外部服务。对于删除数据等破坏性操作，App Builder 测试会模拟或阻止执行。
</Warning>

选择 **运行测试**，检查应用是否已产生预期结果。使用 **运行详情** 排查错误或不符合预期的输出。如果启用了真实操作，在所连接的服务中核实结果。

如果错误仍然存在，选择 **再次修复**，尝试另一种修复方案。

## 回退草稿

选择 **回退**，恢复到 App Builder 最近的还原点，即构建、修改或修复前保存的草稿副本。系统会丢弃此后的草稿修改，包括手动修改。

<Warning>
回退不会撤销测试期间已在外部服务中执行的操作。
</Warning>

## 发布 <a id="keep-or-publish-the-changes"></a>

结果符合需求，且当前草稿已通过不含模拟步骤的测试后，选择 **发布修复**，让应用上线。

如需继续检查或测试，或测试中使用了模拟步骤，选择 **保留草稿**。在画布编辑器中，Workflow 应用使用 **测试运行**，Chatflow 应用使用 **预览**。结果符合需求后，选择顶部工具栏中的 **发布**。
