## 连接应用

创建 Langfuse 项目，在 **Project Settings** > **API Keys** 中获取 [API 密钥](https://langfuse.com/faq/all/where-are-langfuse-api-keys)。使用 Langfuse Cloud 时，选择 [所在区域的基础 URL](https://langfuse.com/docs/api-and-data-platform/features/public-api#select-the-regional-base-url)，不要包含 `/api/public` 后缀。自部署实例的基础 URL 可向其管理员获取。

在 Dify 应用中，打开 **监测**（Agent 应用中为 **监控**）> **追踪应用性能**。点击 **Langfuse** 的 **配置**，填写连接信息：

| 字段 | 是否必填 | 填写内容 |
|:------|:---------|:------|
| **密钥** | 是 | 项目的密钥。 |
| **公钥** | 是 | 与密钥配套的公钥。 |
| **Host** | 是 | Langfuse 实例的 HTTP(S) 基础 URL。 |

<Note>
此集成需要通过 Langfuse 的旧版接收 API `/api/public/ingestion` 接收追踪数据。使用 `events_only` 模式的 Langfuse v4 部署无法接收这些数据。接入前，与 Langfuse 管理员核对 [Langfuse 的数据接收兼容性](https://langfuse.com/docs/api-and-data-platform/features/public-api#ingest-traces-via-the-api)。
</Note>

确认 [Dify 发送的数据](#dify-发送的数据) 后，点击 **保存并启用**。每个应用只能启用一个追踪服务；选择 Langfuse 会替换当前选择。

编辑配置时，已保存的凭据不会显示。如果 **Host** 不变，将凭据留空即可保留原值；如果更改目标地址，则需重新填写凭据。

## Dify 发送的数据

一条追踪记录包含一次应用执行中的各项操作及其耗时，每个操作称为一个 **span**。每个 span 包含状态和错误信息。Dify 还会发送采集到的输入和输出、模型用量，以及消息、工作流和节点的 ID 等元数据。

在 Workflow 应用的追踪记录中，可查看各节点的 span，包括循环和迭代分组。聊天追踪记录会在消息下展示模型调用。Chatflow 应用的追踪记录则在消息下展示工作流。

在 Langfuse 中打开一条 generation 记录，可查看采集到的模型调用输入和输出。如果有 token 数量和美元费用数据，会显示在对应的用量和费用字段中。

### 采集 Agent 调用和内容

<Note>
Agent 应用和 [新 Agent 节点](/zh/self-host/use-dify/nodes/agent#new-agent) 默认关闭追踪。让部署管理员同时设置 `OPS_AGENT_TRACE_ENABLED=true` 和 `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true`。设置位置详见 [环境变量](/zh/self-host/deploy/configuration/environments#llmops-追踪投递)。
</Note>

在应用的追踪设置中，找到 **Agent 数据采集**：

- **采集 Agent 内部过程**：调试 Agent 的决策时，保持开启可查看其内部的模型和工具调用。关闭后不再采集这些内部调用，但仍保留 Agent 运行或工作流节点本身。
- **采集内容**：仅在需要向监控服务发送这些运行的输入和输出时开启。关闭后仍可查看耗时、token 信息和状态。

<Note>
这些设置适用于 Agent 应用，以及包含新 Agent 节点的 Workflow 或 Chatflow 应用。在这些工作流中，**采集内容** 也控制其他节点的输入和输出。其他应用仍可能发送输入和输出；如果不能向监控服务发送这些内容，应保持追踪关闭。
</Note>

新 Agent 节点使用所在 Workflow 或 Chatflow 应用的追踪设置。工作流工具内部的 Agent 调用不会包含在父级 Agent 的追踪记录中。

## 验证新的追踪记录

1. 在 Dify 应用中发起一次新请求，等待运行完成。
2. 在 **追踪应用性能** 中，点击 **Langfuse** 的 **查看**，打开配置的项目。
3. 按运行时间找到新的追踪记录，打开后查看模型 generation 记录或节点 span。

运行结束后，追踪记录可能需要一段时间才会显示。

## 故障排查

<AccordionGroup>
  <Accordion title="配置已保存，但没有追踪记录">
    保存配置时会检查项目访问权限。确认已选择 Langfuse 并启用追踪，然后重新运行应用，在同一项目中查找。

    让管理员检查 worker 日志中的数据接收错误，并确认 Langfuse 能通过 `/api/public/ingestion` 接收数据。如果仍找不到新运行的追踪记录，还需检查 [追踪数据投递队列](/zh/self-host/deploy/configuration/environments#llmops-追踪投递)。
  </Accordion>
  <Accordion title="Dify 无法连接监控服务器">
    Dify 的 API 和 worker 必须能访问该地址。容器中的 `localhost` 指向容器自身，因此应填写 Dify 可访问的监控服务器主机名。

    使用内网 HTTP 端点时，让管理员检查 [SSRF 代理允许列表](/zh/self-host/deploy/configuration/environments#ssrf-代理)，仅放行所需的目标地址。
  </Accordion>
</AccordionGroup>

如需使用 Langfuse 中管理的提示词，参考社区维护的 [Langfuse 提示词管理插件](https://github.com/gao-ai-com/dify-plugin-langfuse)，了解安装和使用方法。
