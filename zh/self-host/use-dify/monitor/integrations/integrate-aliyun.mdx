## 连接应用

让部署管理员参考 [阿里云接入说明](https://help.aliyun.com/en/arms/tracing-analysis/before-you-begin)，提供 License Key 和 HTTP 追踪 URL。管理员应选择 Dify 服务可访问的地域和网络地址。

在 Dify 应用中，打开 **监测**（Agent 应用中为 **监控**）> **追踪应用性能**。点击 **云监控** 的 **配置**，填写连接信息：

| 字段 | 是否必填 | 填写内容 |
|:------|:---------|:------|
| **License Key** | 是 | 采集器的认证密钥，与端点分开填写。 |
| **Endpoint** | 是 | 采集器的 HTTP(S) 基础 URL，可包含端口号。 |
| **App Name** | 是 | 自定义应用名称，用于在 ARMS 控制台中显示。 |

将 HTTP 追踪 URL 中 `/adapt_` 之前的部分填入 **Endpoint**，将认证令牌 填入 **License Key**。例如，HTTP 追踪 URL 为：

```text
https://tracing-analysis-dc-hz.aliyuncs.com/adapt_example-key/api/otlp/traces
```

- **Endpoint**：`https://tracing-analysis-dc-hz.aliyuncs.com`
- **License Key**：`example-key`

保留 HTTP 端点中的端口号；此处不能使用 `8090` 等 gRPC 端口。

确认 [Dify 发送的数据](#dify-发送的数据) 后，点击 **保存并启用**。每个应用只能启用一个追踪服务；选择 云监控 会替换当前选择。

编辑配置时，已保存的凭据不会显示。如果 **Endpoint** 不变，将凭据留空即可保留原值；如果更改目标地址，则需重新填写凭据。

## Dify 发送的数据

一条追踪记录包含一次应用执行中的各项操作及其耗时，每个操作称为一个 **span**。每个 span 包含状态和错误信息。Dify 还会发送采集到的输入和输出、模型用量，以及消息、工作流和节点的 ID 等元数据。

在 Workflow 应用的追踪记录中，可查看各节点的 span，包括循环和迭代分组。聊天追踪记录会在消息下展示模型调用。Chatflow 应用的追踪记录则在消息下展示工作流。

在阿里云云监控中打开一个模型 span，可查看采集到的输入和输出，以及已记录的 token 数量。Dify 不会填充该平台的内置费用字段。

### 采集 Agent 调用和内容

<Note>
Agent 应用和 [新 Agent 节点](/zh/self-host/use-dify/nodes/agent#new-agent) 默认关闭追踪。让部署管理员同时设置 `OPS_AGENT_TRACE_ENABLED=true` 和 `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true`。设置位置详见 [环境变量](/zh/self-host/deploy/configuration/environments#llmops-追踪投递)。
</Note>

在应用的追踪设置中，找到 **Agent 数据采集**：

- **采集 Agent 内部过程**：调试 Agent 的决策时，保持开启可查看其内部的模型和工具调用。关闭后不再采集这些内部调用，但仍保留 Agent 运行或工作流节点本身。
- **采集内容**：仅在需要向监控服务发送这些运行的输入和输出时开启。关闭后仍可查看耗时、token 信息和状态。

<Note>
这些设置适用于 Agent 应用，以及包含新 Agent 节点的 Workflow 或 Chatflow 应用。在这些工作流中，**采集内容** 也控制其他节点的输入和输出。其他应用仍可能发送输入和输出；如果不能向监控服务发送这些内容，应保持追踪关闭。
</Note>

新 Agent 节点使用所在 Workflow 或 Chatflow 应用的追踪设置。工作流工具内部的 Agent 调用不会包含在父级 Agent 的追踪记录中。

## 验证新的追踪记录

1. 在 Dify 应用中发起一次新请求，等待运行完成。
2. 在 **追踪应用性能** 中，点击 **云监控** 的 **查看**，打开 ARMS 大模型控制台。
3. 找到填写的应用名称，再按运行时间定位新的追踪记录，查看其中的子 span。

运行结束后，追踪记录可能需要一段时间才会显示。

## 故障排查

<AccordionGroup>
  <Accordion title="配置已保存，但没有追踪记录">
    保存配置时会测试采集器是否可访问，不会创建实际追踪记录。确认已选择云监控并启用追踪。在阿里云云监控中，按配置的应用名称找到并打开应用，然后重新运行 Dify 应用。

    如果仍找不到新运行的追踪记录，让管理员检查 worker 日志和 [追踪数据投递队列](/zh/self-host/deploy/configuration/environments#llmops-追踪投递)。
  </Accordion>
  <Accordion title="Dify 无法连接监控服务器">
    Dify 的 API 和 worker 必须能访问该地址。容器中的 `localhost` 指向容器自身，因此应填写 Dify 可访问的监控服务器主机名。

    使用内网 HTTP 端点时，让管理员检查 [SSRF 代理允许列表](/zh/self-host/deploy/configuration/environments#ssrf-代理)，仅放行所需的目标地址。
  </Accordion>
</AccordionGroup>
