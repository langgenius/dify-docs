## 连接应用

在 Arize 的 **Settings** > **API Keys** 中获取 API 密钥和当前 Space ID，详见 [Arize 快速入门](https://arize.com/docs/ax/quickstarts)。确定目标项目名称。如需连接 Phoenix，参考 [Phoenix 集成](/zh/self-host/use-dify/monitor/integrations/integrate-phoenix)。

在 Dify 应用中，打开 **监测**（Agent 应用中为 **监控**）> **追踪应用性能**。点击 **Arize** 的 **配置**，填写连接信息：

| 字段 | 是否必填 | 填写内容 |
|:------|:---------|:------|
| **API Key** | 是 | 有数据写入权限的 Arize API 密钥。 |
| **Space ID** | 是 | 接收追踪数据的 Arize 空间。 |
| **项目** | 是 | 目标项目名称。 |
| **Endpoint** | 否 | 默认为 `https://otlp.arize.com`。使用自定义采集器时，填写管理员提供的地址。 |

自定义 **Endpoint** 必须支持 OTLP/gRPC。向管理员获取主机名和端口，不要包含 `/v1/traces` 等 HTTP 路径。

确认 [Dify 发送的数据](#dify-发送的数据) 后，点击 **保存并启用**。每个应用只能启用一个追踪服务；选择 Arize 会替换当前选择。

编辑配置时，已保存的凭据不会显示。如果 **Endpoint** 不变，将 **API Key** 和 **Space ID** 留空即可保留原值；如果更改端点，则需重新填写这两项。

## Dify 发送的数据

一条追踪记录包含一次应用执行中的各项操作及其耗时，每个操作称为一个 **span**。每个 span 包含状态和错误信息。Dify 还会发送采集到的输入和输出、模型用量，以及消息、工作流和节点的 ID 等元数据。

在 Workflow 应用的追踪记录中，可查看各节点的 span，包括循环和迭代分组。聊天追踪记录会在消息下展示模型调用。Chatflow 应用的追踪记录则在消息下展示工作流。

在 Arize 中打开一个模型 span，可查看采集到的输入和输出，以及已记录的 token 数量。Dify 不会填充 Arize 的内置费用字段。

### 采集 Agent 调用和内容

<Note>
Agent 应用和 [新 Agent 节点](/zh/self-host/use-dify/nodes/agent#new-agent) 默认关闭追踪。让部署管理员同时设置 `OPS_AGENT_TRACE_ENABLED=true` 和 `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true`。设置位置详见 [环境变量](/zh/self-host/deploy/configuration/environments#llmops-追踪投递)。
</Note>

在应用的追踪设置中，找到 **Agent 数据采集**：

- **采集 Agent 内部过程**：调试 Agent 的决策时，保持开启可查看其内部的模型和工具调用。关闭后不再采集这些内部调用，但仍保留 Agent 运行或工作流节点本身。
- **采集内容**：仅在需要向监控服务发送这些运行的输入和输出时开启。关闭后仍可查看耗时、token 信息和状态。

<Note>
这些设置适用于 Agent 应用，以及包含新 Agent 节点的 Workflow 或 Chatflow 应用。在这些工作流中，**采集内容** 也控制其他节点的输入和输出。其他应用仍可能发送输入和输出；如果不能向监控服务发送这些内容，应保持追踪关闭。
</Note>

新 Agent 节点使用所在 Workflow 或 Chatflow 应用的追踪设置。工作流工具内部的 Agent 调用不会包含在父级 Agent 的追踪记录中。

## 验证新的追踪记录

1. 在 Dify 应用中发起一次新请求，等待运行完成。
2. 在 **追踪应用性能** 中，点击 **Arize** 的 **查看**。如果快捷链接不可用，直接打开 Arize 空间和项目。
3. 按运行时间找到新的追踪记录，打开后查看子 span。

运行结束后，追踪记录可能需要一段时间才会显示。

## 故障排查

<AccordionGroup>
  <Accordion title="配置已保存，但没有追踪记录">
    保存配置时会测试采集器是否可访问，不会创建实际追踪记录。确认已选择 Arize 并启用追踪。在 Arize 中打开配置的空间和项目，然后重新运行应用。

    如果仍找不到新运行的追踪记录，让管理员检查 worker 日志和 [追踪数据投递队列](/zh/self-host/deploy/configuration/environments#llmops-追踪投递)。
  </Accordion>
  <Accordion title="Dify 无法连接采集器">
    Dify 的 API 和 worker 必须能访问 gRPC 采集器。让管理员检查采集器的主机名、端口和网络访问权限。填写可访问的服务器地址，不支持 `localhost` 等回环地址。
  </Accordion>
</AccordionGroup>

评估已采集的追踪数据时，可参考 Arize 的 [Agent 评估指南](https://arize.com/guides/ai-agent-handbook/agent-evaluation/) 和 [大语言模型评估指南](https://arize.com/resources/llm-evaluation/)。
