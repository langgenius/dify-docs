## Opik 简介

Opik 是一个开源的 LLM 评估平台，用于评估、测试和监控大型语言模型（LLM）应用。它由 Comet 开发，旨在促进对基于 LLM 的应用进行更直观的协作、测试和监控。

<Info>
如需了解更多详情，请参考 [Opik](https://www.comet.com/site/products/opik/)。
</Info>

---

## 开始配置 Opik

使用托管版 Opik 时，按以下步骤注册账户并获取 API 密钥。如果自部署实例未启用身份验证，**API Key** 可留空。

### 1. 注册/登录 [Opik](https://www.comet.com/signup?from=llm)

### 2. 获取 Opik API 密钥

从右上角的用户菜单中获取 Opik API 密钥。点击 **API Key**，然后点击 API Key 进行复制：

<Frame>
  ![](https://assets-docs.dify.ai/2025/01/a66603f01e4ffaa593a8b78fcf3f8204.png)
</Frame>

### 3. 集成 Opik 与 Dify

在 Dify 应用中配置 Opik。打开需要监控的应用，在侧边菜单中打开 **监控**，并在页面上选择 **追踪应用性能**。

<Frame>
  ![](https://assets-docs.dify.ai/2025/01/9d52a244e3b6cef1874ee838cd976111.png)
</Frame>

点击配置后，按需填写 **API Key**，并输入 **项目** 名称。项目留空时使用 `Default Project`；新项目在收到第一条追踪记录时创建。**Workspace** 可留空，使用账户的默认工作区。自部署 Opik 需将 **Url** 设为以 `/api/` 结尾的 API 基础 URL（默认为 `https://www.comet.com/opik/api/`），然后保存。

<Frame>
  ![](https://assets-docs.dify.ai/2025/01/7f4c436e2dc9fe94a3ed49219bb3360c.png)
</Frame>

成功保存后，你可以在当前页面查看监控状态。

## 查看监控数据

配置完成后，你可以照常调试或使用 Dify 应用。新的运行记录可在 Opik 中查看，启用前的使用历史不会补发。

<Frame>
  ![](https://assets-docs.dify.ai/2025/01/a1c5aa80325e6d0223d48a178393baec.png)
</Frame>

当你切换到 Opik 时，可以在仪表板中查看 Dify 应用的详细操作日志。

<Frame>
  ![](https://assets-docs.dify.ai/2025/01/09601d45eaf8ed90a4dfb07c34de36ff.png)
</Frame>

通过 Opik 的详细 LLM 操作日志将帮助你优化 Dify 应用的性能。

<Frame>
  ![](https://assets-docs.dify.ai/2025/01/708533b4fc616f852b5601fe602e3ef5.png)
</Frame>

<Note>
保存配置并启用追踪后，重新运行应用，在监控服务中确认是否出现新的追踪记录。追踪数据会异步发送，仅保存配置不能确认追踪数据已送达。

对于 Agent 应用以及使用 [新版 Agent 节点](/zh/self-host/use-dify/nodes/agent#new-agent) 的工作流，需要在部署中同时启用 `OPS_AGENT_TRACE_ENABLED=true` 和 `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true`。详见 [环境变量](/zh/self-host/deploy/configuration/environments#llmops-追踪投递)。这些应用的 **采集内容** 默认关闭，该设置控制整个工作流的输入和输出。其他应用仍可能发送输入和输出。
</Note>

## 监控数据列表

Dify 会按父子层级导出执行操作：消息包含 `llm` 调用，Chatflow 消息包含工作流及其节点操作。下表中的追踪 ID 和 span ID 由 Dify 派生生成，并非直接复制数据库 ID。只有模型调用会填充监控服务的原生 token 用量字段。

以下明细列出 Dify 的源记录和元数据。实际导出时仅发送相关且可用的值，不会完整发送原始记录。
