### 什么是 W&B Weave

Weights & Biases (W&B) Weave 是一个用于跟踪、实验、评估、部署和改进基于 LLM 的应用的框架。Weave 专为灵活性和可扩展性而设计，支持 LLM 应用开发工作流的每个阶段。

<Info>
    更多详情，请参考 [Weave](https://docs.wandb.ai/weave)。
</Info>

### 如何配置 Weave

#### 1. 注册/登录

前往 [W&B Weave](https://wandb.ai/signup) 注册/登录。创建一个 Weights & Biases (W&B) 账户，并在[此处](https://wandb.ai/authorize)复制 API 密钥。

#### 2. 将 W&B Weave 与 Dify 集成

在 Dify 应用中配置 Weave。打开需要监控的应用，在侧边菜单中打开 **监控**，在页面上选择 **跟踪应用性能**。

<Frame>
  ![在 Dify 应用中配置 Weave](https://assets-docs.dify.ai/2025/04/c33e8fda75ee9052ed23c8690e314862.png)
</Frame>

点击配置后，粘贴 **API Key** 和已存在且可写的 **项目** 名称，并按需指定 **W&B 实体**。实体留空时，Dify 使用 API 密钥的默认实体，该实体也可能是团队。然后保存配置。

<Frame>
  ![](https://assets-docs.dify.ai/2025/04/60bce1ae7b883825b13526d172ae0073.png)
</Frame>

成功保存后，你可以在当前页面查看监控状态。

<Frame>
  ![成功保存后，你可以在当前页面查看监控状态](https://assets-docs.dify.ai/2025/04/9486cee7bbb61f069842c9ea860e679c.png)
</Frame>

通过 Weave 获取的详细 LLM 操作日志将帮助你优化 Dify 应用的性能。

<Note>
保存配置并启用追踪后，重新运行应用，在监控服务中确认是否出现新的追踪记录。追踪数据会异步发送，仅保存配置不能确认追踪数据已送达。

对于 Agent 应用以及使用 [新版 Agent 节点](/zh/self-host/use-dify/nodes/agent#new-agent) 的工作流，需要在部署中同时启用 `OPS_AGENT_TRACE_ENABLED=true` 和 `DIFY_AGENT_APPLICATION_TRACING_ENABLED=true`。详见 [环境变量](/zh/self-host/deploy/configuration/environments#llmops-追踪投递)。这些应用的 **采集内容** 默认关闭，该设置控制整个工作流的输入和输出。其他应用仍可能发送输入和输出。
</Note>

### 监控数据列表

Dify 会按父子层级导出执行操作：消息包含 `llm` 调用，Chatflow 消息包含工作流及其节点操作。下表中的追踪 ID 和 span ID 由 Dify 派生生成，并非直接复制数据库 ID。只有模型调用会填充监控服务的原生 token 用量字段。

以下明细列出 Dify 的源记录和元数据。实际导出时仅发送相关且可用的值，不会完整发送原始记录。

#### **Workflow/Chatflow 追踪信息**

**用于追踪 Workflow 和 Chatflow**

| 工作流                                   | Weave 追踪                   |
| ---------------------------------------- | ---------------------------- |
| workflow_run_id | id                           |
| user_id                        | attributes.user_id               |

| metadata                                 | attributes                        |
| error                                    | exception                        |
| 会话 ID     | thread_id  |
| 父 span（如有）                           | parent_id              |

**工作流追踪信息**

* workflow_id - 工作流的唯一标识符

* workflow_run_id - 当前运行的 ID
* tenant_id - 租户 ID
* elapsed_time - 当前运行所花费的时间
* status - 运行状态
* version - 工作流版本
* total_tokens - 当前运行中使用的总令牌数
* file_list - 处理的文件列表
* triggered_from - 触发当前运行的来源
* workflow_run_inputs - 当前运行的输入数据
* workflow_run_outputs - 当前运行的输出数据
* error - 当前运行期间遇到的错误
* query - 运行期间使用的查询
* workflow_app_log_id - Workflow 应用日志 ID
* message_id - 关联的消息 ID
* start_time - 运行的开始时间
* end_time - 运行的结束时间
* workflow node executions - 工作流节点执行的信息
* 元数据
  * workflow_id - 工作流的唯一标识符
  * conversation_id - 对话 ID
