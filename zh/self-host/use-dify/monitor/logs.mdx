在任意应用的 **日志** 页面中，可看到应用的真实使用情况：用户提交了什么、应用如何响应、收到了哪些反馈。

聊天类应用（聊天助手、Chatflow、Agent）和文本生成应用记录对话；Workflow 应用记录运行。在 Agent Console 中构建的 Agent 也以同样的方式记录会话，位于控制台自己的 **日志** 页面。

## 记录内容

日志涵盖所有渠道的真实使用：Web 应用、API，以及在 Dify 内的使用。Workflow 应用中由 [触发器](/zh/self-host/use-dify/nodes/trigger/overview) 启动的运行也会被记录。

终端用户的反馈（点赞/点踩和评论）与对应消息一同保存。

Chatflow 和 Workflow 应用在编辑器中的测试（**预览** 和 **测试运行**）不会出现在日志中；其他应用类型的测试对话会被记录。

## 浏览日志

每一行是一次对话或一次运行。多数列一目了然，少数几列需要说明：

- **标题**：由对话的第一条消息自动生成。
- **用户或账户**：Web 应用和 API 的使用显示会话 ID，Dify 内的使用显示团队成员账户。
- **用户反馈** 统计终端用户的点赞/点踩，**管理员反馈** 统计团队成员的点赞/点踩，均按整个对话汇总。
- **触发方式**（Workflow 应用）：显示运行的来源：网页应用、Webhook、定时任务、集成（来自已连接服务的事件）或调试。
  <Info>通过 API 启动的运行同样显示为网页应用。</Info>
- **来源**（Agent）：显示发起会话的一方：该 Agent 的 Web 应用，或调用它的具体工作流。

关键词搜索匹配消息内容和终端用户会话 ID；Workflow 应用还匹配运行的输入、输出以及完整的运行 ID。

## 查看对话

点击某一行可打开完整的消息记录。

将鼠标悬停在回答上，可看到该条消息的 token 消耗与耗时、背后的日志（原始提示词、Agent 应用的工具调用过程，或 Chatflow 消息的逐节点追踪），以及两个团队操作：

- **评价回答**：作为团队反馈，点踩时可附评论说明问题。团队评价计入 **管理员反馈** 列，与终端用户反馈分开统计。
- **添加标注**：为该问题配上改进后的回复。标注如何生效，详见 [标注系统](/zh/self-host/use-dify/monitor/annotation-reply)。

对话 ID 包含在页面 URL 中，复制链接即可把某条日志分享给同事。

Agent 的会话以同样的消息记录形式打开，可查看每条消息的 token 与耗时，但没有上述团队操作。

## 查看运行

对于 Workflow 应用，点击某次运行可查看其结果、带状态和 token 总量的输入输出，以及逐节点的执行追踪，便于定位运行失败或变慢的环节。

点击 **按此参数测试**，可在编辑器中以该次运行的输入重新运行工作流，方便复现问题。

## 日志保留

<Warning>
日志包含完整的用户对话，可能涉及敏感信息。确保你的应用符合当地数据隐私法规：发布隐私政策，并在需要时获得用户同意。
</Warning>

日志默认无限期保留。定时清理默认关闭，由部署运维人员配置：工作流运行日志通过工作流日志清理环境变量控制（完整变量列表详见 [工作流日志清理](/zh/self-host/deploy/configuration/environments#工作流日志清理)），对话消息通过 `ENABLE_CLEAN_MESSAGES` 控制。处理敏感数据的应用建议设置更短的保留窗口。
