Dify Premium 是我们的 AWS AMI 产品，支持自定义品牌，可一键部署到你的 AWS VPC 作为 EC2 实例。前往 [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-t22mebxzwjhu6) 进行订阅。它在以下几种场景中很有用：

- 你是中小型企业，希望创建一个或几个应用，并且关心数据驻留问题。
- 你对 [Dify Cloud](https://cloud.dify.ai) 感兴趣，但你的用例需要比 [定价计划](https://dify.ai/pricing) 支持的更多资源。
- 你希望在组织内采用 Dify Enterprise 之前运行概念验证。

## 访问与设置

AMI 部署后，通过 EC2 控制台中找到的实例公共 IP 访问 Dify（默认使用 HTTP 端口 80）。

如果这是你首次访问 Dify，输入管理员初始化密码（你的 EC2 实例 ID）来开始设置过程。

## 自定义

### 配置

<Steps>
    <Step title="编辑环境变量">
        在 EC2 实例中，编辑相关文件中的环境变量：

        - **启动设置、共享凭据和 Compose 设置** 位于 `/dify/.env` 中。直接编辑现有文件即可。将 profile、对外发布的端口、挂载路径和健康检查调度设置保存在这里。

        - **服务设置** 在 `/dify/envs/` 下有对应模板。将 `.defaults` 文件复制到其注释中指定的 `.env` 路径。对于仍保留的 `.env.example` 模板，只去掉 `.example` 后缀。若 `.env` 副本已存在，直接编辑即可。

            例如，Compose 配套文件中包含 `opensearch.defaults` 时：

            ```bash
            cd /dify
            cp envs/vectorstores/opensearch.defaults envs/vectorstores/opensearch.env
            ```

            如果部署中仍提供 `opensearch.env.example`，则复制该文件，目标文件名只去掉 `.example` 后缀。

        修改副本中的输入值，取消所需可选设置的注释，并保留 **Container variable mappings** 下的表达式不变。自带的 `.defaults` 文件会自动加载。

        `/dify/.env` 中的值优先于相应服务文件中的设置。

        如果你的 AWS 部署通过 `docker-compose.override.yaml` 注入变量，将这些设置保留在该文件中。Compose 中服务级别的 `environment:` 值优先于 env 文件中的值。
    </Step>
    <Step title="应用配置">
        在 `/dify` 中运行：

        ```bash
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml config --quiet
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d
        ```

        `docker compose restart` 不会重新加载环境变量。
    </Step>
</Steps>

### Web 应用标志和品牌

在 **设置** > **自定义** 中，可移除 `Powered by Dify` 品牌标识或替换为你自己的标志。

## 升级

<Warning>

    - 升级前，查看 GitHub 上的 [Release Notes](https://github.com/langgenius/dify/releases) 了解特定版本的升级说明。某些版本可能需要额外步骤，例如数据库迁移或配置更改。

    - 更新后的 Compose 配套文件需要 Docker Compose 2.35.0 或更高版本。升级前运行 `docker compose version` 确认。

</Warning>

在 EC2 实例中，运行以下命令：

<Steps>
    <Step title="停止运行中的服务">

        ```bash
        cd /dify
        docker compose down
        ```

    </Step>
    <Step title="备份数据">
        备份 `.env` 文件、本地服务 env 文件、Compose 文件，以及包含数据库、存储和其他持久化数据的 `volumes` 目录：

        ```bash
        cp /dify/.env /dify/.env.bak
        tar -cvf envs-$(date +%s).tgz envs
        tar -cvf compose-$(date +%s).tgz docker-compose*.yaml
        tar -cvf volumes-$(date +%s).tgz volumes
        ```

    </Step>
    <Step title="更新 Dify">
        <Warning>
            以下同步操作会覆盖配置模板和 Compose 文件，同时保留 `.env`、`/dify/envs/` 下的本地服务 `.env` 文件，以及 `volumes/` 中的运行时数据。

            如果曾直接修改模板，同步前先将这些修改移到本地 `.env` 副本中。保留现有的覆盖配置文件和可用的密钥。
        </Warning>

        将 `<version>` 替换为选定版本的标签，然后一并同步该版本的 Compose 文件和 `envs/` 模板：

        ```bash
        git clone --branch <version> https://github.com/langgenius/dify.git /tmp/dify
        rsync -av /tmp/dify/docker/ /dify/
        rm -rf /tmp/dify
        ```

        将自定义的 Compose 修改重新应用到更新后的文件，并保留 `docker-compose.override.yaml` 中的 AMI 设置。
    </Step>
    <Step title="比较并合并配置变更">
        对比 `/dify/.env` 与新的 `.env.example`。逐一将本地服务 `.env` 与对应的 `.defaults` 文件或仍保留的 `.env.example` 模板进行比较。使用模板注释中指定的本地覆盖配置路径。

        例如，可用以下命令比较根文件和已有的 OpenSearch 覆盖配置。输出可能包含凭据，不要公开。

        ```bash
        diff /dify/.env /dify/.env.example
        diff /dify/envs/vectorstores/opensearch.env /dify/envs/vectorstores/opensearch.defaults
        ```

        将新增的必需输入添加到现有文件中，并保留现有可用的值。如需新建覆盖配置文件，按 [配置](#配置) 中的说明复制。

        按照 [配置升级步骤](/zh/self-host/deploy/quick-start/docker-compose#升级)，检查重命名的输入、共享凭据、profile 选择，以及旧 Compose 文件曾忽略的服务文件设置。
    </Step>
    <Step title="启动服务">

        ```bash
        docker compose pull
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml config --quiet
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d
        docker compose ps --all
        ```

        检查受影响的服务及其实际生效的配置。一次性任务 `init_permissions` 应以退出码 `0` 结束。
    </Step>
</Steps>
