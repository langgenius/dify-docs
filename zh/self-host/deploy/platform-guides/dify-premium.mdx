Dify Premium 是我们的 AWS AMI 产品，支持自定义品牌，可一键部署到你的 AWS VPC 作为 EC2 实例。前往 [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-t22mebxzwjhu6) 进行订阅。它在以下几种场景中很有用：

- 你是中小型企业，希望创建一个或几个应用，并且关心数据驻留问题。
- 你对 [Dify Cloud](https://cloud.dify.ai) 感兴趣，但你的用例需要比 [定价计划](https://dify.ai/pricing) 支持的更多资源。
- 你希望在组织内采用 Dify Enterprise 之前运行概念验证。

## 访问与设置

AMI 部署后，通过 EC2 控制台中找到的实例公共 IP 访问 Dify（默认使用 HTTP 端口 80）。

如果这是你首次访问 Dify，输入管理员初始化密码（你的 EC2 实例 ID）来开始设置过程。

## 自定义

### 配置

使用 Docker Compose 2.35.0 或更高版本。运行 `docker compose version` 检查版本。

<Steps>
    <Step title="编辑环境变量">
        在 EC2 实例中，编辑相关文件中的环境变量：

        - **必要的启动值** 位于 `/dify/.env` 文件中。直接编辑即可。

        - **可选或特定提供商的设置** 在 `/dify/envs/` 下有对应模板。Compose 自动加载 `.defaults` 文件。如果本地 `.env` 文件已存在，直接编辑即可。否则，将对应的 `.defaults` 文件复制到注释指定的本地 `.env` 路径。

            对于以 `.env.example` 结尾的服务模板，复制时去掉 `.example` 后缀。`middleware.env.example` 模板用于独立的 [源码开发流程](/zh/self-host/deploy/advanced-deployments/local-source-code#使用-docker-compose-启动中间件)，此处不使用。

            例如，如果尚未创建 OpenSearch 覆盖文件，运行：

            ```bash
            cd /dify
            cp -n envs/vectorstores/opensearch.defaults envs/vectorstores/opensearch.env
            ```

        在副本中修改输入值，保持 **Container variable mappings** 下的表达式不变。

        对于上述 OpenSearch 设置，`/dify/.env` 的值优先于 `opensearch.env`。其他服务以各自模板的注释为准；部分服务只加载自己的配置文件或指定的根配置输入。

        如果 AWS 部署通过 `docker-compose.override.yaml` 注入变量，将这些设置保留在该文件中。Compose 中服务级别的 `environment:` 值优先于 env 文件中的值。
    </Step>
    <Step title="应用更改">
        在 `/dify` 中校验配置，并重建受影响的服务。两个命令都保留现有的 AWS 覆盖文件；如果没有该文件，去掉 `-f docker-compose.override.yaml`。

        ```bash
        cd /dify
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml config --quiet
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d
        ```

    </Step>
</Steps>

### Web 应用标志和品牌

在 **设置** > **自定义** 中，可移除 `Powered by Dify` 品牌标识或替换为你自己的标志。

## 升级

<Warning>

    - 从 [Release Notes](https://github.com/langgenius/dify/releases) 中选择目标版本，并在更新前阅读其升级说明。

    - 当前 Docker 文件需要 Docker Compose 2.35.0 或更高版本。升级前运行 `docker compose version` 确认。

</Warning>

在 EC2 实例上运行命令，沿用现有部署的 Compose 项目名称和文件。如果使用了 `-p` 或 `COMPOSE_PROJECT_NAME`，保留原值，以继续挂载原有命名卷。如果没有 `docker-compose.override.yaml`，去掉下面命令中对应的 `-f` 选项。

<Steps>
    <Step title="备份部署">
        备份 `/dify/.env`、`/dify/envs/` 下所有本地 `.env` 文件、`docker-compose.override.yaml` 和其他自定义部署文件。保留现有密钥和卷路径，包括显式设置或已存储的 [SECRET_KEY](/zh/self-host/deploy/configuration/environments#secret_key)。

        按照部署的备份流程保存持久化数据。备份范围包括 `/dify/volumes/` 和外部数据库或存储。

        如果配置了 `local_sandbox`，还需备份其挂载到 `/home/dify` 和 `/workspace` 的命名卷。在 `/dify` 中，沿用现有的项目和文件选项，查询这些卷在 Docker 中的实际名称。容器无论正在运行还是已停止，此命令都适用：

        ```bash
        docker inspect --format '{{range .Mounts}}{{if eq .Type "volume"}}{{println .Name .Destination}}{{end}}{{end}}' "$(docker compose -f docker-compose.yaml -f docker-compose.override.yaml ps --all --quiet local_sandbox)"
        ```

        备份命令返回的数据卷。

        使用能保证一致性的数据库备份；在数据库写入期间复制数据文件无法保证备份可靠。
    </Step>
    <Step title="更新到所选版本">
        将 `<version>` 替换为选定的版本标签，同时复制该版本的 Docker 文件和模板：

        ```bash
        release_tag="<version>"
        upgrade_dir="$(mktemp -d)"
        git clone --depth 1 --branch "$release_tag" https://github.com/langgenius/dify.git "$upgrade_dir/dify"
        rsync -av --exclude='.env' --exclude='*.env' \
          --exclude='docker-compose.override.yaml' --exclude='volumes/' \
          "$upgrade_dir/dify/docker/" /dify/
        ```

        排除规则会保留本地环境文件、AWS 覆盖文件和运行数据。其他部署文件中的自定义更改，需从备份中重新应用。
    </Step>
    <Step title="检查配置">
        对照 `/dify/.env.example`，检查现有 `/dify/.env` 是否包含必要的启动输入。将各个本地服务 `.env` 文件与对应的 `.defaults` 或 `.env.example` 模板比较。

        现有 `shared.env` 文件仍受支持。`api-worker.env` 和已有的 `shared.env` 都应与 `envs/core-services/api-worker.defaults` 比较。

        将需要的设置添加到现有文件中；用模板覆盖文件会丢失自定义设置。如果缺少本地沙箱令牌，运行 `openssl rand -hex 32` 生成一个。在 `/dify/.env` 中，将 [`DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN`](/zh/self-host/deploy/configuration/environments#dify_agent_local_sandbox_auth_token) 设为生成的值。

        保留现有的数据库、向量存储选择项和卷路径。更改选择项不会迁移数据。如需新增可选覆盖文件，按 [配置](#配置) 中的步骤创建。
    </Step>
    <Step title="应用并检查升级">

        ```bash
        cd /dify
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml config --quiet
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml pull
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml ps --all
        ```

        确认常驻服务显示为 `Up` 或 `healthy`，且 `init_permissions` 以 `Exited (0)` 结束。打开 Dify，检查使用了自定义设置的功能。
    </Step>
</Steps>
