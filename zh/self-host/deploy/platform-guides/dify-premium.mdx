Dify Premium 是我们的 AWS AMI 产品，支持自定义品牌，可一键部署到你的 AWS VPC 作为 EC2 实例。前往 [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-t22mebxzwjhu6) 进行订阅。它在以下几种场景中很有用：

- 你是中小型企业，希望创建一个或几个应用，并且关心数据驻留问题。
- 你对 [Dify Cloud](https://cloud.dify.ai) 感兴趣，但你的用例需要比 [定价计划](https://dify.ai/pricing) 支持的更多资源。
- 你希望在组织内采用 Dify Enterprise 之前运行概念验证。

## 访问与设置

AMI 部署后，通过 EC2 控制台中找到的实例公共 IP 访问 Dify（默认使用 HTTP 端口 80）。

如果这是你首次访问 Dify，输入管理员初始化密码（你的 EC2 实例 ID）来开始设置过程。

## 自定义

### 配置

使用 Docker Compose 2.35.0 或更高版本。运行 `docker compose version` 检查版本。

<Steps>
    <Step title="编辑环境变量">
        按 [设置变量](/zh/self-host/deploy/configuration/environments#设置变量) 中的说明，把每项设置放到对应位置：

        - Compose 最先读取的设置（如 `COMPOSE_PROFILES` 和 `VECTOR_STORE`）以及共享凭据，写在 `/dify/.env` 中。
        - AWS 部署已在 `docker-compose.override.yaml` 中设置的项，继续保留在该文件中。
        - 其他设置都写在 `/dify/envs/` 下的本地 `.env` 文件中，不要写进 `.defaults` 文件。

        例如，要修改 OpenSearch 的设置，先复制其 defaults 文件（只需复制一次），再编辑副本：

        ```bash
        cd /dify
        cp -n envs/vectorstores/opensearch.defaults envs/vectorstores/opensearch.env
        ```

    </Step>
    <Step title="应用更改">
        在 `/dify` 中校验配置，并重建受影响的服务。两个命令都保留现有的 AWS 覆盖文件；如果没有该文件，去掉 `-f docker-compose.override.yaml`。

        ```bash
        cd /dify
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml config --quiet
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d
        ```

        如果修改没有生效，检查 `/dify/.env` 或 `docker-compose.override.yaml` 是否也设置了该项：两者都优先于本地文件（详见 [优先级](/zh/self-host/deploy/configuration/environments#优先级)）。
    </Step>
</Steps>

### Web 应用标志和品牌

在 **设置** > **自定义** 中，可移除 `Powered by Dify` 品牌标识或替换为你自己的标志。

## 升级

<Warning>
    从 [发布说明](https://github.com/langgenius/dify/releases) 中选择目标版本，并在更新前阅读其升级指南。
</Warning>

下面的每条 Compose 命令都在 EC2 实例上运行，并沿用部署现有的项目名称和文件，包括 `-p` 或 `COMPOSE_PROJECT_NAME`（如有）。项目名称一旦不同，就会改用全新的空命名卷启动。如果没有 `docker-compose.override.yaml`，去掉对应的 `-f` 选项。

<Steps>
    <Step title="备份部署">
        1. 在 `/dify` 中停止部署，避免复制数据库文件时数据库仍在写入：

            ```bash
            docker compose -f docker-compose.yaml -f docker-compose.override.yaml stop
            ```

            如果无法停止部署，改用各数据库自带的导出工具备份数据库。

        2. 备份 `/dify/.env`、`/dify/envs/` 下所有本地 `.env` 文件、`docker-compose.override.yaml` 和其他自定义部署文件。然后备份持久化数据，包括 `/dify/volumes/` 以及外部数据库或存储（如有）。

        3. 如果部署中包含 `local_sandbox`，还需备份其挂载到 `/home/dify` 和 `/workspace` 的命名卷。用以下命令列出这些卷：

            ```bash
            docker inspect --format '{{range .Mounts}}{{if eq .Type "volume"}}{{println .Name .Destination}}{{end}}{{end}}' "$(docker compose -f docker-compose.yaml -f docker-compose.override.yaml ps --all --quiet local_sandbox)"
            ```

    </Step>
    <Step title="更新到所选版本">
        将 `<version>` 替换为选定的版本标签，同时复制该版本的 Docker 文件和模板：

        ```bash
        release_tag="<version>"
        upgrade_dir="$(mktemp -d)"
        git clone --depth 1 --branch "$release_tag" https://github.com/langgenius/dify.git "$upgrade_dir/dify"
        rsync -av --exclude='.env' --exclude='*.env' \
          --exclude='docker-compose.override.yaml' --exclude='volumes/' \
          "$upgrade_dir/dify/docker/" /dify/
        ```

        排除规则会保留本地环境文件、AWS 覆盖文件和运行数据。其他部署文件中的自定义更改，需从备份中重新应用。
    </Step>
    <Step title="检查配置">
        将 `/dify/.env` 与 `/dify/.env.example` 对比，并将 `/dify/envs/` 下的每个本地文件与其新模板对比。如有差异，按以下方式处理：

        - 保留你有意设置的值，包括数据库和向量数据库的设置。
        - 其余的采用模板中的值。
        - 如果发布说明中重命名了某项设置，改用新名称。

        不要直接用模板覆盖已有文件，否则你改过的值会丢失。

        <Note>
            如果 `/dify/.env` 中还没有设置 [`DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN`](/zh/self-host/deploy/configuration/environments#dify_agent_local_sandbox_auth_token)，运行 `openssl rand -hex 32` 生成一个值，并在该文件中设置。Agent 后端及其本地沙箱都需要这个共享令牌才能启动。
        </Note>
    </Step>
    <Step title="应用并检查升级">

        ```bash
        cd /dify
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml config --quiet
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml pull
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d
        docker compose -f docker-compose.yaml -f docker-compose.override.yaml ps --all
        ```

        确认常驻服务显示为 `Up` 或 `healthy`，且 `init_permissions` 以 `Exited (0)` 结束。然后打开 Dify，检查使用了自定义设置的功能。
    </Step>
</Steps>
