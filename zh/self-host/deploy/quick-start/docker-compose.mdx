默认的 Docker Compose 部署包含 PostgreSQL、Weaviate 和 Dify 运行所需的配套服务。服务默认值会自动加载，首次部署时在 `docker/.env` 中配置启动设置即可。

<Tip>
常见部署问题，详见 [常见问题解答](/zh/self-host/deploy/quick-start/faqs)。
</Tip>

## 部署前准备

### 硬件

- CPU：至少 2 核
- RAM：至少 4 GiB

### 软件

安装 Docker 和 2.35.0 或更高版本的 Docker Compose，并确保 Docker 守护进程正在运行。此外，还需用 Git 下载 Dify，用 OpenSSL 生成沙箱令牌。

| 操作系统 | 安装说明 |
|:---|:---|
| macOS | 在受支持的 macOS 版本上安装 [Mac 版 Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/)。为其虚拟机配置至少 2 个虚拟 CPU 和 8 GiB 内存。 |
| Linux | 按所用发行版的说明安装 [Docker Engine](https://docs.docker.com/engine/install/) 和 [Docker Compose](https://docs.docker.com/compose/install/)。 |
| Windows（启用 WSL 2） | 安装 [Windows 版 Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)。将源代码和容器数据存放在 Linux 文件系统中。 |

开始前检查 Compose 版本：

```bash
docker compose version
```

## 部署并启动

已有部署按 [升级](#升级) 步骤操作，以保留配置和数据。

<Steps>
  <Step title="获取 Dify 发行版">
    从 [Dify releases](https://github.com/langgenius/dify/releases) 选择一个版本。将 `<version>` 替换为该版本的发布标签，然后克隆：

    ```bash
    git clone --branch <version> --depth 1 https://github.com/langgenius/dify.git
    cd dify/docker
    ```

  </Step>
  <Step title="配置启动设置">
    创建本地配置文件：

    ```bash
    cp .env.example .env
    ```

    使用默认部署时，保留 `COMPOSE_PROFILES=weaviate,postgresql,collaboration`。

    为 Agent 沙箱生成一个令牌：

    ```bash
    openssl rand -hex 32
    ```

    在 `.env` 中，将 `DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN` 设为上面命令的输出。Agent 后端和本地沙箱都需要这个共享令牌才能启动。
  </Step>
  <Step title="启动并检查服务">
    在 `dify/docker` 中运行：

    ```bash
    docker compose up -d
    docker compose ps --all
    ```

    持续运行的服务应显示 `Up` 或 `healthy`。`init_permissions` 任务仅运行一次，用于设置存储权限，完成后应显示 `Exited (0)`。
  </Step>
</Steps>

## 访问

将部署开放给公网访问前，配置 [HTTPS](/zh/self-host/deploy/configuration/environments#nginx-reverse-proxy)，并替换 [插件守护进程配置](/zh/self-host/deploy/configuration/environments#插件守护进程配置) 和 [Agent 设置](/zh/self-host/deploy/configuration/environments#dify_agent_server_secret_key) 中说明的开发凭据。

在浏览器中打开 [http://localhost/install](http://localhost/install)，创建管理员账户。设置完成后，在 [http://localhost](http://localhost) 登录。

远程部署时，将 `localhost` 替换为服务器的 IP 地址或域名。默认 HTTP 端口为 `80`。在 `docker/.env` 中，将 `NEXT_PUBLIC_SOCKET_URL` 设为浏览器可访问的 WebSocket 地址，例如 HTTPS 部署可使用 `wss://dify.example.com`，再运行 `docker compose up -d` 应用。端点格式见 [WebSocket 配置](/zh/self-host/deploy/configuration/environments#cors-配置)。

## 自定义

将部署设置和共享凭据保存在 `docker/.env` 中。Compose 在容器启动前从此文件读取 profile、对外发布的端口、挂载路径和健康检查调度等设置。

服务会自动加载 `docker/envs/` 下自带的 `.defaults` 文件。如需修改服务设置，按模板注释中指定的路径创建本地 `.env` 文件；文件已存在时，直接编辑。可选的提供商和安全设置也有 `.env.example` 模板，复制时去掉 `.example` 后缀即可。

如需修改 API、Worker 和定时任务共用的设置，从 `envs/core-services/api-worker.defaults` 复制创建 `api-worker.env`。只取消所需设置的注释，并保留 **Container variable mappings** 下的表达式不变。文件优先级、共享凭据和各项设置的说明，详见 [环境变量](/zh/self-host/deploy/configuration/environments#配置文件)。

例如，要将 Nginx 的请求体大小上限设为 `200M`，在 `dify/docker` 中执行以下操作：

<Steps>
  <Step title="设置覆盖值">
    如果 `envs/infrastructure/nginx.env` 不存在，先创建：

    ```bash
    cp envs/infrastructure/nginx.defaults envs/infrastructure/nginx.env
    ```

    在 `envs/infrastructure/nginx.env` 中设置：

    ```dotenv
    NGINX_CLIENT_MAX_BODY_SIZE=200M
    ```

  </Step>
  <Step title="应用配置">
    验证配置，然后重建受影响的容器：

    ```bash
    docker compose config --quiet
    docker compose up -d
    ```

    `docker compose restart` 会保留现有容器的环境变量。修改环境变量后，使用 `up -d` 应用。
  </Step>
  <Step title="检查生效值">
    查看 Nginx 当前生效的配置：

    ```bash
    docker compose exec -T nginx nginx -T 2>&1 | grep client_max_body_size
    ```

    输出应包含 `client_max_body_size 200M;`。如果显示其他值，先检查 `docker/.env` 中是否有覆盖值，再检查 Shell 变量和 Compose 中显式设置的 `environment` 条目。这些值的解析规则，详见 [优先级](/zh/self-host/deploy/configuration/environments#优先级)。
  </Step>
</Steps>

## 升级

从 [Dify releases](https://github.com/langgenius/dify/releases) 选择目标版本，更新前先阅读该版本的升级说明。

<Steps>
  <Step title="备份部署">
    按现有备份流程保存 `docker/.env`、本地服务 `.env` 文件、自定义 Compose 文件和持久化数据。保留当前可用的密钥和数据卷路径，包括显式设置或保存在存储中的 [SECRET_KEY](/zh/self-host/deploy/configuration/environments#secret_key)。

    默认部署的备份需包含 `docker/volumes/`，以及 `local_sandbox` 的命名卷 `dify_agent_local_sandbox_home` 和 `dify_agent_local_sandbox_workspace`。确保数据库备份具有一致性；数据库正在写入时，直接复制文件无法得到可靠的备份。如果配置了外部数据库和存储，也需一并备份。

    在 `dify/docker` 中保存 `docker compose config` 的输出，用于更新后对比。输出包含密钥，保存和比较时均应限制访问。
  </Step>
  <Step title="更新到所选版本">
    如果修改过 Git 跟踪的文件，先保存这些修改，再切换版本。本地 `.env` 文件保留在原路径。

    在仓库根目录获取发布标签，并切换到所选版本：

    ```bash
    git fetch --tags origin
    git checkout <version>
    ```

    将自定义 Compose 设置重新应用到该版本的文件中。Compose 文件和 `envs/` 模板需来自同一版本。
  </Step>
  <Step title="检查配置">
    对比 `docker/.env.example` 与现有的 `docker/.env`，检查必需的输入。将每个本地服务文件与对应的 `.defaults` 或 `.env.example` 模板比较，`api-worker.env` 或现有的 `shared.env` 则与 `api-worker.defaults` 比较。

    在现有文件中更新所需设置，直接用模板覆盖文件会丢失自定义配置。使用当前模板中的输入名称，并保留容器映射表达式不变。就地升级时，沿用现有数据库和向量数据库；修改其选择变量不会迁移数据。

    在 `dify/docker` 中，将 `docker compose config` 解析后的输出与已保存的配置比较，两份配置都应限制访问。检查凭据、数据卷路径、profile 和自定义设置的变化。
  </Step>
  <Step title="应用并检查升级结果">
    在 `dify/docker` 中运行：

    ```bash
    docker compose config --quiet
    docker compose pull
    docker compose up -d
    docker compose ps --all
    ```

    检查持续运行的服务是否为 `Up` 或 `healthy`，以及 `init_permissions` 是否以 `Exited (0)` 结束。打开 Dify，检查使用了自定义设置的功能。Nginx 配置的检查方法见 [自定义](#自定义) 中的生效值检查步骤。
  </Step>
</Steps>
